# Task 与基线（Vanilla / RAG / RAG-KG）是什么关系

> 更新日期：2026-08-25  
> 一句话：**Task = 考场给你什么工具；基线 = 你交什么答题程序。两套东西，正交，别混成一层。**

更细的数据文件 / v4·v5 / 筛题说明见：[CRAG评测与Task讨论纪要.md](../CRAG评测与Task讨论纪要.md)。

---

## 1. 先分清两轴

```
        环境（平台按 Task 定）
              │
   Task1 网页 │ Task2 网页+KG │ Task3 更多网页+API
 ─────────────┼───────────────┼─────────────────
 Vanilla      │  能跑但不吃检索 │  能跑但仍不用 API
 RAG          │ ★最匹配 Task1  │  能跑但没用 KG
 RAG-KG       │  能跑（KG 可空）│ ★最匹配 Task2/3
        方法（你在 user_config 里选的基线）
```

| 轴 | 问的是 | 例子 |
|----|--------|------|
| **Task 1 / 2 / 3** | 评测时**提供什么输入/API** | 有没有 Mock KG、HTML 有多少页 |
| **Vanilla / RAG / RAG-KG** | 模型**怎么用这些输入** | 闭卷 / 只用网页 / 网页+KG |

同一道题可以：用 Vanilla 答（假装没看见检索），或用 RAG 答（用网页），或用 RAG-KG 答（再查 Mock API）。  
换 Task 通常是**换环境**，不一定换「另一份题目文件」。

---

## 2. Task 1 / 2 / 3 各是什么

| Task | 考场给你什么 | 在考什么 |
|------|--------------|----------|
| **Task 1** | 主要是样本里的 **网页检索结果**（`search_results`） | 会不会用网页证据答题、拒答 |
| **Task 2** | **网页 + 知识图谱 / Mock API** | 会不会额外查结构化知识 |
| **Task 3** | **更多网页**（噪声更大）+ API | 更难的检索与筛选 |

要点：

- 官方开发集里，**Task1 和 Task2 共用同一份混合文件**（如 `crag_task_1_and_2_dev_v4.jsonl.bz2`），**没有**单独的「只有 Task1」下载包。
- Task 的差别主要在**正式评测怎么配环境**；本地用同一套 `local_evaluation*.py` 脚手架。
- 想在本地**近似拆开**「网页题 / KG 题」：用 **v5** 的 `popularity`（空≈网页/偏 Task1；`head|torso|tail`≈KG/偏 Task2）。**v4 没有该字段，拆不开。**

---

## 3. 三个基线各是什么

| 基线 | 代码入口（示意） | 实际行为 |
|------|------------------|----------|
| **Vanilla** | `InstructModel` | **闭卷**：几乎不用 `search_results`，只靠模型参数里的知识 |
| **RAG** | `RAGModel` | **网页 RAG**：从 HTML 抽句、检索，再生成 |
| **RAG-KG** | `RAG_KG_Model` | **网页 + Mock KG**：在 RAG 上再调 Mock API |

递进关系：闭卷上限 → 经典网页 RAG → 网页+结构化知识。

切换方式：改 `models/user_config.py`（以及 RAG-KG 时启动 Mock API）。操作见 [05-RAG与RAG-KG基线操作手册.md](./05-RAG与RAG-KG基线操作手册.md)。

## 4. 和你们已经跑过的实验怎么对上号

| 你们做的 | 实际含义 | **不是** |
|----------|----------|----------|
| 全量 **Vanilla** vs **RAG**（v4，2706） | 同一混合开发集上，比「闭卷 vs 网页检索」 | 不是官方 Task1 榜 vs Task2 榜 |
| 典型子集 200 条 | 从上述全量结果里抽的快迭代集 | 不必先按 Task1/2 再拆一遍 |
| 若以后跑 **RAG-KG + Mock API** | 更接近 **Task 2** 设定 | 仍不等于已经交了 Task2 正式榜 |

当前主线（嘈杂网页下的可信问答 / 拒答）→ 继续以 **RAG（网页）** 为方法轴即可；Task2/RAG-KG 作对照，不是眼下必须先拆题。

---

## 5. 常见误解

1. **「Vanilla 就是 Task1，RAG 就是 Task2」** — 错。Task 是环境，基线是方法。  
2. **「要跑 Task1 必须另下一份 Task1 数据」** — 错。开发集 Task1+2 同一文件；拆题靠 v5 `popularity` 或论文口径筛选。  
3. **「子集必须标成 Task1 或 Task2」** — 现阶段不必。跟全量 v4 混合口径一致即可；要对齐论文 Task 分榜时再用 v5 筛。  
4. **「开了 Mock API 就自动是 Task2」** — 不完全。还要模型**真的去调 API**（如 RAG-KG）；只开服务、仍用 Vanilla，等于没用上 Task2 工具。
