# 02 · 文献守门人（rag_worse 解法轮）

**任务：** 评估「解除检索绑架（Vanilla✓→RAG✗）」各类解法的文献撞车、空白与可辩护性。  
**立场：** 审稿人口吻；**不**把 set/基数/形态线当本轮主线；**允许** RH-ACS 族占一席，但必须过 Astute 差界。

**本地锚点：** CRAG 噪声网页 · 常无任意外网 Web · 8B · 主成功线 **accuracy↑ 或 rag_worse↓** · 忌只刷 missing/拒答分。

---

## 1. 解决 rag_worse 的合法策略族与文献饱和度

`rag_worse` 的操作定义：**闭卷通道已可答对，加检索后被误导→幻觉**。合法解法必须回答「何时、如何**解除**检索对闭卷正确答案的绑架」，而不是「从坏检索里炼出真理」。

| 策略族 | 典型动作 | 对 rag_worse 是否对症 | 文献饱和度 | 代表文献 / 变体 |
|--------|----------|----------------------|------------|-----------------|
| **A. 回退闭卷** | 判定检索有害 → **弃用网页**，输出参数知识 | ✅ **最直接** | **极高** | Astute RAG、Adaptive Retrieval、Self-RAG Retrieve/NoRetrieve、双通道 RAG、各类「with/without retrieval」路由 |
| **B. 滤噪 / 解除绑架（仍走 RAG 通道）** | 删冲突句、缩窗、重排、约束过滤后再生成 | ✅ 对症（若删掉了害人句） | **高** | Corrective RAG（Relevant 支路）、IR 约束过滤、NLI 忠实度、ALCE 引用对齐、MMR/去重重排 |
| **C. 拒答 / 选择性生成** | 证据不够或不可信 → IDK / 部分拒 | ⚠️ **保底**，单独难抬 acc | **极高** | Sufficient Context、Self-RAG IsRel/IsSup、RGB/CRAG 拒答评测线、v2 类事后相似度拒答 |
| **D. 冲突融合 / 内外知识合并** | 检索与参数知识冲突时**合成**新答案 | ⚠️ 对 rag_worse **不稳定**（可能仍被检索带偏） | **高** | Astute consolidation、RAG-Fusion、多文档冲突合并 |
| **E. 生成前伤害检测 / 反事实门控** | 并行或序贯短答，检测「检索是否改坏了闭卷」 | ✅ 对症 | **中** | 与 Astute **现象重叠**但机制可差界；Corrective **不做**此目标 |
| **F. 训练式反射** | 学何时用/不用检索 | ✅ 对症但难落地 | **高（训练栈）** | Self-RAG、Toolformer 式、RA-DIT — **本地 8B 无训练 ≈ 不可用** |

### 1.1 饱和度判读（严厉版）

```text
A + C + D 三条线已被 Astute / Corrective / Sufficient / Self-RAG 占满叙事空间。
B 线「过滤」本身不新；新在「过滤目标是否含 Retrieval Harm」。
E 线是唯一还能写 B 类缺口、又直指 rag_worse 的窄门——但进门就要和 Astute 肉搏。
F 线对本仓库等于不存在：别拿 Self-RAG 当可复现主方法。
```

### 1.2 与主指标的错配（常见假解法）

| 若主报告 | 对 rag_worse | 审稿结论 |
|----------|--------------|----------|
| missing↓、score↑，acc 平或↓ | 可能只是把不会答的题拒了 | **刷分**，不恢复闭卷已对 |
| hallucination↓ 但 rag_worse 桶不动 | 打的是别类幻觉 | **未解绑架** |
| 全数据集 acc↑ 2pt，rag_worse 子集无表 | 增益可能来自 missing 题 | **主贡献不成立** |

## 2. 「闭卷探针冲突 → 回退」类：与 Astute 差界清单

**这是全场撞车最高峰。** Astute 已明确：量化 LLM-wins-RAG-loses，并在冲突时倾向**弃不可靠检索、用参数知识**。你若写「检索与闭卷冲突则回退」，默认被判 **Astute-lite / training-free consolidation 简化版**。

### 2.1 不可省略的差异（缺任一条 → 换皮）

| # | 必须写清的差异 | RH-ACS+ 对应 | 若省略 |
|---|----------------|--------------|--------|
| D1 | **决策目标**是 *Retrieval Harm*（闭卷可答前提下检索是否造成伤害），不是泛化「内外知识冲突融合」 | 主指标 RHR / rag_worse 桶 | → Astute |
| D2 | **闭卷草稿 a0 是 harm 探针**，不是第二答案源做 merge | a0 仅用于冲突检测，输出 a0 而非融合稿 | → Astute consolidation |
| D3 | **伤害门与充分性强制串联**：`c 高 ∧ a0–证据冲突 → 闭卷`；`c 低 → 拒答`（不是「冲突就融合」） | RH-ACS+ 决策树 | → Sufficient 或 Astute |
| D4 | **No-Web 是问题设定**：Incorrect/高伤害 → 闭卷或拒答，**禁止** Web 再检索 | 对 G2 的硬承诺 | → No-Web Corrective 仍像 CRAG 变体 |
| D5 | **主表必须含 rag_worse 子集**，且增益在该桶 **可分离** | 25 条流转表 | → 整体 acc 故事 |
| D6 | **强基线**：Astute-lite（规则冲突弃检索）、No-Web Corrective、Sufficient-style | 消融表必备 | → 贡献不可证 |

### 2.2 可接受但仍需话术的「近邻」（不是免死金牌）

- **门控闭卷**（~35–50% 题跑 a0）：工程优化，**不是**创新点；写进 efficiency ablation 可以，写进贡献句会被打。
- **约束覆盖 c**：来自 IR/QA 老套路；新在 **c 与 harm 门串联**，不在 c 本身。
- **Counterfactual Harm Gate**（a0 与 a_rag 并行比对）：比单 a0 探针更像 **反事实伤害检测**，与 Astute **融合**路径仍不同，但 reviewer 会要求 side-by-side。

### 2.3 明确判为换皮（别投稿）

- 贡献句 =「我们提出双通道，冲突时用闭卷」→ **Astute 摘要复述**  
- 贡献句 =「相关低则不用检索」→ **Corrective / adaptive**  
- 贡献句 =「充分性不足则拒答」→ **Sufficient**；且 **不恢复 rag_worse**  
- 只有实现差异（8B、CRAG 网页、无训练）→ **工程适配，非方法**

## 3. 「滤噪解除绑架」类：与 Corrective / 约束过滤的撞车与空白

### 3.1 已有覆盖

| 已有 | 做什么 | 与 rag_worse 关系 |
|------|--------|-------------------|
| **Corrective RAG** | 检索器评 **Relevant / Ambiguous / Incorrect**；Incorrect → **Web** | 管「相关三态」，**不管**闭卷是否已对；Incorrect 路径 **不适配无 Web** |
| **约束 / 槽位过滤** | 年份、实体、数量等硬约束筛句 | 可减噪，但 **G1：相关≠不伤害**；高分约束外噪声仍可能绑架 |
| **NLI / 忠实度 / ALCE** | 答–证据一致性 | 多 **事后**；v2 已证 score↑ acc↓ |
| **MMR / 去重 / 重排** | 多样性、近重复 | 工程 IR；**不保证**害人的那句被去掉 |

### 3.2 撞车结论

**「先过滤再生成」 alone 不够新。** 审稿人一句：「Corrective 的 Relevant 支路 + 传统约束过滤。」

### 3.3 仍可挖的空白（B 类，但必须绑 harm）

| 空白 ID | 内容 | 为何算缺口 |
|---------|------|------------|
| **H-F1** | 过滤目标含 **「与闭卷探针冲突的片段」**，而非仅相关/约束 | Corrective 不拿闭卷当参照；Astute 在 **融合前** 做，少强调 **义务覆盖 + 片段级 harm** |
| **H-F2** | **义务槽覆盖 c** 作生成前充分性（非 embedding 相似度） | G3：v1 余弦失败；Sufficient 未绑 CRAG 硬约束 |
| **H-F3** | 滤噪 **失败时** 的 **显式回退闭卷**（二段决策），不是滤完硬答 | Corrective Incorrect→Web；你方 Incorrect→**Vanilla** |
| **H-F4** | 以 **rag_worse 恢复率** 证明过滤规则赢 baseline | 文献少报此桶 |

**严厉提醒：** 若过滤后仍走 RAG、且无闭卷回退，对 **Pixar 式 rag_worse**（闭卷本对、检索整页带偏）**常常不够**——滤噪是 **辅路**，不是 **主路**。

## 4. 「新信号 / 新目标」：尚存的 B 类创新空白

在 **不训练、无 Web、8B、CRAG 栈** 约束下，还能写进 Related Work 空白的：

| Gap | 未解决点 | 可支撑的新信号 / 目标 | 与 set/基数线关系 |
|-----|----------|----------------------|-------------------|
| **G1** | 相关≠不伤害 | harm_score、a0–证据槽冲突、反事实改写检测 | 正交；**勿混写** |
| **G2** | Incorrect 后无 Web 时的动作 | 回退闭卷 / 拒答 **决策表** | 正交 |
| **G3** | 充分性信号弱 | **义务槽覆盖 c**（非 cosine） | 正交 |
| **G6** | 主指标非 rag_worse | **RHR**、Vanilla✓→RAG✗ 恢复率 | **核心** |
| **G7** | 事后拒答刷分 | **生成前**通道选择 | 正交 |
| **G8**（补） | 伤害 **可在线检测** 无 GT | 闭卷探针 + 约束冲突 **无需标答** | RH-ACS / CHG 的理论卖点 |
| **G9**（补） | 8B 上 Astute 式融合 **不稳定** | **硬切换**优于软融合（需实验） | 若证明切换 > 融合，可加强 E 线 |

**明确不属于 rag_worse 主线的空白（本轮勿当解法）：**

- 集合基数 N2、双源成员 N3、答形态 N1、时间锚 N4、KV 表 N5 — 主要打 **set 幻觉 / 假填充**，对 rag_worse=25 桶 **贴度次要**；可作 **插件**，不能 **顶替** harm 叙事。

## 5. 可辩护的 5 个方法方向

每条：**撞车风险** · **必做消融/对照** · **贡献句能否过审**。

---

### 方向 1 · RH-ACS+（Retrieval Harm 决策 + 无 Web 回退闭卷）

| 项 | 内容 |
|----|------|
| **机制** | 义务覆盖 c → 低则拒；高风险题门控 a0；`c 高 ∧ a0–证据冲突` → **输出 a0**；否则 RAG |
| **撞车风险** | **高**（Astute 同现象；Corrective 三态；Sufficient 拒答） |
| **必做消融** | 去 a0；去约束 c；always-RAG；always-闭卷；Astute-lite；No-Web Corrective；Sufficient-style 阈值 |
| **必报子表** | 全 200 四指标 + **rag_worse 25 条**流转（Vanilla✓→?） |
| **贡献句能否过审** | **能，但仅当** rag_worse 桶有 **独占增益** 且 §2.1 六条差界 **全写进正文**；否则降级为「CRAG 问题实证」 |

**过审示例（合格）：**

> Astute 处理内外冲突融合，Corrective 在 Incorrect 时依赖 Web，Sufficient 用充分性拒答但未以 Retrieval Harm 为生成前目标；我们在无 Web CRAG 栈上将 **义务覆盖与闭卷 harm 探针强制串联**，以 **rag_worse 恢复** 为主验证。

**拒稿示例（不合格）：**

> 我们提出冲突时用闭卷的双通道 RAG。

---

### 方向 2 · CHG（Counterfactual Harm Gate，反事实伤害门）

| 项 | 内容 |
|----|------|
| **机制** | 并行或序贯生成 **a0** 与 **a_rag**（短答）；仅当 a_rag **无证据支持地改写** a0 的关键槽 → 输出 a0；否则 a_rag |
| **撞车风险** | **中高**（Astute：内外冲突；但 CHG 强调 **反事实改写** 非融合） |
| **必做消融** | 仅 a0 无 a_rag（退化为 RH-ACS）；仅冲突检测不做槽级；always 取 a_rag / a0 |
| **必做对** | 与 Astute-lite **同参** 对照（都弃检索，比的是 **检测规则**） |
| **贡献句能否过审** | **能（中）** — 关键句：「**伤害 = 检索稿相对闭卷的反事实改写**」，不是「冲突则融合」 |

---

### 方向 3 · HACF（Harm-Aware Constraint Filter → 失败则回退）

| 项 | 内容 |
|----|------|
| **机制** | 生成前：约束过滤 + **丢弃与 a0 槽冲突的 top 句**；若剩余上下文仍与 a0 冲突或 c 不足 → **回退 a0** |
| **撞车风险** | **中**（Corrective 滤噪 + 约束过滤；Astute 弃检索） |
| **必做消融** | 只约束不过 harm；只 harm 不约束；滤后无回退；RH-ACS+ 全门 |
| **贡献句能否过审** | **能（中）** — 若证明 **滤噪 alone 不够**、**+回退** 才赢 rag_worse；否则降为 M1 工程 |

---

### 方向 4 · NWC-Corrective（No-Web Corrective：Incorrect → 闭卷/拒答）

| 项 | 内容 |
|----|------|
| **机制** | 显式复刻 Corrective **三态判别**（可用轻量 NLI/相关分）；**Incorrect 不 Web**，改 **Vanilla 或 IDK** |
| **撞车风险** | **中偏高**（审稿人：「Corrective 去掉 Web 的 CRAG 适配」） |
| **必做消融** | 原 Corrective 叙事对照（说明无 Web）；Incorrect→IDK vs Incorrect→闭卷；Relevant 仍 harm 的子集 |
| **贡献句能否过审** | **勉强** — 贡献必须钉在 **G2 + G6**（Incorrect 动作改写 + rag_worse 表），不能写「提出三态」 |

**价值：** 作 **强基线** 往往比当主贡献更稳；主贡献仍建议 RH-ACS+ / CHG。

---

### 方向 5 · RHR-Opt（Retrieval Harm Rate 显式优化路由）

| 项 | 内容 |
|----|------|
| **机制** | 学习或规则化 **harm_score**（c、a0 冲突、题型先验等）→ 路由 {RAG, Vanilla, IDK}；**训练目标 / 主表** 写 RHR |
| **撞车风险** | **高**（adaptive retrieval；与 RH-ACS **同族**） |
| **必做消融** | 去 harm 特征；固定阈值 vs 学习路由；证明 **非** 题型 domain 路由 |
| **贡献句能否过审** | **低~中** — 易被 RH-ACS+ **吸收**为同一篇；除非 harm_score **公式** 本身有新信号 |

**建议：** 降级为 RH-ACS+ 的 **指标叙事 / 消融**，不单独立项。

---

### 五方向总表

| 方向 | 撞车 | 过审概率 | 与 rag_worse 贴度 | 建议 |
|------|------|----------|-------------------|------|
| 1 RH-ACS+ | 高 | 中（差界齐则可） | ★★★★★ | **主做** |
| 2 CHG | 中高 | 中 | ★★★★☆ | a0 不够时 **升级** |
| 3 HACF | 中 | 中 | ★★★☆☆ | 辅线 / 消融 |
| 4 NWC-Corrective | 中高 | 低~中 | ★★★★☆ | **强基线** |
| 5 RHR-Opt | 高 | 低 | ★★★★☆ | 不单独立项 |

## 6. 明确否决：看起来像新解法，其实不打 rag_worse 或纯工程

以下 **不得** 作为「解决 rag_worse」的主贡献报出：

| 否决项 | 理由 |
|--------|------|
| **调 top-k / 缩窗 / 收紧检索** | IR 工程；不区分「闭卷已对」与「本来就不会」 |
| **v1 余弦阈值 / 检索分充分性** | G3 已失败；≈ Sufficient 换皮；**不恢复 rag_worse** |
| **v2 事后答案–证据相似度拒答** | G7：score↑ acc↓；对 Vanilla✓→RAG✗ **无针对性** |
| **纯拒答 / 刷 missing** | 把会答的题也拒了；**accuracy 不升** |
| **Sufficient 式题级充分性换信号** | 饱和；且拒答 **≠** 恢复闭卷正确 |
| **Astute 式融合稿**（冲突则 merge） | 对 rag_worse **不可靠**；且 **撞 Astute** |
| **对比解码 / logits 混合两路** | 连续版双通道 ≈ Astute/adaptive；8B 工程险 |
| **题型 / domain 路由（M5、N1）** | 打形态错配，**非** rag_worse 主因 |
| **N2 基数 / N3 双源成员 / N5 KV 表** | 打 set 幻觉；**可降 rag_worse 子集幻觉**，但 **不是** 「闭卷已对却被绑架」的主机制 |
| **HTML 清洗 / 抽取流水线** | 预处理；无 **harm 决策** 不算方法 |
| **「检索错了所以无解」放弃治疗** | 与 06 号文档结论相反；**学术上错误** |
| **Self-RAG 训练式** | 本地栈不可复现；不能当主方法 |
| **Corrective + Web** | **违反** CRAG 无 Web 设定；不能当本赛道解法 |
| **只报全量 acc↑ 不报 rag_worse 桶** | **回避**主问题 |

### 6.1 否决话术（写进 Related Work 防身）

```text
「提升整体拒答率」≠「修复 Retrieval Harm」。
「降低 set 列表幻觉」≠「恢复闭卷已对的短答题」。
「过滤噪声网页」若无闭卷回退，对 rag_worse 仅部分有效，不得宣称主贡献。
```

## 7. 审稿人一句话（本轮门禁）

**rag_worse 解法的设计空间已被 Astute（回退）、Corrective（滤噪/Web）、Sufficient（拒答）三角占满；在本仓库约束下，唯一还能过的窄门是「No-Web + 生成前 Retrieval Harm 决策 + rag_worse 子表独占增益」——RH-ACS+ 族是其中可辩护性最高的一条，但必须带 Astute-lite 强基线与六条差界，否则就是换皮。滤噪、拒答、基数、清洗都只能当辅证，不能当逃回 unrelated 主线的借口。**

## 8. 给方法设计师的硬约束（衔接 03）

1. 本轮 **至少 3 条** 必须 **显式含 rag_worse 恢复机制**（回退或 harm 门），不能全是 set/形态。  
2. 每条贡献句 **预写 Related Work 反驳句**（针对 Astute / Corrective / Sufficient 各一句）。  
3. 主表 **必须** 含 25 条 `rag_worse_hallucination` 流转；缺则 **整包不予过审**。  
4. RH-ACS+ 占 **1 席**；其余席位优先 **CHG、HACF**，**NWC-Corrective 作基线**，**RHR-Opt 不单列**。
