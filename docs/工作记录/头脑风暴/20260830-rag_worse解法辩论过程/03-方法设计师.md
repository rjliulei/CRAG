# 03 · 方法设计师（rag_worse 解法枚举）

**任务：** 设计/枚举解除「检索绑架」的方法；产出互不为父子的主五 **W1–W5**；合法动作仅回退闭卷、滤噪后再答、拒答。

---

## 1. 问题定义（一句）

**rag_worse**：同一题上闭卷（Vanilla）已答对，但接入 top-k 网页证据后 RAG 通道产生幻觉——根因是**高分噪声/冲突片段在生成前未被识别，模型被强制沿错误证据作答**，解法空间是**生成前/生成中解除绑架**（回退闭卷、剪枝后 RAG、拒答），而非从错检索中「炼」出正确答案。

---

## 2. 主五 W1–W5

### W1 · RH-ACS+（Retrieval-Harm-Aware Channel Selection Plus，检索伤害感知通道选择增强版）

**贡献句（B 类）：**  
Astute / Corrective / Sufficient 分别处理冲突融合、相关纠偏、充分性拒答，但**未把「检索是否伤害闭卷已可答的题」做成生成前可测决策**（G1/G6），且 Corrective 的 Incorrect→Web（G2）不适配无 Web 的 CRAG 栈；本地 v1 亦证绝对余弦不能当充分性（G3）。我们提出 **RH-ACS+**：以 **Retrieval Harm** 为主决策——**约束义务覆盖 c** 与 **闭卷探针 a0–证据冲突** **强制串联**（c 高仍冲突→回退闭卷；c 极低→拒答；否则 RAG），主表报告 **rag_worse / RHR** 与 accuracy。

**机制（决策树 + 伪代码）：**

```text
slots ← RuleExtract(query)          // 年份、实体、数量/集合类型
chunks ← RetrieveTopK(query)
c ← Coverage(slots, chunks)         // 义务槽被任一片段覆盖的比例

if c < τ_low:
    return IDK                      // 证据不够，不绑架也不硬编

need_probe ← HighRisk(query, c)     // 中间带 c、set/simple 形态、多高分 chunk
if need_probe:
    a0 ← GenClosedBook(query, max_tokens=16)
    conflict ← SlotConflict(a0, chunks, slots)
    if conflict:
        return a0                     // 检索伤害闭卷 → 回退
else:
    a0 ← ∅

return GenRAG(query, chunks)        // 默认检索通道
```

**与 RH-ACS+ 的正交点：** —（本条即 RH-ACS+ 本体，作为基线候选）

**最小实验：**

- 在 `rag_llama_baseline.py` 加开关：`RAG_RH_ACS_ENABLED=1`，门控闭卷 `RAG_RH_CB_ALL=0`（约 35–50% 题跑 a0）
- 200 子集 full run + 消融：去 a0 / 去约束 c / Astute-lite 对照
- 切片：**rag_worse 25 条** 流转表（幻觉→正确 / →missing / 仍幻觉）

**预期对 rag_worse 的效应：**  
**主降**——直接对准「闭卷对、RAG 错」：冲突触发时输出 a0，25 条桶中幻觉→正确应占大头；全子集 accuracy 有机会↑；miss 可能略↑（可接受）。

### W2 · ECP（Evidence Conflict Pruning，证据冲突剪枝）

**贡献句（B 类）：**  
现有伤害方法多在**通道级**二选一（用或不用检索），但 rag_worse 常由**少数高分误导句**混入 top-k 触发，整题弃检索会误伤 rag_helps；检索侧 MMR/阈值只动相关分，**不检查片段间与问题约束的互斥**。我们提出 **ECP**：在**仍走 RAG 通道**的前提下，生成前对 top-k 做**约束互斥剪枝**——剔除与问题槽冲突、或与「约束满足核」互斥的 chunk，仅在剪后子集上生成；剪空则降级闭卷/拒答。

**机制：**

```text
slots ← RuleExtract(query)
chunks ← RetrieveTopK(query)
core ← { ch | Satisfy(ch, slots) }           // 满足全部硬槽的片段
if core = ∅:
    core ← { ch | PartialCover(ch, slots) }  // 退：覆盖最多槽

pruned ← ∅
for ch in chunks ordered by score:
    if ∃ s ∈ slots: Violate(ch, s):         continue
    if ∃ c ∈ core: Mutex(ch, c, slots):      continue   // 年份/实体/基数互斥
    pruned ← pruned ∪ {ch}

if pruned = ∅:
    return FallbackClosedBookOrIDK()
return GenRAG(query, pruned)                 // 滤噪后再答，非换通道主逻辑
```

`Mutex` 例：query 问「2020 年 CEO」，chunk A 写 2019 年人名、chunk B 写 2020 年另一人名 → 同槽不同值，二者不能同时进 context。

**与 RH-ACS+ 的正交点：**  
RH-ACS+ 判「整题是否被检索伤害」并**切换通道**；ECP **不改通道默认**（默认仍 RAG），动作是**编辑输入证据集**。可单独生效：a0 未跑时也能靠 chunk–chunk / chunk–query 互斥降绑架。

**最小实验：**

- 仅改 context 组装：在 `build_prompt` 前插入 ECP，top-k 仍 20，报告剪后平均句数
- 对照：raw top-k RAG、RH-ACS+、ECP-only
- 抽 10 条 rag_worse：人工标「误导句是否被剪除」

**预期对 rag_worse 的效应：**  
**中–高**——适合「闭卷本对、仅 1–3 句噪声带偏」子类；整题回退闭卷 unnecessary 的题上比 W1 少误伤 rag_helps；对「多句联合幻觉（并集）」单 ECP 可能不够，需配 W5。

### W3 · CDR（Contrastive De-Retrieval Decoding，对比去检索解码）

**贡献句（B 类）：**  
Astute 等在**答案级**融合内外知识；RH-ACS+ 在**生成前**离散选通道——二者都不作用于「已决定走 RAG 时，token 级被误导 logits 拉偏」的过程。我们提出 **CDR**：在同一 RAG 前向中，并行维护**无上下文**短前缀的 logits 参考，解码时**减去检索引入且缺乏片段支撑的正向偏置**，在生成中持续去绑架，而非事后改 IDK。

**机制：**

```text
// 轻量：不是每 token 全序列双前向，而是每步用 cached empty-prefix 的最后层 logits
logit_ctx  ← Forward(query + pruned_chunks, prefix)
logit_cb   ← Forward(query + "Answer briefly:", prefix)   // 极短无证据前缀

for step in decode:
    delta ← ReLU(logit_ctx - logit_cb)                     // 检索增量
    if step adds entity/slot value v:
        support ← MaxEntail(chunks, v, slots)              // 任一句是否支撑 v
        if support < τ_sup:
            delta[ v_token ] ← 0                           // 无支撑则不加偏
    logit ← logit_ctx - λ * delta
    token ← Sample(logit)
```

λ 可固定 0.3–0.5；仅对**命名实体/数字/年份 token** 启用 `support` 门（降算力）。

**与 RH-ACS+ 的正交点：**  
W1 = **离散路由**（答前选路）；W3 = **连续解码干预**（已走路仍 debias）。W3 可接住 W1 漏判的 rag_worse（未跑 a0、冲突信号弱但 logits 已被带偏）。

**最小实验：**

- 改生成循环（`generate` 钩子），λ∈{0,0.3,0.5} 网格；**必须**报算力（前向次数×）
- 对照：Vanilla RAG、RH-ACS+、CDR-only（不做通道切换）
- 消融：去 `support` 门 → 纯 contrastive，证明不是 Astute 换皮

**预期对 rag_worse 的效应：**  
**中**——对「逐 token 滑向噪声实体」有效；对「整段上下文框架就错」较弱；与 W1 叠加可补漏判。风险：λ 过大伤 rag_helps（需门控 λ 仅在 HighRisk 题开启）。

---

### W4 · AVC（Answer Verification against Closed-book，闭卷对照验真）

**贡献句（B 类）：**  
RH-ACS+ 在**生成前**用 a0 判伤害；但若仍走 RAG 通道，生成长答案仍可能在 a0 正确核心上**膨胀实体/并集**（set 幻觉）。Sufficient/v2 用 embedding 做事后相似度，易 score↑ acc↓。我们提出 **AVC**：**RAG 生成后**对答案做**槽级双源验真**——每个候选实体/数值须**同时**不被 a0 否证，且被至少一片段字面或规则支撑；不满足则**删除该槽或整答回退 a0**，把「伤害恢复」从路由扩展到**答案编辑**。

**机制：**

```text
a0 ← GenClosedBook(query, max_tokens=16)        // 可与 W1 共用缓存
a_rag ← GenRAG(query, chunks)

claims ← SlotSplit(a_rag)                       // {实体, 年份, 数量…}
kept ← ∅
for claim in claims:
    if Contradict(claim, a0, slots):            // a0 明确不同 → 伤害嫌疑
        if EntailAny(chunks, claim):  kept ← kept ∪ {claim}
        else:                       drop claim  // 检索添加且无支撑 → 删
    elif EntailAny(chunks, claim):
        kept ← kept ∪ {claim}
    else:
        drop claim                              // 闭卷未否证但也无证据 → 不膨胀

if kept 为空核心槽:
    return a0
return Render(kept) 或 a0 if |kept| ≪ |claims|
```

**与 RH-ACS+ 的正交点：**  
W1 = **生成前路由**；W4 = **生成后验真/剪枝答案**。W4 即使 W1 误判走 RAG 仍可回收；W4 也不剪 input chunk，与 W2 不同轴。

**最小实验：**

- Pipeline：always RAG → AVC（先不加 W1，测纯验真增益）
- 再叠 W1：W1→RAG 分支 → AVC
- 指标：rag_worse 桶 + **set 题**子集（成员膨胀）

**预期对 rag_worse 的效应：**  
**中–高**——专打「a0 对但 RAG 多编了名单/实体」；对「RAG 整题方向就错」需配合 a0 回退。计算：每题 +1 次短 a0（可与 W1 共享）+ 规则验真，无二次全序列生成。

---

### W5 · SCC（Single Consistent Cluster Generation，单一致簇生成）

**贡献句（B 类）：**  
rag_worse 中常见**多高分 chunk 各带不同人名/年份，模型做并集**（Pixar 类），RH-ACS+ 的 a0–证据冲突未必触发（a0 短答未列全、冲突不敏感）。简单 top-k 收紧会切掉真证据。我们提出 **SCC**：对 top-k 按**答案槽赋值等价类**聚类，**只允许单簇进 context**，生成时禁止跨簇并集；选簇依据 query 约束覆盖 + 簇内一致度，而非全局相关分排序。

**机制：**

```text
chunks ← RetrieveTopK(query)
slots ← RuleExtract(query)

// 每 chunk 抽候选槽赋值 vector v(ch) = (year, entities, …)
clusters ← UnionFind(chunks, λ equiv: Agree(v) on ≥1 answer-bearing slot)

score(c) ← Cover(c, slots) + α·Consistency(c) - β·MutexPenalty(c)
C* ← argmax_{c: |c|≥1} score(c)

if Cover(C*, slots) < τ_cov:
    return IDK or ClosedBookFallback()

return GenRAG(query, C*)    // 单簇，prompt 明示「Do not merge other pages」
```

**与 RH-ACS+ 的正交点：**  
W1 不解决「证据内部多阵营并存」；W5 **不依赖 a0**，纯证据结构选**单一自洽子世界**再生成。与 W2（ pairwise 删句）不同：W5 是**簇级硬隔离**，防止并集幻觉。

**最小实验：**

- 只在 `answer_type=set` 或 rag_worse 中「成员列表过长」子集开启 SCC
- 对照：full top-k RAG、ECP、SCC-only
- 报告：平均 context 簇大小、并集实体数变化

**预期对 rag_worse 的效应：**  
**中**——对多片段互斥+并集类 rag_worse 针对性强；对「单句就带偏」弱于 W2/W3；simple 题可能无簇结构，需形态门控 skip。

## 3. 正交关系速览

```text
         │ 决策时机 │ 作用对象 │ 核心信号
─────────┼──────────┼──────────┼──────────────────
W1 RH-ACS+ │ 生成前   │ 通道     │ c + a0–证据冲突
W2 ECP     │ 生成前   │ 输入证据 │ 约束/互斥剪枝
W3 CDR     │ 生成中   │ logits   │ ctx vs 无ctx 对比
W4 AVC     │ 生成后   │ 输出答案 │ 槽级 a0+片段双验
W5 SCC     │ 生成前   │ 证据子集 │ 单簇一致，禁并集
```

互不为父子：W2 不是 W1 的子模块（默认仍 RAG）；W4 不是 W1 的「再跑一次」（验真 vs 路由）；W5 不用 a0 做主信号，≠ W1 前置。

## 4. 降级池（否决或二期）

| 项 | 理由 |
|----|------|
| **N1 AFFR / N2 CBSD / N3 DSM / N4 TAR / N5 SKV 原样** | 打形态/基数/表征，**非**伤害绑架主机制；除非改写为 ECP/SCC 子规则，否则不进 rag_worse 主五 |
| **纯 top-k / MMR / 相对阈值** | 只动相关分，不判伤害；可作 ECP 基线对照，不当贡献 |
| **v1 余弦拒答 / v2 事后改 IDK** | 本地已证误伤或 acc↓；禁止主创新 |
| **Corrective Incorrect→Web** | 无 Web 栈不适用；叙事撞 G2 |
| **RHR-Router 单独立项** | 与 W1 同族路由，指标故事并入主表即可 |
| **COS-Harm 单独立项** | c 的计算可并入 W1 消融，不单列方法 |
| **纯 Counterfactual 双答融合（Astute-lite）** | 缺「弃检索保护闭卷」差界；作 W1 对照，不当 W2–W5 |
| **从错检索炼真理 / query rewrite 救场** | 违反问题定义 |
| **训练式 Self-RAG / 重训 reranker** | 与 8B 无训栈不匹配；二期 |

## 5. 若只做一件打 rag_worse

**选 W1 RH-ACS+。**

**原因：** rag_worse 的定义性结构是「闭卷已对、RAG 更差」——最直接合法动作是**识别伤害并回退闭卷**；W1 唯一把 a0–证据冲突与约束覆盖**串成生成前决策**，对准 G1/G6，且 08 决议已有 MVP 路径与 25 条桶验收线。W2–W5 是**同一绑架现象的其他解耦面**，但单点收益与叙事完整度均不及 W1。

---

## 6. 若做组合：可叠加且叙事可拆

**推荐：W1 + W2（RH-ACS+ + ECP）**

| 维度 | 说明 |
|------|------|
| **为何正交** | W1 管「这题要不要弃检索」；W2 管「若仍 RAG，喂哪些句」——时机同为生成前，但**动作对象不同**（通道 vs 上下文），消融可拆：仅 W1 / 仅 W2 / W1→W2 级联 |
| **叙事** | 「伤害路由 + 冲突剪枝」双栏；Related Work 可写 Astute（路由） vs 检索降噪（剪枝） |
| **预期** | W1 Recover 闭卷对；W2 降 W1 漏判且证据可部分使用的 rag_worse，并控 rag_helps 误伤 |

**次选：W1 + W4**——若 set/成员膨胀在 rag_worse 中占比高：路由 + 答后验真，叙事「双阶段伤害防护」；成本略高于 W1+W2。

**不建议首组合：W3 + 任意**——解码钩子在工程与算力上最险，宜作 W1 稳定后的增强消融，不作第一刀。
