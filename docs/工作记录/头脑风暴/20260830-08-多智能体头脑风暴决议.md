## 3. 修订后主方法：RH-ACS+（采纳守门人「须改」）

### 3.1 贡献句（更新）

> **Astute / Corrective / Sufficient** 分别处理冲突融合、相关纠偏、充分性拒答，但 **未把「检索是否伤害闭卷已可答的题」做成可测的生成前决策目标（G1/G6），且 Corrective 的 Incorrect 默认换源（G2）不适配无 Web 的 CRAG 栈；本地 v1 证明绝对余弦不能当充分性（G3）**。  
> 我们提出 **RH-ACS+**：以 **Retrieval Harm** 为主决策——**约束义务覆盖 c** 与 **闭卷探针 a0–证据冲突** **强制串联**（c 高仍冲突 → 回退闭卷；c 极低 → 拒答；否则 RAG），主表报告 **rag_worse / RHR** 与 accuracy。  
> **不声称** 首创双通道、纠检索或充分性；声称 **伤害触发式通道选择 + 无 Web 回退闭卷**。

### 3.2 不可省略的机制差界（守门人要求）

```text
1) 伤害门串在充分性之后：c 高 ∧ a0–证据冲突 → 回退闭卷（≠ Sufficient「不够就拒」）
2) a0 是 harm 探针，不是「第二融合答案源」（≠ Astute consolidation）
3) Incorrect/高伤害 → 回退闭卷或拒答，禁止 Web（≠ Corrective）
4) 主指标含 rag_worse 桶；必须消融打：去 a0 / 去约束 / Astute-lite 或 No-Web Corrective 对照
```

### 3.3 MVP 决策树（工程版）

```text
检索 top-k + 算约束覆盖 c
  c < τ_low                    → IDK（不跑闭卷）
  非高风险题且 c 高            → 直接 RAG（省 a0）
  高风险（题型/分数/覆盖中间带）→ 生成短 a0
       a0 与证据槽冲突         → 输出 a0
       否则                    → RAG
关：v1、v2；k 收紧不作主创新对照
```

### 3.4 环境变量草图（摘自工程代理）

`RAG_RH_ACS_ENABLED` · `RAG_RH_CLOSED_BOOK` · `RAG_RH_CONSTRAINT` · `RAG_RH_CB_ALL=0`（门控）· `RAG_RH_MIN_COVERAGE` · 强制 `RAG_ABSTAIN_*=0`
