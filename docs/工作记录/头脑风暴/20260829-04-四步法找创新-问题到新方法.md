## ① 定位问题（我们到底在解什么）

### 1.1 一句话问题

> 在 **CRAG 嘈杂网页检索** 设定下，固定 top-k RAG 能提高答对率，但更容易被高相似噪声片段带偏；如何在 **生成前** 减少「检索致错」，并在证据不足时正当拒答，使 **accuracy 与 score 同向改善**（而不只靠事后改成 `I don't know` 刷分）？

### 1.2 问题拆解（可检验）

| 子问题 | 本地证据 | 研究含义 |
|--------|----------|----------|
| P1 检索有用但有限 | 全量 acc 15.8%→23.1%，score 仅 −0.00185→+0.014 | 不能停在「再加检索」 |
| P2 检索抬幻觉 | hall 16.0%→21.7% | 可信度/降噪是瓶颈 |
| P3 **检索致错** | `rag_worse` 25/200，几乎全标过度检索 | **高价值创新切口** |
| P4 相似度≠证据 | max_score 中位≈0.75；v1 阈值几乎不触发 | 不能再用绝对余弦当充分性 |
| P5 事后拒答偏刷分 | v2：score↑、accuracy↓ | 主贡献不能押 v2 |
| P6 假前提非主因 | false_premise 上 RAG 已偏拒 | 勿把假前提当主故事 |

### 1.3 非问题（刻意不做大）

- 发明全新 LLM / 换更大生成模型 alone  
- 复现论文 leaderboard 双裁判数字  
- 法律可研里的「要不要外挂检索」产品题（仅动机）

### 1.4 成功时世界长什么样

- 同一 200 子集：相对 RAG baseline，**accuracy↑**，score 不降（最好升）  
- `rag_worse` 桶：幻觉减少或改对↑  
- 机制在 **生成前**；Related Work 能与 Corrective / Astute / Sufficient **差一句**

## ② 现在都是如何解决的（本领域地图）

按「动哪一层」归类；★ = 本地已试或高度相关。

### 2.1 RAG / 可信生成本领域

| 路线 | 代表思路 | 解决什么 | 未覆盖我们什么 |
|------|----------|----------|----------------|
| 固定 top-k RAG | 官方 CRAG 基线 ★ | 召回网页句答题 | 噪声致错、无降噪 |
| 纠检索 | **Corrective RAG**：相关三档→滤/Web 再搜 | 检索差时换源或滤噪 | Incorrect→Web；≠充分性；≠专打 rag_worse |
| 冲突与不完美检索 | **Astute RAG**：引出内部知识、分源合并 | 检索与参数知识冲突 | 偏合并策略，不是 CRAG 网页句切流水线 |
| 充分性拒答 | **Sufficient Context** | 证据够不够 → selective abstain | 需可操作的充分性信号；我们 v1 余弦失败 |
| 不可答分类 | **UAEval4RAG** | 不可答类型学 + 答拒权衡 | 偏评测框架 |
| 噪声下该拒 | **RGB** | negative rejection 诊断 | 诊断≠方法 |
| 训练反射 | **Self-RAG** | 检索/支持/批判 token | 要训练；我们偏规则+8B |
| 幻觉语料 | **RAGTruth** | 有上下文仍无支持的声明 | 检测/标注，非在线策略 |
| 事后忠实度 | 答案–证据相似度 ★v2 | 压不忠实输出 | **抬分不抬 acc**；不宜主创新 |
| 答前检索分阈值 | max cosine ★v1 | 低分则拒 | **本地几乎不触发** |

### 2.2 本地已走通的「解法结论」

```text
只堆 top-20 相似句     → 有用但 hall↑、存在 rag_worse
绝对相似度阈值拒答 v1  → 失败（信号错位）
答案–片段事后拒答 v2   → 分数技巧，accuracy↓ → 降级为对照
下一步创新必须：生成前 + 新信号/新决策，主看 accuracy / rag_worse
```

### 2.3 相关领域常见解法（为 §③ 供联想原料）

| 领域 | 典型做法 | 可借的「结构」 |
|------|----------|----------------|
| 信息检索 | 重排、学习排序、多样性 (MMR)、查询改写 | 排序目标 ≠ 生成有用 |
| 事实核查 / NLI | 声明–证据蕴含 | 「支撑/反驳/不足」三态 |
| 稳健学习 / 噪声标签 | 小损失优先、冲突样本降权 | 高相似噪声当「噪声标签」 |
| 控制系统 / 门控 | 先检测再切换控制器 | 题型/约束触发不同策略 |
| 数据库 / 查询规划 | 约束下推、谓词检查 | 年份/集合约束先校验再答 |
| 人机协作 / 拒识 | 不确定则交还人工 | CRAG 的 missing ≈ 拒识 |
| 多文档摘要 | 去重、冲突呈现 | 列表题少「拼错名单」 |
| 因果 / 反事实 | 有无检索的对照 | 正是 rag_worse 的定义 |

## ③ 头脑风暴：本领域 + 相关领域开放联想

规则：先求数量与跨界，**不立刻否决**；§④ 再收成可做方法。每人/每轮可从下表「触发词」蹦想法。

### 3.1 联想触发词

```text
检索致错 · 高分噪声 · 约束题（年份/集合）· Vanilla 更稳
充分性 · 冲突 · 多样性 · 谓词下推 · 噪声标签 · 双通道（内知识 vs 网页）
拒识 · 控制器切换 · 反事实（去掉检索会怎样）· 列表对齐
```

### 3.2 开放联想清单（跨域 → 可能迁移成什么）

| # | 联想来源 | 蹦出的点子（粗） | 可能打的子问题 |
|---|----------|------------------|----------------|
| L1 | 数据库谓词下推 | 先从问题抽 **约束槽**（时间、集合边界、实体），片段不过槽位检查则丢弃或降权 | P3 过度检索 |
| L2 | NLI 事实核查 | 生成前不产全文，先产「候选短答/关键断言」再对 top 句做支撑判定 | P4 P6 |
| L3 | 反事实 / A-B 测试 | **静默对照**：同题跑「仅参数」与「+检索」草稿，仅当检索稿与证据一致且相对闭卷有增益时才采用检索稿 | P3 rag_worse |
| L4 | 噪声标签学习 | 把「分高但与约束冲突 / 与 top1 语义冲突」的句当噪声，训练或规则降权 | P3 P4 |
| L5 | 控制器切换 | **题型路由**：set/comparison/multi-hop 走约束校验；simple 走充分性；false_premise 走前提检测 | P1–P6 分层 |
| L6 | 多文档冲突呈现 | 检测名单/日期冲突 → 禁止合并列举，改为拒答或只输出无冲突子集 | P3 列表幻觉 |
| L7 | Astute × CRAG | 显式「内知识通道 vs 网页通道」；网页与内知识冲突时偏保守或偏可验证网页 span | P3 |
| L8 | IR 多样性 | MMR 不仅去重，且 **惩罚「同实体反复出现但不含约束词」** 的句 | P3 |
| L9 | 拒识 / 校准 | 用「约束可校验比例」当置信度，不足则 missing——**不是**答案–片段像不像 | P5 正当拒答 |
| L10 | 查询改写 | 把约束写进检索 query（「Pixar films released after 2017」）再检索，从源头少招噪声 | P3 |
| L11 | 稳健聚合 | 多句投票实体/日期，少数派高分句作废 | 生成错日期/名单 |
| L12 | 人机协作 | 模型只许输出「片段中出现的 span」；无法对齐则拒答（抽取式上限） | P2 生成错 |
| L13 | Corrective 无 Web | Incorrect 时不搜网，改为 **缩窗到 top-1～3 或回退 Vanilla**（专打 rag_worse） | P3 |
| L14 | 因果干预 | 在线估计「加检索是否伤害」：检索稿相对闭卷稿的偏离 + 证据支持弱 → 丢弃检索 | P3 |
| L15 | 信息论 | 片段对问题的 **信息增益**（能否减少约束不确定性）；增益低则不喂 | P4 |

> 会上可继续追加 L16…；每条只写一行，不展开实现。

### 3.3 联想收敛提示（仍属风暴，不作最终判决）

- 与 **P3 rag_worse** 交集大的：L1 L3 L6 L7 L10 L13 L14

- 实现过重、本阶段易炸：需新训大模型的变体、强依赖外网的 Corrective 全文

## ④ 提出新的解决方法（候选，待投票）

下列从 §③ 收成 **可命名的方法假设**；均强调相对已有工作的「差一句」。详细筛分用 [头脑风暴指南](./20260829-03-方法创新头脑风暴指南.md) S1–S4。

### 方法 M1 · 约束感知检索过滤（Constraint-Aware Denoise）

| 项 | 内容 |
|----|------|
| **是什么** | 从问题解析约束槽（时间、数量、集合边界等）；生成前丢弃/降权「未支撑约束」的高分句，再送 LLM |
| **为什么可能新** | 不是通用相关分，而是 **问题约束可满足性**；对准 set+年份类过度检索 |
| **vs 已有** | Corrective=文档相关；本方法=**约束谓词**。Sufficient=够不够答；这里先 **滤再答** |
| **最小验证** | 规则/轻量抽取约束 + 关键词/年份匹配过滤；200 子集看 accuracy 与 rag_worse |
| **风险** | 约束抽取错、改写句无显式年份被误杀 |

### 方法 M2 · 反事实通道选择（Counterfactual Channel Select）

| 项 | 内容 |
|----|------|
| **是什么** | 同题生成（或草稿）闭卷答案与 RAG 答案；仅当 RAG 答案被证据支撑 **且** 与闭卷不一致时的「增益」可信才采用 RAG，否则回退闭卷或拒答 |
| **为什么可能新** | 直接操作 **rag_worse 的定义**（Vanilla 对、RAG 错的在线近似） |
| **vs 已有** | Astute 偏知识冲突合并；这里是 **显式双通道择优/回退**。非 v2（可在选通道后生成，或对草稿做证据检查） |
| **最小验证** | 先规则：RAG 稿与 top 句 overlap 低 → 回退 Vanilla 行为（或 IDK）；子集看 rag_worse 是否降、acc 是否升 |
| **风险** | 双倍生成成本；闭卷也错时如何决策 |

### 方法 M3 · 冲突禁止合并（Conflict-Blocked Aggregation）

| 项 | 内容 |
|----|------|
| **是什么** | 检测 top-k 中实体名单/日期冲突；冲突时禁止「拼列表」，只输出一致子集或拒答 |
| **为什么可能新** | 专打 **set/列表幻觉**（Pixar 例），把「多文档摘要冲突」做成答前硬约束 |
| **vs 已有** | Astute 做巩固；我们做 **禁止聚合 + CRAG 短答** |
| **最小验证** | 简单日期/名称集合冲突启发式 + 缩小生成空间 |
| **风险** | 启发式脆；非列表题收益小 |

### 方法 M4 · 无 Web 的伤害感知纠检索（Harm-Aware Corrective-lite）

| 项 | 内容 |
|----|------|
| **是什么** | 相关分三态后：Correct 滤噪生成；Ambiguous 缩窗；**Incorrect/高风险 不 Web，而回退闭卷或拒答**（因 CRAG 赛道常无任意外网） |
| **为什么可能新** | 改写 Corrective 的 Incorrect 支路：**回退 Vanilla/拒答** 对齐 rag_worse，而非换源硬答 |
| **vs 已有** | Corrective Incorrect→Web 仍答；我们 **宁可少答或闭卷** |
| **最小验证** | 相对阈值三态 + 回退策略开关；对照纯 top-k |
| **风险** | 被审稿人视为 Corrective 变体——差界必须写清「无 Web + 回退闭卷」 |

### 方法 M5 · 题型路由的可信控制器（Type-Routed Trust Controller）

| 项 | 内容 |
|----|------|
| **是什么** | 按 `question_type` 切换策略：set→M1/M3；simple→充分性/抽取式；false_premise→前提检测；multi-hop→分解 |
| **为什么可能新** | **决策层新**（控制器），组件可旧；贡献在路由策略与 CRAG 题型对齐 |
| **vs 已有** | 统一 RAG 流水线；文献少按 CRAG 八题型做可信路由 |
| **最小验证** | 先只路由 set+simple 两路；看整体 acc 与分题型 |
| **风险** | 被评「工程拼装」——需证明路由本身带来增益（消融关掉路由） |

### 方法 M6 · 信息增益喂养（Info-Gain Grounding）

| 项 | 内容 |
|----|------|
| **是什么** | 估计片段是否降低「约束不确定性」；增益低于阈值的不入 prompt |
| **为什么可能新** | 信号从「像问题」改为「减少答题不确定」 |
| **vs 已有** | 近 Sufficient Context，但可用轻量代理（约束覆盖率）先近似 |
| **最小验证** | 用约束覆盖率当 IG 代理，与 M1 可能合并 |
| **风险** | 与 M1 重叠；需说清是否独立贡献 |
