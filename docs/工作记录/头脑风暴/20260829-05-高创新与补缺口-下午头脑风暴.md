## 0. 两种合法的「新」（先选叙事，再想方法）

| 类型 | 含义 | 审稿/导师怎么听 |
|------|------|------------------|
| **A. 方法形态新** | 机制、信号、目标函数别人少见 | 「你们提出了××」 |
| **B. 问题缺口新（推荐作主叙事）** | 别人提出了方向，但 **留下明确未解决部分**；你们 **改善并补上** | 「×× 没解决 Y；我们解决了 Y」 |

对当前阶段：**B 往往比硬拗 A 更稳。**  
「创新性很高」≠ 必须从零发明名词；也可以是：**把文献承认的 gap + 本地测出的 gap 钉死，给出可验证补丁。**

下午议程默认走：**先找 gap → 再设计补法 → 最后才起方法名。**

## 1. M1–M6 与现有方法重叠吗？别人做过吗？

**总判：** 六个都不是「无人做过的全新算法」；多数是旧思想变体。单独拿去当「很高创新」叙事偏虚。

| 方法 | 重叠度 | 别人是否做过类似 | 当主创新？ |
|------|--------|------------------|------------|
| **M1 约束过滤** | 中高 | IR/QA 槽位·时间约束过滤常见 | 最多「中创新」；可作 **补 Corrective「只看相关不看约束」** 的 B 类 |
| **M2 反事实通道** | 中 | adaptive retrieval、双通道、Astute 内外知识有影子 | **相对最值得深挖**（若钉死 rag_worse 在线准则） |
| **M3 冲突禁止合并** | 高 | 多文档冲突、Astute、事实核查 | 插件，不当主创新 |
| **M4 伤害感知纠检索** | **很高** | ≈ Corrective RAG 三态 | 易被说成变体；除非 Incorrect 支路差界极硬 |
| **M5 题型路由** | 高 | 任务分流 pipeline 常见 | 工程拼装风险高 |
| **M6 信息增益** | 高 | ≈ Sufficient Context | 宜并入充分性线，不单立 |

### 1.1 下午怎么用这张表

- **不要**在 M1–M6 上投票「哪个最新」然后直接开干。  
- **可以**把 M2 / M1 当作「补缺口」的候选零件。  
- **主战场**转到下文 §2–§3：别人没解决什么 → 我们补什么。

## 2. 别人已经解决了什么？还留下什么未解决？

结合精读 (#5 Corrective / #6 Sufficient / #8 Astute / #4 Self-RAG) + 本地实验。

### 2.1 文献已覆盖（别再宣称首创）

| 已解决/已提出 | 代表 |
|---------------|------|
| 检索差时应纠偏（滤噪 / 再检索） | Corrective RAG |
| 证据充分性 → 选择性作答 | Sufficient Context |
| 不完美检索与知识冲突 | Astute RAG |
| 训练侧检索/支持反射 | Self-RAG |
| 噪声下该拒不拒的评测现象 | RGB、CRAG 指标设计 |

### 2.2 文献明确或隐含的缺口（B 类创新原料）

| Gap ID | 未解决 / 解决得不够 | 谁留下的 | 本地是否对得上 |
|--------|---------------------|----------|----------------|
| **G1** | 纠检索判的是 **文档相关**，不是「片段是否满足问题约束 / 是否会伤害原本能答对的闭卷」 | Corrective | ✅ max 分高仍 rag_worse；相关≠有用 |
| **G2** | Incorrect 后 **倾向 Web 再答**，不是「检索致错时回退闭卷 / 拒答」 | Corrective | ✅ CRAG 常无任意外网；rag_worse=25 |
| **G3** | 充分性方法强依赖 **好的充分性信号**；简单检索相似度不够 | Sufficient 等 | ✅ **v1 已失败**（阈值几乎不触发） |
| **G4** | 冲突工作重 **合并/巩固**，少做「禁止聚合列举 → 短答/拒答」的硬决策（CRAG 短答设定） | Astute 等 | ✅ set 列表幻觉（Pixar 例） |
| **G5** | 训练式反射难落到 **无训练、8B、官方切句 RAG 栈** 的可复现增量 | Self-RAG | ✅ 本地约束 |
| **G6** | 少有工作以 **「Vanilla 对、RAG 错」恢复率** 为主指标讲故事 | 多数报整体 EM/acc | ✅ 已有 `rag_worse` 桶 |
| **G7** | 事后忠实度检查易变成 **刷拒答分**，不恢复答对 | 各类 answer-evidence 相似度 | ✅ **v2：score↑ acc↓** |

### 2.3 一句话缺口（下午贴墙用）

```text
别人会纠「相关」、会谈「充分」、会处理「冲突」，
但很少同时解决：
  在噪声网页 + 无 Web 回退 + 轻量栈上，
  识别并阻断「检索伤害本已能答对的问题」（rag_worse），
  且用生成前机制抬 accuracy，而不是事后改 IDK。
```

## 3. 高创新怎么找：下午头脑风暴协议

### 3.1 目标（写在白板第一行）

> 产出 **1 个主贡献句（B 类优先）** + **1 个备选**；创新性自评 ≥「高」或「补关键缺口」；一周内可在 200 子集验证。

### 3.2 流程（约 90–120 分钟）

| 时段 | 做什么 | 产出 |
|------|--------|------|
| 0–15' | 齐读 §1 重叠表 + §2.2 Gap 表；宣布 M1–M6 **降级为零件** | 共识：不刷旧方法 |
| 15–35' | **只攻缺口：** 每人给 G1–G7 各写「若只补这一个，方法长什么样」（不限实现） | 缺口→点子便签 |
| 35–55' | **加高创新约束：** 点子必须含「新信号 **或** 新决策目标 **或** 新评价指标」之一；去掉纯 top-k/MMR/v2 | 过滤后清单 |
| 55–75' | 合并成 ≤3 个「贡献句」；强制写 **补了哪个 G#**、**没重复宣称什么** | 候选句 |
| 75–100' | 用下方「高创新筛子」打分；定 1 主 1 备；写最小实验 | 下午结论 |

### 3.3 高创新筛子（比原 S1–S4 更严）

每条 0/1，**满分 5；主做须 ≥4**。

| # | 标准 | 问自己 |
|---|------|--------|
| H1 | **钉住 G#** | 能否指出补的是 G1–G7 哪一条（或新写 G8）？ |
| H2 | **禁止旧主创新** | 主贡献是不是又沦为 top-k / MMR / Corrective 原样 / v2？ |
| H3 | **差界一句能辩护** | 被问「这不就是 Corrective/Astute/Sufficient 吗」时，有无 **不可省略** 的差别？ |
| H4 | **主指标不是刷 missing** | 成功标准是否含 accuracy↑ 或 rag_worse↓？ |
| H5 | **可周内验证** | 200 子集 + 现有栈能否做出 before/after？ |

### 3.4 贡献句强制模板（B 类）

> **〔工作 X〕** 解决了 〔相关/充分/冲突…〕，但 **未解决 〔G#：具体缺口〕**。  
> 我们提出 **〔方法名〕**，通过 **〔新信号/新决策〕**，在 CRAG 噪声网页与本地栈上 **补上该缺口**，使 **〔accuracy↑ / rag_worse↓〕**。  
> 我们 **不声称** 首创 〔纠检索/充分性/冲突检测〕。

## 4. 导向「更高创新 / 补缺口」的提问（下午用）

不要从「还能加什么模块」开始；从这些问题开始：

1. **若 Corrective 在 CRAG 上不许 Web，Incorrect 支路的「正确动作」应是什么？**（对准 G2）  
2. **如何在线识别「这条检索正在伤害闭卷已会的题」？**（对准 G1/G6，贴近 M2 但可更狠）  
3. **v1 失败后，下一代「充分性信号」若 ban 掉绝对余弦，还剩什么可计算量？**（对准 G3）  
4. **列表题冲突时，合并 vs 禁止合并，哪一个才是 CRAG 短答下的最优决策？**（对准 G4）  
5. **能否定义一个新指标：Retrieval Harm Rate（检索伤害率）= rag_worse / 可对比题，方法以降低它为主目标？**（对准 G6，指标也可成为贡献）  
6. **有没有一种机制，在「滤噪」和「拒答」之间自动选择，且选择依据不是答案像不像片段？**（避开 G7）

每题至少逼出 **1 个** 不同于 M1–M6 原文的变体或全新句。

## 6. 预期心态（避免下午空转）

| 不现实 | 现实 |
