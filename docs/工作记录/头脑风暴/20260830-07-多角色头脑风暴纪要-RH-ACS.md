## Round 1 · 只攻缺口（各提一招）

### 对 G1（相关 ≠ 不伤害）

**E：** 高分句照样害人。需要「伤害」信号，不是更高的相关分。

**M-点子①：** **Parametric Consistency Gate（参数一致性门）**  
同题先廉价闭卷草稿（短答），再看检索 top 句是否 **支持闭卷稿**；若检索与闭卷冲突且检索侧约束/ ential 弱 → 判定「检索可能伤害」→ 采用闭卷。

**L：** 有点像 Astute 内外知识，也像 adaptive RAG。「双通道」不新。

**M：** 差界可以是：**以「是否伤害闭卷已有答案」为触发**，主指标是 rag_worse 恢复，不是知识融合质量。

**S：** 要多一次生成，成本×2，但 200 子集可接受；可用很短 max_tokens。

### 对 G2（Incorrect 不 Web）

**M-点子②：** **No-Web Harm Branch**  
Corrective 式三态，但 Incorrect/高风险 → **强制回退 Vanilla 或拒答**，禁止 Web。

**L：** 审稿人会写「Corrective 变体」。除非全文强调 Incorrect 支路改写 + CRAG 无 Web 设定 + rag_worse 实证。

**T：** 可作备选或 Related Work 差界，不当「很高创新」主卖点。H 分会卡在 H3。

### 对 G3（非余弦充分性）

**M-点子③：** **Constraint Coverage Sufficiency**  
从问题抽约束槽（时间、实体、集合边界），用「槽被片段覆盖比例」当充分性；覆盖低 → 拒答或回退；覆盖高但与闭卷冲突 → 走伤害门（点子①）。

**L：** 槽位覆盖 IR 里旧。但你们 **v1 余弦已挂**，换成约束覆盖是「换信号」，B 类说得通。

**E：** 对 set+年份类过度检索很贴 Pixar 例。

### 对 G6（检索伤害率作主目标）

**M-点子④：** 方法论文主表增加 **Retrieval Harm Rate (RHR)** = rag_worse 类题占比或绝对数；优化目标显式降 RHR。

**T：** 指标可以是贡献的一部分，但单靠「定义指标」不够，必须绑一个机制。建议与点子①捆绑。

## Round 2 · 辩论与合并

**S：** 一周能做的组合：  
`闭卷短草稿` + `约束覆盖` + `冲突则回退闭卷` + `覆盖极低则拒答`。  
滤噪 top-k 当强基线，不写进创新点。

**L：** 合并后叫什么不重要。必须写清：

| 他们 | 我们 |
|------|------|
| Corrective | 相关三态 + Web；我们 **无 Web，伤害则回退闭卷** |
| Astute | 冲突后 consolidation 仍偏作答；我们 **优先保护闭卷正确、可直接弃检索** |
| Sufficient | 充分性；我们充分性代理是 **约束覆盖**，且与 **伤害门** 串联 |
| v2 | 事后答案–片段像不像；我们 **生成前通道选择** |

**E：** 主故事就一句：  
**在线阻断检索对参数正确答的伤害（降 rag_worse），在无 Web 的 CRAG 栈上。**

**T：** 把合并方案定为 **主贡献**；点子②单独当备选叙事弱化版。

## Round 3 · 命名与 H 打分

### 主贡献候选名

**Retrieval-Harm-Aware Channel Selection（RH-ACS）**  
中文工作名：**检索伤害感知的通道选择**（闭卷 vs 检索 vs 拒答）

**机制（最小版，一周可做）：**

```text
1) 约束槽抽取（规则/轻量）→ 算片段约束覆盖率 c
2) 短闭卷草稿 a0（可关消融）
3) 检索 top-k（可先 k=8 工程向，非创新点）
4) 决策：
   - c 极低 → 拒答 或 仅用 a0（消融二选一，主实验先：c低且无可靠闭卷→拒答）
   - a0 与检索证据冲突 / 检索不支持 a0 → 输出 a0（回退闭卷）★打 rag_worse
   - 否则 → 用检索生成 a_rag
5) 不做：事后答案–片段改 IDK 当主结果
```

**H 打分（T 主持）：**

| H | 判 | 理由 |
|---|----|------|
| H1 | 1 | 钉 G1+G2+G6（兼 G3 信号） |
| H2 | 1 | 不是 top-k/MMR/Corrective 原样/v2 |
| H3 | 1 | 差界可写：无 Web + 回退闭卷打伤害 + 约束覆盖非纯余弦 |
| H4 | 1 | 主看 accuracy↑、rag_worse↓ |
| H5 | 1 | 200 子集可做 |
| **合计** | **5/5** | 允许主做（实现要守住差界话术） |

**风险（L）：** 「双通道」仍会被说眼熟 → 摘要和贡献列表必须出现 **Retrieval Harm / rag_worse / no-Web fallback**，不能只写 multi-channel RAG。

### 备选

**No-Web Corrective with Vanilla Fallback**（G2 专用）  
H≈3–4：差界硬但易被称变体；主贡献一周无信号时再推。

## Round 4 · 拍板

| 项 | 决议 |
|----|------|
| **主做** | RH-ACS（检索伤害感知通道选择） |
| **备选** | No-Web Corrective + Vanilla/拒答支路 |
| **降级** | 纯 top-k、v1、v2、单 M3/M5/M6 |
| **下周验证** | 关 v1/v2；baseline RAG vs RH-ACS；表：四指标 + rag_worse 桶变化 |
| **成功线** | accuracy 不低于 baseline 且尽量↑；rag_worse 幻觉数↓；score 不降 |

### 最小验证草图（S）

```text
对照：子集 RAG baseline（已有 −0.30 / 24.5%）
实验：RH-ACS（闭卷草稿 + 约束覆盖 + 冲突回退闭卷）
可选消融：
  - 去掉闭卷回退（只留约束覆盖）
  - 去掉约束覆盖（只留闭卷冲突回退）
  - 仅 k=8（工程基线，不报创新）
```

## 一句话结论

**模拟会收敛：主做「检索伤害感知的通道选择（RH-ACS）」——用约束覆盖 + 闭卷草稿与检索的冲突，在生成前选择闭卷 / 检索 / 拒答，专打 rag_worse，补 G1/G2/G6；不宣称首创纠检索或充分性。**
