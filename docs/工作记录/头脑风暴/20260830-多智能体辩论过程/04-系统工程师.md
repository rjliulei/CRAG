# 04 · 系统工程师（完整发言）

**任务：** 单卡 8B + MiniLM + 200 子集 + 一周 + 无外网；RH-ACS 成本与 MVP；Go/No-Go。

---

## 1) 风险与成本

**延迟：** 每题闭卷+RAG ≈ LLM×2，墙钟约 +80%～100%；门控后可降。  
**显存：** 不增模型；两路分两次 generate；batch 可 4→2。  
**工程：** 主要改 `batch_generate_answer()`，中等复杂度；难在阈值，不在 vLLM。  
**最大风险：** 规则冲突 **误杀 rag_helps** 或 **漏检 rag_worse**。

---

## 2) 最小 MVP（一周）

| 天 | 动作 |
|----|------|
| D1 | `_rh_acs_config()`；关 v1/v2；闭卷 prompt |
| D1–2 | 规则抽年份/实体等；算覆盖 c |
| D2 | **门控闭卷**（非每题）；冲突→输出 a0；否则 RAG |
| D3 | smoke 10 条 |
| D4–5 | baseline + RH-ACS full 各 200 |
| D6 | 消融：去闭卷 / 去约束 |
| D7 | rag_worse 25 条流转表 + case |

---

## 3) 消融默认关闭

v1、v2、embedding 冲突、LLM 抽槽、题型路由、把 k=8 当创新对照、Web 支路。  
主实验：低覆盖→**IDK**（闭卷回退作冲突支路，不作低覆盖默认）。

---

## 4) 环境变量草图（摘要）

`RAG_RH_ACS_ENABLED` · `RAG_RH_CLOSED_BOOK` · `RAG_RH_CONSTRAINT` · `RAG_RH_CB_ALL=0`（门控）· `RAG_RH_MIN_COVERAGE` · 强制 `RAG_ABSTAIN_*=0`

---

## 5) 双倍生成：门控闭卷

只对高风险题跑 a0（约 35%～50%）；同 batch 先收集再一次闭卷 generate。  
**不推荐 MVP：** 每题必跑 a0；另加载小模型做 a0。

---

## Go / No-Go

| 维度 | 判定 |
|------|------|
| 一周出四指标 + rag_worse 桶 + 2 消融 | **Go** |
| 一周保证 rag_worse↓ 且 acc 不降 | **No-Go 保证**（依赖规则） |
| 结论 | **Go 做 MVP**；工程成功 ≠ 方法成立 |
