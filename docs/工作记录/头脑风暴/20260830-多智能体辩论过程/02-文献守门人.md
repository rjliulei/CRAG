## 2) 怎样改才能让差界「不可省略」

**话术：**

- 目标不是「相关/充分/冲突」，而是 **Retrieval Harm**（闭卷已可答时，检索是否绑架答案）。  
- 主指标写 **RHR / rag_worse 恢复**，表头单独 `Vanilla✓→RAG✗` 桶。  
- **No-Web 是问题设定**，不是 ablation。  
- **不宣称** 首创纠检索/充分性/双通道；宣称 **伤害触发式通道选择**。

**机制（缺了会被 Astute 吞）：**

- 伤害门串在充分性之后：`c 高但 a0–证据冲突` → 回退闭卷；仅 `c 低` → 拒答。  
- 闭卷草稿是 **harm 探针**，不是第二融合答案源；消融必须含「去掉 a0」。  
- 强基线：Astute-lite、No-Web Corrective、Sufficient-style——证明赢的是 **rag_worse 桶**。

## 3) 更不易撞车的方向

**A · Counterfactual Harm Gate**  
闭卷短答 vs 检索短答并行；仅当闭卷满足约束 ∧ 检索稿无证据支持地改写闭卷时切闭卷。  
差界：Astute 融合；Corrective 换源；你做 **反事实判伤害**。

**B · Set/List Merge Prohibition**  
名单题多片段集合冲突 → 禁止拼列表，短答可证子集或拒答。
