# 03 · 方法设计师（完整发言）

**任务：** 高创新或补缺口；主指标 accuracy↑ 或 rag_worse↓；生成前；禁 v2 当主创新。给 3 方法 + Top-3。

---

## 方法 1 · RH-ACS+（增强版）

- **核心：** 约束覆盖率 c + 闭卷短草稿 a0 与证据硬槽冲突 → 选闭卷 / RAG / 拒答。  
- **伪代码：**
```text
slots ← 抽问题约束槽; c ← top-k 对 slots 的覆盖率
a0 ← 8B 闭卷短答(max_tokens 小)
if c < τ_low → IDK 或 a0(消融)
elif a0 与 top-k 在实体/年份/数量槽冲突 → 输出 a0
else → 用 top-k 生成 a_rag
```
- **补 G#：** G1 + G2 + G3 + G6  
- **差一句：** Corrective→Web；Astute 融合；Sufficient 余弦——我们用 **约束覆盖 + 伤害门保护闭卷**，无 Web。  
- **一周可做：** ✅

---

## 方法 2 · COS-Harm（约束义务覆盖 + 伤害串联门）

- **核心：** 充分性 = 义务槽覆盖比例 c；c 低拒答；c 高仍与 a0 冲突 → 回退。  
- **补 G#：** G3（主）+ G1 + G6  
- **差一句：** Sufficient 信 embedding；我们信 **结构化义务覆盖** 并与闭卷冲突串联。  
- **一周可做：** ✅（可作 RH-ACS 模块）

---

## 方法 3 · RHR-Router（检索伤害率优先路由）

- **核心：** harm_score 路由 RAG / Vanilla / IDK，主优化 RHR。  
- **补 G#：** G6（主）+ G1 + G2  
- **差一句：** Corrective 优化相关三态；我们优化 **Vanilla 对、RAG 错的恢复**。  
- **一周可做：** ✅（与 RH-ACS 重叠，易被说换皮）

---

## Top-3 排序

| 排名 | 方法 | 理由 |
|------|------|------|
| **1** | **RH-ACS+** | G1/G2/G3/G6；差界最硬；已有 07 共识 |
