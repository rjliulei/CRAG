## 1. 已有研究说「能实现」，我们还要改什么？

### 1.1 两层问题要分开

| 层次 | 已有文献大致回答 | Step 4 要回答 |
|------|------------------|---------------|
| **能不能做** | Self-RAG、Sufficient Context、KDD Cup CRAG 等：证据不足时应 abstain；支持度/置信度 **可以实现** | — |
| **在我们这条链路上有没有用** | **没有自动保证** | 同协议下 RAG vs RAG+门控 有没有 **可测增量** |

文献说「能实现」≠ 在 **CRAG + Llama-3.1-8B + MiniLM 切句 + HTML 噪声 + DeepSeek 裁判 + 本地 200 子集错误分布** 上「值得继续押 4 周」。

### 1.2 修改（v1 支持度阈值）的具体意义

**不是**重复证明「拒答这个概念成立」，而是：

1. **go / no-go 决策**  
   全量已证：RAG 抬 acc 同时抬幻觉；Phase B Top-3 = 生成错 / 过度检索 / 缺证据。  
   Step 4 验证：**只加一道规则门控、不动模型不训练**，能否 measurable 压幻觉、抬 score？  
   - 有效 → 主线成立，再 v2 / 全量 / 更重方法  
   - 无效 → **负结果也有价值**：改打检索纠错或 rag_worse 一致性，避免白烧工程  

2. **测最轻的一档，定位该用多重的药**  
   文献多用训练/reflection/大模型；我们用 **max 余弦分 + 阈值**。  
   - v1 有效 → 瓶颈含「低支持度仍硬答」，轻量规则够用  
   - v1 无效 → 单靠检索分数不够，要上 v2 或改检索  

3. **同一协议 before/after**  
   同一 `RAGModel`、同一 200 子集、同一裁判、同一四指标 → **可复现对照表 + case**，供预实验报告与 Day12 去留。文献表格无法直接替你们对齐这条链。

4. **与错误类型对齐，非泛泛降幻觉**  
   v1 打 **缺证据 + 部分生成错**；**不声称**一次解决 **rag_worse（过度检索）**——那留给 v2。  
   修改的意义 = **错误驱动的最小分流实验**。

5. **预实验阶段的决策价值 > 论文首创**  
   Day12 问「清晰增量」：有 → 立项；无 → 转向。比「别人论文里实现了」对 **当前阶段** 更实用。

### 1.3 宜说 / 不宜说

| 不宜 | 宜 |
|------|-----|
| 我们发明了证据不足拒答 | 已有 selective abstention；我们在 CRAG 噪声网页 + 本地失败模式上用 **最小规则门控** 做 **同协议对照** |
| 我们复现 Self-RAG SOTA | 我们检验 **轻量门控** 对我们实测瓶颈（RAG 幻觉↑）是否有 **可复现增量** |

**一句话：** 已有研究说机制能实现；我们要证明在 **我们的 CRAG 栈、我们的失败模式、我们一两天能跑完的最小改法** 上 **有没有用、用到什么程度、下一步该轻还是该重**。

## 2. 创新点要不要限制在某个模型？

### 2.1 结论

**不必把创新点绑死在某个 checkpoint**；**预实验必须固定一个模型做对照**（控制变量 ≠ 理论边界）。

| 层次 | 内容 | 是否绑死 Llama-3.1-8B |
|------|------|-------------------------|
| 问题设定 | CRAG 嘈杂网页；有检索仍幻觉 / rag_worse | ❌ |
| 方法 | 证据支持度（+ 可选答案–片段一致性）→ 答/拒 | ❌ 原则上模型无关 |
| 实证 | RAG vs RAG+门控 四指标 + case | ✅ 实验时固定 8B |

### 2.2 实验 vs 表述

**Step 4（现在）**

- 固定：Llama-3.1-8B + MiniLM + DeepSeek 裁判 + 200 子集  
- **不要**为 Step 4 换模型——否则无法归因  

**写贡献 / 开题**

- 主实验：「在 CRAG 上、以 Llama-3.1-8B 为 backbone 验证…」  
- 机制表述：「方法不依赖特定生成模型；门控在检索分数上，与 LLM 解耦」  
- 若只测 8B：加 **Limitation**「未在其他规模上验证」，**不要**写「8B 专用创新」  

**若后续正式论文**

- 主结果 8B + **至少 1 组**换模型/换检索消融，或明确 limitation  

### 2.3 一般不绑定的组件

- **裁判**（DeepSeek）：评测工具，非方法一部分  
- **检索编码器**（MiniLM）：基线管线；若只改门控，不必声称 MiniLM 创新  

### 2.4 创新点措辞草案（读完 Sufficient Context / UAEval4RAG 后可改）

> 在 CRAG 噪声网页设定下，基于检索证据支持度（及可选的答案–片段一致性）做答/拒决策，在固定 RAG 基线上压幻觉并抬 score；针对「有检索仍硬编 / 检索后更差（rag_worse）」等本地主导失败模式，而非再发明通用拒答提示或绑定单一 LLM。

对照表见 [09-精读论文清单.md](../09-精读论文清单.md) §5。

## 4. 给自己看的一句话

学界方案多，说明 **问题值钱**；我们的价值是 **本地实证瓶颈 → 最小可对照改法 → 量出有没有增量 → 决定轻规则还是重方法、继续还是转向**。创新在 **设定 + 机制 + 失败模式**，不在「只适用于 8B」。
