## 1. 论文用了两个评价模型，为什么本地只用 DeepSeek？

### 1.1 论文 vs 本地

| 维度 | CRAG 论文 | 本地（截至 2026-08-24 实验） |
|------|-----------|------------------------------|
| 裁判 | **GPT-3.5-turbo + Llama-3-70B**，两路打分后**取平均** | **DeepSeek-V3.2 单裁判**（硅基流动） |
| 入口脚本 | 论文 / 竞赛平台自有 pipeline | `local_evaluation_deepseek.py` |
| 目的 | 官方 leaderboard、Table 11 | 本地对比 Vanilla / RAG / RAG-KG |

### 1.2 为什么改成 DeepSeek 单裁判？

1. **成本**：原版 `local_evaluation.py` 默认 **GPT-4** 裁判；全量 2706 条 API 费用高。工作记录中已决定「省钱换模型」，故新增 `local_evaluation_deepseek.py`。
2. **仓库未实现双裁判**：`local_evaluation.py` 每次只接受一个 `EVALUATION_MODEL_NAME`。Llama-70B 裁判分支为占位，会直接 `NotImplementedError`。
3. **Meta 开源的是单裁判 auto-eval 框架**，不是论文 leaderboard 的「GPT + Llama-70B 双平均」流水线。

### 1.3 对研究的影响

| 场景 | 是否受影响 |
|------|------------|
| Vanilla ↔ RAG ↔ 自研方法 **相对对比** | **不受影响**（应固定同一裁判、同一数据集） |
| 与论文 Table 11 **逐数字对齐** | **不能**当作严格复现（还有模型 3 vs 3.1、题集、混合 Task 等差异） |
| 边界样本判定 | 单 DeepSeek vs 双裁判平均，accuracy / hallucination 可能漂移 |

### 1.4 若要对齐论文双裁判（可选，成本高）

1. `local_evaluation.py` + GPT-3.5/4 跑一遍并落盘 `api_responses/`。
2. 自实现 Llama-3-70B 本地裁判（或第二路 API 大模型）。
3. 脚本对两路指标**取平均**。

日常调研：**同配置下的相对差**比硬对齐论文更重要。

## 2. 论文说 30% / 30% / 40% 拆分，为什么没看到三个数据集文件？

### 2.1 论文划分 vs 实际发布

| 子集 | 比例 | 是否公开下载 |
|------|------|--------------|
| Validation | 30% | ✅ 已发布 |
| Public test | 30% | ✅ 已发布 |
| Private test | 40% | ❌ **不发布**（竞赛 Phase 2 / 防刷榜） |

官方只发布 **validation + public test = 60%**，合并为一个开发集文件，**没有**三个独立下载包。

本地已有文件：

- `data/crag_task_1_and_2_dev_v4.jsonl.bz2`（2706 条）
- `data/crag_task_1_and_2_dev_v5.jsonl.bz2`（更新版，多 `popularity` 字段）

### 2.2 拆分信息在哪？

每条样本的 **`split` 字段**（见 `docs/dataset.md`）：

| `split` | 含义 |
|---------|------|
| `0` | validation |
| `1` | public test |

**v4 实测计数（2026-08-26）：**

```text
split=0 (validation):  1371 条
split=1 (public test): 1335 条
合计:                  2706 条
```

推算全量约 4510 条，private 约 1804 条（40%）未公开。

`example_data/dev_data.preview.json` 中可见 `"split": 1` 等示例。

### 2.3 为什么感觉「没看到拆分」？

1. 文件名是 `*_dev_*`，把 validation + public **打成一个包**。
2. `local_evaluation*.py` **不筛 split**，默认整文件 2706 条一起评。
3. 论文 Table 数字多基于 **public test（1335）**；我们已跑的是 **2706 全量 dev**。

### 2.4 与 Task 1/2/3 勿混

- **`split`**：validation vs public test 的**数据划分**。
- **Task 1/2/3**：**评测环境**（网页页数、Mock API），Task1/2 共用同一份 `crag_task_1_and_2_dev_*.jsonl.bz2`。

### 2.5 对齐论文：只评 public test

```python
import bz2, json, os

src = "data/crag_task_1_and_2_dev_v4.jsonl.bz2"
out = "example_data/dev_public_test_only.jsonl.bz2"
os.makedirs("example_data", exist_ok=True)

with bz2.open(src, "rt") as fin, bz2.open(out, "wt") as fout:
    for line in fin:
        if json.loads(line).get("split") == 1:
            fout.write(line if line.endswith("\n") else line + "\n")

print("written ->", out)
```

`.env` 设 `DATASET_PATH=example_data/dev_public_test_only.jsonl.bz2` 后再跑评测。

## 3. 结论（一句话）

- **裁判**：论文双模型是官方 benchmark 设计；本地 DeepSeek 单裁判是**省钱 + 本地基线自洽**的工程取舍，不是漏跑。
- **数据**：拆分已做，内嵌在 `split` 字段；private 40% 从未发布；全量 2706 用于方法对比合理，对齐论文 Table 需筛 `split=1`（1335 条）。
