## 1. v2 跑了什么、数字怎么读


| 运行                   | score  | accuracy | hallucination | missing |
| -------------------- | ------ | -------- | ------------- | ------- |
| RAG 原版（子集）           | −0.30  | 24.5%    | 54.5%         | 21.0%   |
| v2 答案–片段一致性 sim=0.25 | −0.225 | 19.5%    | 42.0%         | 38.5%   |
| v2 答案–片段一致性 sim=0.35 | −0.175 | 16.5%    | 34.0%         | 49.5%   |


评分：`score = (2×correct + miss) / n − 1`。

### 机制（实现方式）

```text
检索 top-k → LLM 生成 → 答案向量 vs 片段向量（MiniLM 余弦）
                         → max(sim) < 阈值 → 改成 "I don't know"
                         → 否则保留原答案
```

代码：`models/rag_llama_baseline.py`（`RAG_ABSTAIN_V2_*`，生成后检查）。

### 准确表述（避免误读「有效」）


| 说法                                  | 是否成立              |
| ----------------------------------- | ----------------- |
| 相对子集 baseline：hallucination↓、score↑ | ✅                 |
| 准确率上来了                              | ❌（24.5%→16.5%，在掉） |
| 绝对水平变好 / 接近全量 RAG 正分                | ❌（score 仍为负）      |
| 检索或生成「更会答」了                         | ❌（只是把不少硬答改成拒答）    |


**一句话：** v2 提升的是「少扣分」（幻觉→拒答），不是「答对能力」。若研究目标是检索增强问答变好，**不宜把 v2 当主创新或主结论**。

## 2. 「和答案比较」是不是作弊？

### 不是泄题 / 对标准答案

v2 **没有**使用 gold answer、裁判标签或评测答案；只比较：

- 模型**自己生成**的文本；
- **同题检索到的** top-k 片段。

因此不是对答案、不是刷测试集标签。

### 但可以算「刷分偏好」

CRAG 对幻觉重罚、对 missing 相对宽容。事后把「不像证据的回答」改成 IDK，会系统性抬 score，同时误杀部分本来正确的题。


| 视角                   | 结论                                         |
| -------------------- | ------------------------------------------ |
| 工程 / faithfulness 后检 | 合法技术（文献里也有类似一致性/忠实度检查）                     |
| 研究叙事（「RAG 变强了」）      | **偏虚**——主结果若只报 score↑ 而回避 accuracy↓，容易像刷公式 |
| 本项目取舍                | v2 **降级为辅助对照 / 消融 / limitation**，不作为主攻方向   |

## 3. 正当主攻：大方向与思路

原则：**决策尽量在开口之前或改检索；少靠「答完不像就改 IDK」抬分。**

错误分析已有三类失败（Phase B Top-3 + rag_worse），三刀分别打：


| 失败模式                 | 该打哪里       | 正当思路                       |
| -------------------- | ---------- | -------------------------- |
| **过度检索 / rag_worse** | 喂进 LLM 的证据 | 生成前过滤噪声、纠检索、冲突检测           |
| **缺证据**              | 该不该答       | 答前「证据是否可支撑」→ 拒答            |
| **生成错**              | 怎么生成       | 证据约束生成（短答 / span / 核对后再开口） |


### 方向 1 · 检索侧降噪（优先，对准 rag_worse）

- **问题：** 高分片段仍可误导；Vanilla 对、RAG 错的 25 条典型如此。  
- **思路：** 检索后、生成前，丢掉明显无关/冲突句；必要时二次检索或缩小 top-k。  
- **期望：** 有机会 **accuracy 与 score 一起动**（而不只是 missing↑）。  
- **文献锚点：** Corrective RAG（纠检索）、Astute RAG（不完美检索与冲突）。  
- **详细规划：** [20260829-02-方向1-检索侧降噪原理与验证步骤.md](./20260829-02-方向1-检索侧降噪原理与验证步骤.md)（是什么/为什么/怎么办、算法分档、验证 Step 0–6）

### 方向 2 · 答前「可支持性」门控（正当拒答）

- **问题：** v1 用「问题–片段相似度」代理「证据够不够」→ 子集上 max 分普遍偏高，门控几乎不触发。  
- **思路：** 不问「像不像」，问「这些片段能否支撑回答该题」（槽位覆盖、粗粒度蕴含、假前提等）。拒答发生在**生成前**。  
- **期望：** hallucination↓，且尽量少误杀正确题。  
- **文献锚点：** Sufficient Context、UAEval4RAG、RGB（噪声下该拒不拒）。

### 方向 3 · 证据约束生成（抬准确率）

- **问题：** 有检索仍自由发挥 → 生成错。  
- **思路：** 有证据才生成，答案尽量来自片段（短答、实体/数字拷贝、禁止无依据发挥）。  
- **期望：** **correct↑**，而不只是 hallucination→missing。  
- **文献锚点：** Self-RAG（IsSup 等，偏训练；本地可先用规则近似）。

### 方向 4 · v2 的位置

- 保留开关，作 faithfulness 后检对照。  
- 写进 limitation：改善 score ≠ 检索变好。  
- **主论文/预实验叙事不要押在 v2 上。**

## 4. 建议推进顺序（近 1–2 周）

```text
1. 固化表述：v1 信号错位无效；v2 仅「少胡说抬分」，accuracy↓
2. **（若要方法新）** 按 [头脑风暴指南](./20260829-03-方法创新头脑风暴指南.md) 开会 → 填候选贡献句
3. 主攻：入选创新假设的最小验证（200 子集；生成前机制优先）
4. 工程基线可并行：方向1 档 A（top-k）作强对照，不当主创新宣称
5. 有信号后再：消融 + Related Work 差界；可选全量复核
```

### 本阶段明确不做

- 再扫 v1 的 τ=0.35/0.45  
- 未经验证就全量 2706  
- 换更大生成模型 / 上 RAGFlow 当主线  
- 把 v2 写成「主要贡献」

### 成功标准（修正）


| 方法类型         | 更看重的信号                                 |
| ------------ | -------------------------------------- |
| 检索降噪 / 约束生成  | **accuracy↑**（或 correct 数↑），score 同步不掉 |
| 答前可支持性拒答     | hallucination↓，误杀正确题可控，score 可升        |
| 仅事后一致性拒答（v2） | 只作对照，不单独宣称「方法有效」                       |
