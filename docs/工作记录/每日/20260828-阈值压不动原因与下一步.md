## 2. 为什么阈值压不动？（原因分析）

### 2.1 直接证据：门控几乎没触发

v1 规则：`max(cosine_scores) < τ` → 强制 `I don't know`。

若规则生效，**missing 必须上升**（强制拒答会计入 missing）。  
三次有效跑 **`n_miss` 全是 42** → 几乎没有样本被规则拦下。

τ=0.30 相对 baseline：正确 +1、幻觉 −1、missing 不变 → 符合 `temperature=0.1` 的波动，**不是拒答收益**。

### 2.2 机制层面：测错了「证据不足」的代理量

| 真实需要 | v1 实际用的信号 |
|----------|-----------------|
| 「这些片段是否足以支撑正确答案？」 | 「问题与 top 句的向量相似度高不高？」 |

相似度高 ≠ 证据充分：

- HTML 切句后，同主题句子很容易和 query 很像（实体名、题型词重复）→ **max 分偏高**；
- 高分片段仍可含噪声、过时信息、错列表项 → 模型照样幻觉（Phase B：**过度检索 / rag_worse**）；
- 「缺证据」类也可能仍有若干相关句，max 分不一定掉到 0.30 以下。

因此 τ=0.40、甚至 0.30，对多数题都「过得了门」——**阈值不是太紧，而是信号本身与失败模式不对齐**。

### 2.3 与错误分析早已对齐（方案文档已预警）

`20260827-Step4最小修改方案.md` §5：

> 过度检索 25 条全来自 `rag_worse_hallucination`——检索分数**不低**，但片段**误导**。**max 阈值压不住。**

Phase B Top-3：生成错 / **过度检索** / 缺证据。  
v1 最多指望压「max 分极低」的缺证据；子集上这类占比不足以拉动四指标，且实测几乎触发不到。

### 2.4 工程因素（已排除为主因）

| 因素 | 状态 |
|------|------|
| `.env` 在 `import UserModel` 之前未加载 | 已修；`…002518` / `…003532` 为修复后跑次 |
| 仍完全同 baseline（0.40） | 更支持「阈值几乎不触发」而非「开关仍坏」 |
| 裁判 / 数据不一致 | 同 200 子集、同 DeepSeek、同 RAGModel |

**待补强（下一步诊断）：** 显式落盘每题 `max_score`，确认 `<0.40` / `<0.30` 的条数是否接近 0。

### 2.5 小结（可写进预实验报告）

```
阈值压不动
  = 门控几乎不触发（missing 不变）
  + max 余弦分 ≠ 证据充分性
  + 主失败模式是「高分噪声 / 生成不忠于证据」，不是「检索分极低」
```

继续盲扫 τ=0.35/0.45 **期望收益极低**；把 τ 抬到 0.55+ 可能误杀正确样本，且未验证分布前不建议。
