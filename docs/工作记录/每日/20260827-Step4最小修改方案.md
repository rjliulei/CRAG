**最小修改 = 只改一个决策点、只动一个文件**：在 **检索之后、LLM 生成之前** 加一道 **证据支持度门控**。

## 2. Step 4 v1 机制：检索支持度阈值 → 拒答

对每道题，在已有 `cosine_scores` 上取：

```text
support = max(cosine_scores)   # 备选：mean(top-5)
```

若 `support < τ`（阈值 τ，如 0.35–0.45，在 200 子集上调）：

→ **不调用 LLM**，直接返回 `"I don't know"`。

否则：走原流程（拼 References → `llm.generate`）。

### 为什么选这个当「最小」？

1. **零额外模型调用**，不烧 API、不增显存。
2. **信号已经算出来了**，原基线只用于取 top-k，未用于决策。
3. **对应 Phase B Top-3 里两类**：
   - **缺证据**（22/110）：检索整体弱 → max 低 → 该拒
   - **生成错**（38/110）：片段不太相关仍硬答 → 低支持度门控可压一部分

### 与现有 prompt 的区别

基线 prompt 已有「references 不够就说 I don't know」，但 LLM 常不听。  
Step 4 是 **规则层强制拒答**，不是再改 prompt——对应待办 Day10「规则最小改进」。

## 3. 伪代码（实现参考）

```python
# CONFIG 区
RAG_ABSTAIN_ENABLED = os.getenv("RAG_ABSTAIN_ENABLED", "0") == "1"
RAG_ABSTAIN_MIN_MAX_SCORE = float(os.getenv("RAG_ABSTAIN_MIN_MAX_SCORE", "0.40"))

# batch_generate_answer 内，每个 _idx 循环
max_score = float(cosine_scores.max()) if len(cosine_scores) else 0.0

if RAG_ABSTAIN_ENABLED and max_score < RAG_ABSTAIN_MIN_MAX_SCORE:
    batch_retrieval_results.append([])
    abstain_flags.append(True)
else:
    retrieval_results = relevant_chunks[(-cosine_scores).argsort()[:NUM_CONTEXT_SENTENCES]]
    batch_retrieval_results.append(retrieval_results)
    abstain_flags.append(False)

# 生成后（或生成前短路）
for i, abstain in enumerate(abstain_flags):
    if abstain:
        answers.append("I don't know")
    else:
        answers.append(responses[j].outputs[0].text)
        j += 1
```

## 4. 预期指标变化

| 指标 | 预期 |
|------|------|
| **hallucination** | ↓（主目标） |
| **missing** | ↑（可接受；CRAG 对 missing 不扣分） |
| **score** | ↑ 若少幻觉收益 > 少答对损失 |
| **accuracy** | 可能略↓ |

判读（见 `08-Step4后续工作细化.md`）：

| 现象 | 下一步 |
|------|--------|
| hallucination↓ 且 score↑ | 继续主线 → Day11 消融 |
| 几乎不动 | 调 τ 或加 v2 |
| missing 暴涨、score 掉 | 阈值过狠，收窄条件 |

## 5. v1 刻意不做（留给 v2 / Day11）

Phase B：**过度检索 25 条全来自 `rag_worse_hallucination`**——检索分数**不低**，但片段**误导**。**max 阈值压不住**。

| 机制 | 打什么 | 复杂度 |
|------|--------|--------|
| top1 − top2 分数差太小 → 拒答 | 检索歧义 | +几行 |
| 生成后：答案与 top-k 片段相似度/重叠 → 不一致则拒答 | rag_worse | +一次 encode 或规则 |
| 声明分解 + 逐条核对 | 生成错 | 明显更重 |

**顺序**：先只上 v1，看 200 子集四指标；有信号再叠 v2 打 `rag_worse`。

### 与错误类型对应

```
                    ┌─ max_score 低 ──→ v1 阈值拒答 ──→ 压「缺证据」「部分生成错」
检索 → 打分 → 决策 ─┤
                    └─ max_score 高但答错 ──→ v2 一致性检查 ──→ 压「过度检索/rag_worse」
```

## 7. 一句话

**最小修改 = 在 `RAGModel.batch_generate_answer` 里，用已有 top-k 余弦相似度的 max 做支持度门控；低于阈值直接 `I don't know`，高于阈值保持原 RAG 不变。** 改的是「该不该让 LLM 开口」，不是检索算法、生成模型或评测公式。
