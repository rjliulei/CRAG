## 1. 是什么？

**检索侧降噪** = 在 **LLM 生成之前**，对已经检索到的候选片段做筛选/重排/纠偏，让 prompt 里的 References **更少噪声、更少互相打架**，再让模型答题。

```text
当前基线：
  HTML → 切句 → 与问题算相似度 → 取 top-20 全文塞进 prompt → 生成

方向1（插入点）：
  HTML → 切句 → 相似度打分 → 【降噪 / 纠检索】→ 更干净的 top-k' → 生成
```

| 它是 | 它不是 |
|------|--------|
| 改「喂给模型看什么」 | 改裁判、改评分公式 |
| 生成前动作 | 生成后拿答案去比片段再改 IDK（那是 v2） |
| 对准 `rag_worse` / 过度检索 | 单独解决「完全没证据」时的拒答（那是方向2） |

---

## 2. 为什么要做？

### 2.1 本地证据

- 200 子集里 **`rag_worse_hallucination` = 25 条**：Vanilla 答对，加上网页 RAG 反而幻觉。  
- Phase B 把这 25 条几乎全标成 **过度检索**：不是「没检索到」，而是 **检索到的东西把模型带偏了**。  
- Step4 诊断：`max_score` 中位数 ≈ **0.75**，正确题与幻觉题分数分布接近 → **「和问题很像」≠「是好证据」**。  
- v1 阈值拒答几乎不触发；v2 事后拒答能抬 score，但 **accuracy 下降** → 说明还需要 **把证据弄干净**，才有机会答对。

### 2.2 一个直观例子（来自错误分析）

**题（set）：** Pixar 2017 年之后上映了哪些电影？  
**标准答案侧：** 不含 *Toy Story 4*（按标注口径）。  
**现象：** 网页里大量 Pixar / Toy Story 相关句，和问题实体重合度高 → 余弦分很高 → top-20 里塞满「像相关」的片单、导语、推荐文。  
**模型行为：** 按列表「汇总」时把 TS4 等也写进去 → **幻觉**。  
**Vanilla：** 没被这些网页带跑，反而可能答对或更保守。

**降噪要做的事：** 生成前丢掉「只共现品牌词、但不支持『2017 后片单』约束」的句子，或压低 top-k，避免模型做「网页大杂烩」。

```text
问题：2017 之后的 Pixar 电影？
高分噪声句：「Toy Story 4 is a Pixar film…」（像，但可能不满足年份约束 / 或不在 GT）
有用句：带明确年份、片名单且与提问约束一致的句子

降噪目标：少喂前者，多留（或只留）后者；喂不干净就宁可少喂，而不是塞满 20 句。
```

### 2.3 和「我们想要的效果」对齐

| 想要的效果 | 降噪如何贡献 |
|------------|--------------|
| **accuracy↑** | 少被误导 → 少把对的改错（尤其 rag_worse） |
| **hallucination↓** | 少根据噪声编列表/编日期 |
| **score↑ 且不只靠拒答** | 正确数 ideally↑；拒答不是唯一手段 |
| 研究叙事站得住 | 改的是检索质量，不是刷 missing |

## 3. 怎么办？（流水线位置）

只动 **cosine 排序之后、`format_prompts` 之前** 这一段；Vanilla / 评测脚本不动。

```text
relevant_chunks + cosine_scores
        │
        ▼
 ┌─ 降噪模块（本方向）─────────────────────┐
 │  A. 收紧数量 / 相对阈值                   │
 │  B. 去冗余（MMR 等）                      │
 │  C. 相关性再判断（相对分、关键词、可选重排） │
 │  D.（可选）冲突检测 → 丢冲突或整题保守     │
 └──────────────────────────────────────────┘
        │
        ▼
  batch_retrieval_results（更短、更干净）
        │
        ▼
  format_prompts → llm.generate
```

环境变量建议（与 v1/v2 并列，便于消融）：

| 变量 | 含义 | 示例 |
|------|------|------|
| `RAG_DENOISE_ENABLED` | 总开关 | `0/1` |
| `RAG_DENOISE_MODE` | 算法档位 | `topk` / `rel_thresh` / `mmr` / `corrective_lite` |
| `RAG_CONTEXT_K` | 最终喂给模型的句数 | `5` / `8`（基线 20） |
| 其它 | 随算法增加 | 见 §4 |

## 4. 加入什么算法？能达到什么效果？

按 **实现成本 ↑、能力 ↑** 分档。预实验建议 **先 A → 再 B/C → 有信号再 D**，不要一上来上重模型。

### 档 A · 最小改动（半天，必做）

| 算法 | 做法 | 期望效果 | 风险 |
|------|------|----------|------|
| **Top-k 收紧** | `NUM_CONTEXT_SENTENCES` 20→**5 或 8** | 少喂噪声；rag_worse 可能下降；accuracy 有机会↑ | 真证据排在 10+ 名时被切掉 → missing/错答↑ |
| **相对阈值** | 只保留 `score ≥ α · max_score` 的句（如 α=0.85） | 去掉「远低于最相关句」的尾巴噪声 | α 过大只剩 1–2 句，信息不足 |

**为何可能有效：** 当前固定塞 20 句，噪声网页下「第 6–20 名」经常是同主题闲聊；诊断显示分数整体偏高，**相对差距**比绝对阈值更有用。

### 档 B · 轻量结构（1 天）

| 算法 | 做法 | 期望效果 | 风险 |
|------|------|----------|------|
| **MMR 去冗余** | 在 top-N 候选里迭代选句：相关且与已选句不重复 | 列表题少「同一片单复制 10 遍」带偏 | 参数 λ 需调 |
| **查询词/实体覆盖过滤** | 句中需命中问题关键实体或约束词（年份、专名） | 对准 Pixar+2017 这类 **带约束** 题 | 改写句、代词句被误杀 |

**文献关系：** 工程常用；不声称新算法，作为 CRAG 噪声页上的 **最小可行降噪**。

### 档 C · 纠检索（对齐 Corrective RAG，2–3 天）

Corrective RAG 思想：**先判断检索是否可靠，不可靠则纠正（过滤 / 再检索），再生成。**  
本地不做网页外搜时，可做 **Corrective-lite**：

| 步骤 | 本地近似 |
|------|----------|
| 文档相关性分级 | 用已有 MiniLM：相对 max 分过低 → Irrelevant 丢掉；保留 Supportive |
| 不确定时 | 缩 top-k 或触发「仅用最高分 1–3 句」；**暂不接外网** |
| 再生成 | 只用过滤后集合 |

| 算法 | 期望效果 | 说明 |
|------|----------|------|
| **Corrective-lite（相对分 + 缩窗）** | 对准过度检索；accuracy 有机会与 score 同向 | 与论文完整版差在「web 再检索」；贡献写成 CRAG 设定下的轻量纠检索即可 |
| **（可选）交叉编码器重排** | 句级相关更准 | 需加模型与显存；有信号再上 |

### 档 D · 冲突感知（对齐 Astute，有余力再做）

| 算法 | 做法 | 期望效果 |
|------|------|----------|
| **片段间冲突检测** | 同实体不同年份/不同名单 → 标记冲突 | 减少「拼错列表」；冲突强时可拒答或只信最高分来源 |
| **来源感知合并** | 分页面聚合再选代表句 | 降低多页复制噪声 |

适合解释 **rag_worse**；实现重于 A/B，作 v1.1 而非第一刀。

### 算法与效果对照（预实验怎么选）

| 目标 | 优先算法 |
|------|----------|
| 最快验证「少喂是否减伤」 | **A：k=5/8 + 相对阈值** |
| 列表/set 题少重复误导 | **A + B：MMR** |
| 叙事对齐 Corrective RAG | **C：Corrective-lite** |
| 专打 Vanilla 对、RAG 错 | 在 A/C 上看 **`rag_worse` 桶正确率/幻觉率`** |
| 暂不采用（本阶段） | 生成后答案–片段改 IDK 当主结果；全量外网二次检索 |

## 5. 验证步骤（规划）

成功标准（本方向专用，继承 08-29 修正）：

- **主指标：** 相对子集 RAG baseline，**accuracy↑**（或 `n_correct`↑），score **不降**（最好升）。  
- **辅指标：** hallucination↓；missing 变动需解释（降噪不应只靠狂拒答抬分）。  
- **桶指标：** `rag_worse_hallucination`  ideally 条数↓或其中改对↑。  
- **不达标：** 仅 score↑ 且 accuracy↓ → 记为失败/需改参，不宣称降噪成功。

对照锚点（已有）：

| 运行 | score | accuracy | hall. | miss. |
|------|-------|----------|-------|-------|
| 子集 RAG baseline | −0.30 | 24.5% | 54.5% | 21% |

### Step 1 · 诊断「20 句里有多少噪声」（0.5–1 天，建议先做）

**目标：** 证明「降噪有东西可删」，并给 α、k 定范围。

- [ ] 扩展/复用 `diagnose_retrieval_scores.py`：对每题输出 top-20 的 score 列表、`score/max`、可选「与 query 实体重叠」  
- [ ] 统计：top-20 中 `score < 0.85·max` 的平均句数；rag_worse vs correct 的差异  
- [ ] 人工抽 **5 条 rag_worse + 5 条 correct**：看第 6–20 句是否明显噪声  

**产出：** 一张小表 + 是否支持「先砍 k / 相对阈值」。

### Step 2 · 档 A 对照实验（1 天，主验证）

### Step 3 · 桶级验证（与 Step 2 同一批预测即可）

- [ ] 用子集 manifest / 旧标签，对比 baseline vs 最佳降噪配置：

- [ ] **判定：** rag_worse 改善且 rag_helps 误伤可控 → 方向1 成立；只伤 helps → 降噪过激。

## 7. 一句话

**检索侧降噪 = 生成前把「和问题很像但会带偏」的网页句子拿掉或少喂；先用收紧 top-k + 相对阈值验证 accuracy 能否上来，再按需加 MMR / Corrective-lite，专打 rag_worse，而不是再用事后改 IDK 刷分。**
