截至 **2026 年 8 月**，你问的“**RAG 在证据不足时主动拒答，而不是幻觉作答**”已经形成了比较清晰的研究分支，但仍处于快速发展阶段。现在的前沿问题已经不是简单的“有没有检索到相关文档”，而是：

> **检索到的证据是否足以支撑回答？如果不足，模型应该继续检索、部分回答、请求澄清，还是直接拒答？**

这也是我认为你比较适合切入的点。

### 1. 第一阶段：发现“RAG ≠ 不会幻觉”

较早的工作重点是证明：**给模型接入检索，并不能自动解决幻觉问题。**

RGB Benchmark 系统考察了 RAG 的四种能力：噪声鲁棒性、negative rejection、信息整合和反事实鲁棒性，而且同时提供中文、英文数据。它发现模型尤其难以处理“没有足够信息回答”的情况，也就是说，**即使检索结果没有答案，模型仍倾向于回答。** ([arXiv][1])

RAGTruth 在 ACL 2024 又进一步表明，即使模型已经拿到了检索上下文，生成答案仍然可能出现**没有证据支持的内容或与证据相矛盾的内容**。该数据集提供近 18,000 条人工标注的 RAG 输出，并进行了细粒度幻觉标注。([ACL Anthology][2])

所以这一阶段形成了一个基本共识：

[
Retrieval \neq Grounding
]

即：

> “检索到了文档”不等于“模型的答案得到了这些文档支持”。

---

### 2. 第二阶段：从固定 RAG 转向“自适应 RAG”

2024 年左右，一个很明显的趋势是让 RAG 自己判断：

> 要不要检索？
> 检索结果有没有用？
> 要不要再检索？

比较典型的是 **Self-RAG**。它引入 reflection tokens，让模型判断是否需要检索、文档是否相关、回答是否受到证据支持以及回答是否有用，而不是固定执行一次 Top-K Retrieval → Generation。([arXiv][3])

**Corrective RAG（CRAG）** 则增加一个 retrieval evaluator：

[
Query \rightarrow Retrieval
\rightarrow Retrieval\ Evaluator
\rightarrow Correct / Incorrect / Ambiguous
]

如果检索质量不好，可以采取新的搜索或纠正措施，而不是直接把低质量上下文交给生成模型。([arXiv][4])

但这一阶段的核心问题仍然偏向：

> **“文档质量怎么样？”**

而不是：

> **“这些文档是否已经足够回答这个问题？”**

这两个问题并不完全相同。

---

## 3. 2025 年出现一个非常重要的转折：Evidence Sufficiency

这一点和你刚才提出的研究问题几乎完全重合。

ICLR 2025 的 **Sufficient Context: A New Lens on Retrieval Augmented Generation Systems** 明确提出了 **Sufficient Context** 概念：

> 给定当前检索上下文，它是否包含回答这个问题所需要的充分信息？

作者发现一个非常重要的现象：

**当上下文充分时，一些大型闭源模型表现很好；但当上下文不充分时，它们往往不是拒答，而是继续生成错误答案。**

因此作者进一步做了 selective generation：

[
Sufficient\ Context
\rightarrow Answer
]

[
Insufficient\ Context
\rightarrow Abstain
]

利用 sufficient-context 信号进行拒答后，模型在“选择回答的问题”上的正确率能够进一步提高。([arXiv][5])

这基本把研究问题从：

> Retrieval Relevance

推进到了：

> **Evidence Sufficiency**

这也是目前最值得注意的变化。

---

# 4. 2025 年开始正式研究“Unanswerable RAG”

ACL 2025 的 **UAEval4RAG** 又向前推进了一步。

它指出以前 RAG benchmark 基本都在问：

> “系统能不能正确回答有答案的问题？”

但真实知识库中大量问题其实是：

> **知识库根本回答不了。**

所以 UAEval4RAG 专门研究 **unanswerable queries**，建立了 6 类不可回答问题的分类，同时提出 unanswered ratio、acceptable ratio 等指标。研究还发现：**不存在一种 RAG 配置可以在所有知识库上同时把“该回答的问题答好”和“该拒绝的问题拒绝好”。** ([ACL Anthology][6])

这意味着目前研究已经从：

[
Accuracy
]

转向：

[
Accuracy + Abstention
]

进一步转向：

[
Accuracy + Abstention + Calibration
]

---

# 5. 另一个前沿：证据冲突

现在研究者也意识到，“证据不足”只是问题的一种。

还有一种更困难的情况：

> **证据很多，但是互相矛盾。**

例如：

```text
Document A：
药物 X 推荐剂量为 20 mg。

Document B：
药物 X 推荐剂量为 40 mg。
```

传统 RAG 很容易随机选择一个。

ACL 2025 的 **Astute RAG** 专门研究 imperfect retrieval 以及：

[
Internal\ Knowledge
\leftrightarrow
Retrieved\ Knowledge
]

之间的冲突。它发现，检索结果中的错误信息、无关信息以及模型内部知识和外部知识之间的冲突，是 RAG 可靠性的关键瓶颈。([ACL Anthology][7])

因此现在 Evidence Sufficiency 实际上逐渐扩展为：

[
Evidence\ Quality
]

[
Evidence\ Coverage
]

[
Evidence\ Consistency
]

[
Evidence\ Conflict
]

四个问题。

---

# 6. 到 2026 年，研究开始从“拒答”升级成“决策”

这是最新的一个趋势。

研究者发现只做：

[
Answer / Abstain
]

其实过于简单。

更合理的是：

[
Answer
]

[
Retrieve\ More
]

[
Partial\ Answer
]

[
Clarify
]

[
Abstain
]

也就是说，从**二分类拒答**变成一个 **RAG Controller**。

ACL 2026 的 **S2G-RAG** 就非常典型。它加入一个 **S2G-Judge**，每一轮判断当前 evidence memory 是否已经足够回答。如果不足，它不是简单拒答，而是明确生成“缺少什么信息”，再把 information gap 转换为下一次检索 Query。([ACL Anthology][8])

结构实际上变成：

```text
Query
  ↓
Retrieve
  ↓
Evidence Memory
  ↓
Sufficiency Judge
  ├── Enough → Answer
  │
  └── Not Enough
          ↓
      Identify Gap
          ↓
      New Query
          ↓
      Retrieve Again
```

这比“Top-1 similarity < 0.6 就拒答”已经先进很多。

---

# 7. 多轮对话让这个问题更难

2026 年又出现一个明显变化：

**拒答研究从单轮 QA 扩展到了 Multi-turn RAG。**

MTRAG-UN 专门包含：

* Unanswerable
* Underspecified
* Non-standalone
* Unclear

四类真实对话问题。实验显示，即使当前 RAG 系统已经很强，在这些场景下仍然明显困难。([ACL Anthology][9])

而且 SemEval 2026 甚至专门设置了 **MTRAGEval**，吸引了 107 支注册队伍、92 个系统提交，说明“answerability / grounded generation”已经开始成为一个正式 benchmark 方向。([ACL Anthology][10])

非常值得注意的是，其中表现较好的系统分析发现：

> **当前主要瓶颈开始从 retrieval coverage 转向 answerability calibration。** ([ACL Anthology][11])

换句话说：

**不是模型“找不到东西”这么简单，而是模型“不知道自己找到的东西够不够”。**

---

# 8. 目前真正没有解决好的地方

截至目前，我认为这个方向有 6 个比较明显的研究空缺。

| 问题                             | 当前情况         |
| ------------------------------ | ------------ |
| 文档相关性                          | 已经研究很多       |
| Retrieval confidence           | 比较成熟         |
| Evidence sufficiency           | **正在快速发展**   |
| Partial evidence               | **仍然困难**     |
| Evidence conflict              | **热点问题**     |
| 多跳 evidence completeness       | **热点问题**     |
| Answer / Retrieve / Abstain 决策 | **前沿**       |
| 跨领域阈值 calibration              | **没有很好解决**   |
| 中文 evidence sufficiency        | **研究明显少于英文** |

其中最麻烦的就是 **Partial Evidence**。

比如问题：

> 马云在哪里出生，他哪一年创办阿里巴巴？

检索只有：

> 马云1964年出生于浙江杭州。

这时候：

[
Relevance = High
]

但：

[
Sufficiency = Low
]

因为只回答了一半。

目前单纯 Retriever Score、Reranker Score 都很难发现这个问题。

---

# 9. 还有一个非常现实的问题：拒答过头

这是你如果做论文一定要注意的。

模型全部回答：

> “根据现有证据无法回答。”

当然：

[
Hallucination=0
]

但这个系统完全没用。

2026 年 SemEval 的一个系统就是很典型的例子：它加入 Answerability Classifier 后，**75.5% 的回答被判成 IDK，其中包括 69.8% 本来可以回答的问题**。也就是说模型变得过于保守。([ACL Anthology][12])

因此真正研究的问题不是：

> 如何提高拒答率？

而是：

[
\boxed{
如何找到 Answer 与 Abstain 之间的最佳边界
}
]

这也是为什么现在越来越重视：

**Risk-Coverage**

而不是单纯的 Hallucination Rate。

---

# 10. 中文方面反而还有空间

目前中文已有一些基础。

例如 **RGB** 本身就是中英双语 Benchmark，而且包含 Negative Rejection。([arXiv][1])

2026 年也开始出现更细分的中文任务，例如 CFQA 使用中国上市公司 2023–2025 年年报构建中文金融 QA benchmark，并区分“错误答案”和“无证据捏造”等不同问题。([ACL Anthology][13])

甚至已经出现中英跨语言证据冲突研究，例如 2026 年的 X-MADAM-RAG，不过这篇目前属于预印本性质，而且作者自己也指出其受控 benchmark 存在模板化较强的问题，因此距离自然真实检索环境还有明显差距。([arXiv][14])

所以如果你想做**中文 RAG 论文**，反而存在一个比较明确的 gap：

> **中文 Evidence Sufficiency + Abstention Calibration 的系统性研究明显还不如英文成熟。**

---

## 我会怎样判断这个选题现在还有没有价值

我的判断是：

**有价值，但不能只做“加一个相似度阈值让模型拒答”。**

因为：

```text
Retriever Score < τ → Refuse
```

这种思路现在已经太简单。

比较有论文价值的是：

```text
                    Query
                      ↓
                  Retrieval
                      ↓
                  Reranker
                      ↓
             Evidence Decomposition
                      ↓
        ┌──────── Sufficiency ────────┐
        ↓             ↓               ↓
    Coverage       Conflict       Entailment
        └─────────────┬───────────────┘
                      ↓
                Decision Maker
          ┌───────────┼───────────┐
          ↓           ↓           ↓
       Answer    Retrieve More   Abstain
                      ↓
                 Gap Retrieval
```

所以如果你现在准备确定研究方向，我反而建议把题目从泛泛的：

**“RAG 幻觉检测研究”**

缩成：

> **面向中文检索增强生成的证据充分性感知与自适应拒答方法**

再进一步可以变成：

> **基于证据覆盖度与冲突感知的中文 RAG 自适应回答方法**

这两个题目都比单纯“降低 RAG 幻觉”更容易形成清晰的**研究问题、方法、Baseline、消融实验和创新点**。

而且从 **ACL 2025 的 UAEval4RAG → SemEval/ACL 2026 的 MTRAG-UN 与 S2G-RAG** 这条发展线来看，**Evidence Sufficiency + Answerability Calibration 正好是当前正在升温、但尚未完全做透的方向**。([ACL Anthology][15])
