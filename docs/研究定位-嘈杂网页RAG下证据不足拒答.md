# 研究定位：嘈杂网页 RAG 下「证据不足则拒答」——我们的工作还有什么意义？

> 日期：2026-08-26  
> 目的：在学界已有 Self-RAG / Corrective RAG / Sufficient Context / claim verification / CRAG 赛题方案的前提下，写清**我们还在做什么、不在做什么、预实验判据是什么**。  
> 证据基础：全量 Vanilla/RAG 对比、典型子集 200、错误分析 Phase A/B；见 `docs/工作记录/` 对应文档。

---

## 0. 先回答标题

**不是「发明一个从未有人做过的问题」。**  
「证据不足则拒答 / 声明支持度校验」在 2024–2026 已是成熟方向。

**我们的意义在于：在固定基准（CRAG）、固定失败模式（本地实测）、可控成本（规则最小改进）下，回答「这条线对我们观测到的瓶颈有没有可复现增量」。**

这是**预实验 / 方向验证**，不是重复造轮子写综述，也不是一上来对标 SOTA 训练框架。

---

## 1. 问题成立（本地已实证）

| 观测 | 数字 / 现象 | 与文献是否一致 |
|------|-------------|----------------|
| 检索抬分但幻觉同步升 | 全量 RAG：acc +7.5pp，幻觉 +5.7pp，score 仅 +0.014 | 与 Sufficient Context、CRAG 论文「朴素 RAG 不够」一致 |
| 敢答不等于会拒 | 子集 RAG 幻觉 **50%**（故意抬硬例） | 与 Evidence Sufficiency / RefusalBench「over-answer」一致 |
| 检索会伤人 | `rag_worse_hallucination` **25/200** | 与噪声检索、过度检索文献一致 |
| 假前提不是主瓶颈 | 子集 false_premise 几乎全 missing | 与「会拒假前提 ≠ 会拒证据不足」一致 |

→ **方向不是空想；本地数据已把「该不该做拒答/可信」拍板为继续。**

---

## 2. 学界已有什么（我们不声称首创）

简表（related work 骨架）：

| 类别 | 代表 | 他们解决什么 | 我们预实验阶段是否照搬 |
|------|------|--------------|------------------------|
| 自适应检索 + 自反思 | Self-RAG | 何时检索、是否支持 | 成本高（训练/特殊 token），暂不照搬 |
| 检索纠错 | Corrective RAG（Yan et al.） | 检索差则改写/补搜 | 偏检索侧；可作备选 A |
| 证据充分性 + 选择性生成 | Google Sufficient Context | 够不够答、何时弃权 | **思想对齐**；实现可简化为阈值 |
| 声明分解 + 核对 | HalluMeasure、RT4CHART 等 | 逐 claim 是否有据 | **与 Step 4 同构**；我们先做规则粗版 |
| 赛题工程经验 | KDD Cup 2024 CRAG 报告 | CoT、置信度、SFT、题型规则 | **直接可对照的强基线思路** |
| 统一 grounding+拒答训练 | GRACE 等 | RL / 门控奖励 | Day10 之后，规则有效再考虑 |

**忌讳说法：**「没人做过证据不足拒答」。  
**正确说法：**「已有范式；我们在 CRAG 嘈杂网页 + 本地错误分布上做**最小可跑验证**。」

---

## 3. 那我们的工作意义在哪？

### 3.1 意义一：把「文献共识」落到「可复现实验链」

文献告诉你「应该拒答」；并不自动给你：

- 同一裁判、同一数据、同一生成模型下的 **Vanilla / RAG / RAG+拒答** 对照；
- 针对 **你们机器上** 的 Llama-3.1-8B + DeepSeek 裁判 + Task1/2 网页 HTML 噪声。

**预实验的贡献是证据链，不是新名词。**

### 3.2 意义二：问题切片来自本地错误分析，不是泛泛「降幻觉」

Phase B Top-3：**生成错 / 过度检索 / 缺证据**。  
Step 4 优先打：

1. 证据不足 → 拒答（压生成错 + 缺证据）；  
2. 片段与答案一致性（压 `rag_worse`）。

这与「整库换更大模型」或「先上 RAGFlow」不是同一条路——**有明确失败模式驱动**。

### 3.3 意义三：方法刻意「小」，以便 Day12 能做去留决策

| 我们做 | 我们故意不做（现阶段） |
|--------|------------------------|
| 规则 / 提示级支持度阈值 | 端到端 RL（GRACE 级） |
| 200 子集快迭代 | 每改一版就烧 2706 |
| 与官方 RAG 基线同协议对照 | 宣称刷榜 SOTA |

待办 Day12 问的是：**可复现问题 / 四周出结果 / 清晰增量**。  
规则版若「几乎不动」→ 换备选或收束，这本身也是有意义的负结果。

### 3.4 意义四：与应用叙事可对齐（可选延伸，非当前必做）

若后续接到「可研 / 合规问答」等场景：内部条款库解决「有据可依」，外部动态事实仍会噪声——**同一套「证据不足则拒」比「永远硬答」更可辩护**。  
当前仓库主线仍是 **CRAG 预实验**，应用只作动机，不作本阶段交付物。

---

## 4. 我们不在解决什么（边界）

- 不重新发明 Self-RAG / Corrective RAG 全套架构。  
- 不把子集分数当成全量或论文可比 SOTA。  
- 不把「会拒 false_premise」当成「拒答问题已解决」。  
- 不在未经验证前改 CRAG 评分公式。

---

## 5. 一句话研究主张（可贴预实验报告）

> 在 CRAG 嘈杂网页检索设定下，官方风格 RAG 提升正确率的同时抬高幻觉；本地错误分析表明瓶颈是「证据不足仍生成」与「噪声片段误导」，而非假前提不会拒。我们采用已有范式中的轻量路径——**声明/支持度阈值驱动的选择性拒答**——在固定 200 典型子集上检验：相对同配置 RAG，能否在可接受的 missing 上升下显著降低 hallucination 并提高 score。若有效，再考虑全量复核与更重方法（置信度校准、SFT、检索纠错）；若无效，据此否决或改向，而不是无限堆工程。

## 6. 成功 / 失败判据（与意义挂钩）

| 结果 | 对我们工作的含义 |
|------|------------------|
| 子集上 hallucination↓ 且 score↑（missing 略升可接受） | **主线成立** → 写预实验报告、导师沟通、可选全量复核 |
| 四指标几乎不动 | **负结果有意义** → Day12 换备选 A（检索质量）或收束表述 |
| 幻觉↓但正确率大崩、score 不升 | **阈值过猛** → 调阈值 / 加「仅关键声明」再试一轮，勿直接放弃范式 |

## 9. 结论（给自己看）

学界方案多，说明**问题值钱、方向正确**，不是说明「我们不该做」。  
我们的价值在于：**本地实证问题 → 选一条轻量、可对照的方法 → 用同一协议量出有没有增量 → 据此立项或转向。**

没有这一步，related work 只是书单；有了这一步，才有资格说「这条线在我们的设定下值不值得继续」。
