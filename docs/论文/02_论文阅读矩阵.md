## 矩阵条目

### 1. 短名：RAG (Lewis 2020)  20260806

- **研究问题**：纯参数化 LM 难精确操控、溯源与更新世界知识；如何把预训练 seq2seq（参数记忆）与可检索 Wikipedia 索引（非参数记忆）联合成通用生成配方，在知识密集型任务上提升事实性与可更新性。
- **任务场景**：开放域 QA（NQ / TriviaQA / WebQuestions / CuratedTrec）、开放域抽象问答（MS-MARCO NLG）、Jeopardy 问题生成、事实核查分类（FEVER）。
- **方法核心**：DPR 稠密检索 + BART 生成器端到端微调；检索文档作潜变量做 top-K 边缘化。**RAG-Sequence** 整段共享同一组文档；**RAG-Token** 可按 token 换用不同文档。优化目标 = 检索潜变量下最大化生成似然（固定「先检索再读」）。
- **关键假设**：① 一次查询 + top-K passage 足以覆盖答题证据；② 最大化生成 NLL ≈ 事实正确；③ 文档编码器/索引可冻结，只训 query encoder + generator；④ 无需检索监督、无需显式「是否够证据 / 是否该拒答」决策。
- **数据集**：NQ、TriviaQA、WQ、CuratedTrec；MS-MARCO NLG v2.1；SearchQA Jeopardy 划分；FEVER。非参数记忆：Wikipedia 2018-12 dump，100-word 切块约 21M，FAISS MIPS。公开数据 + HF 开源代码。
- **评价指标**：开放域 QA 用 Exact Match；MS-MARCO 用 BLEU-1 / Rouge-L；Jeopardy 用 Q-BLEU-1 + 人工事实性/具体性成对比较；FEVER 用 label accuracy；多样性用 distinct n-gram 比。
- **对比基线**：闭卷 T5-11B / T5+SSM；开卷 REALM、DPR（检索+抽取）；纯参数 BART；FEVER 强流水线 SotA（含检索监督 / gold evidence）。代码：HuggingFace Transformers `examples/rag/`。
- **主要结果**：NQ EM 44.5（RAG-Seq）等四数据集开域 QA 达当时 SOTA，优于 DPR/REALM/T5；无 gold passage 时 MS-MARCO 仍超 BART（约 +2.6 B-1/R-L）；人工评估 RAG 更事实、更具体；FEVER-3 距强流水线约 4.3% 内且无检索监督；索引可热替换更新世界知识。
- **消融结果**：可学习检索 > 冻结检索；稠密检索在多数任务 > BM25（FEVER 实体型任务 BM25 更好）；测试时增大 K 对 RAG-Seq 单调增益，RAG-Token 约在 K=10 见顶；2016/2018 索引错配时领导人问答准确率骤降至 4–12%。
- **失败场景**：① 检索轮次/查询固定，中间推理无法触发再检索（多跳证据链易断）；② 无「证据不足 → 拒答 / 停止」机制，错误或无关文档仍强制读入；③ top-K 皆无答案时可靠参数记忆猜对（NQ 约 11.8%），但会掩盖证据缺口；④ Wikipedia 覆盖外 / 需 gold passage 的题（如实时天气）失败；⑤ 索引过期则答错；⑥ 不处理多源冲突与声明级引用。
- **资源要求**：BART-large（~400M）+ DPR bi-encoder；原文 8×32GB V100 混合精度（单卡可跑）；全维基索引约 100GB CPU RAM（压缩后约 36GB）；FAISS 检索可放 CPU。
- **可延伸问题**：传统 RAG 优化的是「单次 retrieve-then-read 的生成似然」，不是轨迹级策略——如何把充分性感知做成可学习决策（继续检索 / 停止回答 / 拒答），避免固定 K 下的检索不足与过度检索？
- **明确写的未来方向（Discussion）**
  1. 检索器与生成器能否**从头联合预训练**（类似 BART 的 denoising，或别的目标）
  2. 继续研究**参数记忆与非参数记忆如何交互、怎样更有效结合**，并推广到更多 NLP 任务
- **文中暗示、但未系统列为「不足」的点**
  - MS-MARCO：不少题没有 gold passage / 不在 Wikipedia 上就答不好
  - FEVER：比带检索监督的强流水线仍差约 4.3%
  - 消融：FEVER 上 BM25 有时优于稠密检索；冻结检索会掉点
  - Broader Impact：外部知识源本身可能有偏见或不完全事实；幻觉减少但未根除
  **没写、但你主候选里很关键的缺口**（论文当时不视为问题）
  固定「先检索再读」、无多轮再检索、无证据充分性 / 拒答 / 停止决策——这些是后人对 RAG 的延伸批评，不是 Lewis 原文的 Limitations 清单。

### 2. 短名：ReAct (Yao 2022 / ICLR 2023)  20260807

- **研究问题**：LLM 的推理（CoT）与行动（工具/环境交互）长期被分开研究——纯 CoT 易幻觉与误差传播且不接地；纯 Act 缺显式推理跟踪。如何用交错的 Thought–Action–Observation 把二者协同起来？
- **任务场景**：知识密集推理——多跳 QA（HotpotQA）、事实验证（FEVER）；交互决策——家居文本环境（ALFWorld）、网购（WebShop）。
- **方法核心**：少样本提示让 LLM 交错生成 **Thought**（分解目标、提取观察、改写查询、综合答案等）与 **Action**，环境返回 **Observation** 再驱动下一步。知识任务动作空间：`search[entity]` / `lookup[string]` / `finish[answer]`（弱 Wikipedia API，刻意逼模型用语言推理检索）。决策任务用稀疏 Thought 做子目标分解与状态跟踪。另可用启发式在 ReAct ↔ CoT-SC 间切换以融合内外知识。
- **关键假设**：① 少样本示范足以诱导「何时搜 / 搜什么 / 何时 finish」；② 错误观察可被后续 Thought 纠正；③ 弱 API + 显式推理 ≥ 强检索器的隐式检索；④ 轨迹可读即更可信（不保证证据充分性判定正确）。
- **数据集**：HotpotQA、FEVER；ALFWorld（134 unseen）；WebShop。公开基准；提示与 GPT-3 示例代码开源（主实验 PaLM 当时未公开）。
- **评价指标**：HotpotQA Exact Match；FEVER Accuracy；ALFWorld / WebShop success rate（及 WebShop score）；HotpotQA 人工标注成功/失败模式占比。
- **对比基线**：Standard、CoT、CoT-SC、Act-only；监督 SotA（HotpotQA/FEVER）；ALFWorld 的 BUTLER / Act；WebShop 的 IL、IL+RL；消融 ReAct-IM（类 Inner Monologue 稠密外部反馈 Thought）。
- **主要结果**：PaLM-540B 上 ReAct：HotpotQA EM 27.4（略低于 CoT 29.4）、FEVER Acc 60.9（高于 CoT 56.3）；最佳组合 ReAct→CoT-SC / CoT-SC→ReAct 达 35.1 / 64.6。ALFWorld 最佳 trial 成功率 71%（Act 45%、BUTLER 37%，相对 IL 系约 +34%）；WebShop SR 40.0 vs IL+RL 28.7（约 +10%），仍远低于人类 59.6。微调 3k 轨迹后小模型 ReAct 可超过更大模型纯提示。
- **消融结果**：ReAct > Act（推理引导行动）；ReAct ≫ ReAct-IM（稀疏内在推理优于仅复述外部反馈）；非信息检索占 ReAct 失败约 23%；CoT 幻觉失败约 56% vs ReAct 成功轨迹中假阳性 6%；结构约束使 ReAct 推理错误率高于 CoT（含重复 Thought/Action 死循环）；微调规模曲线上 ReAct 受益最大。
- **失败场景**：① 空搜/无用检索打偏后续轨迹且难恢复（无「证据不足→改策略/拒答」显式机制）；② 重复生成同一 Thought–Action 出不了环；③ 交错格式降低推理灵活性，结构对了但结论错；④ 弱 Wikipedia API 检索能力远弱于现代 retriever；⑤ 提示范式难学复杂动作空间，上下文长度限制示范数；⑥ WebShop 探索与查询改写仍远弱于人类；⑦ 无多源冲突仲裁与过程级奖励。
- **资源要求**：主结果 PaLM-540B 提示（及 8B/62B 微调对比）；附录有 GPT-3；知识任务需 Wikipedia API；决策任务需 ALFWorld/WebShop 环境。少样本即可跑通，全量复现依赖大模型 API。
- **可延伸问题**：ReAct 给出了动态检索的交互外壳，但「何时该搜 / 是否够证据 / 是否该 finish 或拒答」仍靠提示启发式——如何把充分性感知与停止/拒答做成可学习策略（监督或 RL），并降低对空搜与死循环的脆弱性？
- **原文局限与未来方向**：作者承认 prompting 下推理/行动行为支持有限；复杂大动作空间需更多示范却易超出上下文；微调有希望但仍需高质量人工标注。未来：扩大多任务训练，并与强化学习等范式结合。

### 3. 短名：IRCoT (Trivedi 2023 / ACL)  20260807

- **研究问题**：多跳开放域 QA 上，仅用问题做一次 retrieve-and-read 不够——「下一步该检什么」取决于已推出的中间结论，而中间结论又依赖先前检索。如何让检索与 CoT 句子级推理互相引导？
- **任务场景**：多跳开放域 QA：HotpotQA、2WikiMultihopQA、MuSiQue、IIRC（均开域设置）。
- **方法核心**：**IRCoT**（Interleaved Retrieval guided by CoT）。先用问题检索 K 段；然后交替 (i) **Reason**：用「问题 + 已累积段落 + 已有 CoT」生成下一句 CoT；(ii) **Retrieve**：用**上一句 CoT** 作查询再取 K 段并累积。终止条件：CoT 出现 `answer is` 或达到最大步数。最终用累积段落做 Direct / CoT reader 答题（检索过程中的 CoT 抽答案通常更差，故默认另设 reader）。底层检索器为 BM25 类；LLM 为 GPT-3（code-davinci-002）或 Flan-T5-*，少样本人工 CoT 示范，**无需训练**。
- **关键假设**：① 每句 CoT 是足够好的下一跳查询；② 错误中间句可通过后续检索纠正，或至少不严重级联；③ 固定每步都检索 + 最大步数启发式 ≈ 证据充分；④ 基座模型具备 zero/few-shot CoT，且上下文能装下累积段落。
- **数据集**：HotpotQA、2WikiMultihopQA、MuSiQue、IIRC；配套 Wikipedia/语料段落；代码与提示开源（`stonybrooknlp/ircot`）。
- **评价指标**：检索用固定预算下的 **optimal recall**（文档无序、每步 K、总段落有上限，故不用标准 MAP/Recall@k）；QA 用 Answer **F1**；另人工统计 CoT 是否含事实错误（每数据集 40 题）。
- **对比基线**：NoR（无检索，纯参数知识）、OneR（单次问题检索）；reader 消融（有/无单独 reader）；与 SelfAsk / DecomP / ReAct 报告分数对照（作者称非严格 apples-to-apples）。
- **主要结果**：相对 OneR，检索 recall：GPT-3 上 HQ/2Wiki/MuSiQue/IIRC 分别约 **+11.3 / +22.6 / +12.5 / +21.2**；QA F1：Flan-T5-XXL 约 **+9.4 / +15.3 / +5.0 / +2.5**，GPT-3 上前三集约 **+7.1 / +13.2 / +7.1**（IIRC QA 几乎不涨，因参数知识已够）。相对 OneR，HotpotQA 上 CoT 事实错误约 **-50%**。OOD（跨数据集示范）同趋势；Flan-T5-XL（3B）+IRCoT 可超过 GPT-3+OneR。
- **消融结果**：单独 reader 通常优于直接从检索期 CoT 抽答案（Flan 上差距更大）；规模曲线上小模型也受益；IID/OOD 一致显示 IRCoT > OneR > NoR。
- **失败场景**：① 中间 CoT 句错 → 查询偏移 → 错误级联（无逐步证据批判）；② 每步强制检索，缺「已够证据则停止 / 拒答」；③ 依赖基座 CoT 能力与长上下文，小模型/短窗口难用；④ 每句一次 LLM 调用，成本高；⑤ GPT-3 IIRC：检索涨但 QA 不涨（充分性未被正确利用）；⑥ 无多源冲突仲裁；⑦ code-davinci-002 已弃用，GPT 侧难复现。
- **资源要求**：GPT-3 API（已弃用）或公开 Flan-T5（0.7B–11B）；BM25/Elasticsearch 语料检索；少样本提示即可，无额外训练；需较长上下文装多段 Wikipedia。
- **可延伸问题**：作者已点出未来可「**动态决定何时再检索、何时用现有信息继续推理**」——正好接到主候选：如何把充分性感知做成可验证决策（继续检索 / 停止回答 / 拒答），并缓解错误 CoT 句引发的路径偏移？
- **原文局限与未来方向**（Limitations）：依赖 CoT 能力与长输入；每步调用成本高；建议未来做段落重排筛选，以及动态检索时机；商业 API 复现困难，以 Flan-T5 实验为主可复现。

### 4. 短名：Self-RAG (Asai 2024 / ICLR)  20260807

- **研究问题**：固定检索会损害通用能力或引入无关段落；且生成未必与证据一致。如何训练**单一 LM**，用可学习反思标记自适应决定是否检索、证据是否相关、生成是否被支持及回答是否有用？
- **任务场景**：短答开放域 QA（PopQA 长尾、TriviaQA-unfiltered）；闭集推理/核查（PubHealth、ARC-Challenge）；长文带引用（Biography FactScore、ALCE-ASQA）。
- **方法核心**：**Self-RAG**——端到端训练生成器，把 **reflection tokens** 并入词表作下一词预测。标记类型（Table 1）：**Retrieve** ∈ {Yes, No, Continue}（Continue=继续用已取证据，非新查询再搜）；**ISREL**（relevant/irrelevant）；**ISSUP**（fully / partially / no support·contradictory）；**ISUSE**（1–5）。训练：批评器（Llama2-7B，部分标签来自 GPT-4）离线插入反思标记 + 检索段落；推理：按需检索 → 对 top-K 并行生成段落 → 用批判分数加权选段（可调权重/阈值阈值阈值）。检索器默认 Contriever-MS MARCO。
- **关键假设**：① 批评器/GPT-4 标签近似真值；② 句级片段 + 单文档相关/支持足以代理「证据充分」；③ Retrieve=No/Yes/Continue 覆盖主要检索策略，无需显式拒答；④ 推理期加权可权衡事实性与流畅性。
- **数据集**：训练约 150k 指令对（Open-Instruct + KILT 等知识密集数据）；评测 PopQA、TriviaQA、PubHealth、ARC-C、Biography、ASQA。代码与模型：selfrag.github.io。
- **评价指标**：短答 accuracy（答案是否被包含）；Pub/ARC accuracy；Biography **FactScore**；ASQA 的 str-EM、Rouge、MAUVE、citation precision/recall。
- **对比基线**：无检索 Llama2/Alpaca/ChatGPT/Llama2-chat/CoVE；有检索标准 RAG、Ret-ChatGPT/Llama2-chat、SAIL、Toolformer、Llama2-FT+测时检索等。
- **主要结果**（Table 2）：Self-RAG-7B / 13B——PopQA **54.9 / 55.8**，TriviaQA **66.4 / 69.3**，PubHealth **72.4 / 74.5**，ARC **67.3 / 73.1**，Bio FS **81.2 / 80.2**，ASQA citation prec **66.9 / 70.3**、rec **67.8 / 71.3**。多项超 ChatGPT / Ret-Llama2-chat；长文事实性与引用显著提升；引用 precision 可超 ChatGPT。
- **消融结果**（50k 子集）：No Retriever / No Critic 明显掉点；推理关闭检索或 Hard-only Yes 掉点；Retrieve top1（常规 RAG）在 PopQA/ASQA 大降；去掉 ISSUP 损害 ASQA；调高 ISSUP 权重提升 citation precision；检索阈值阈值可在 PubHealth/PopQA 上折中准确率与检索频率。
- **失败场景**：① **Continue ≠ 新一轮查询**，多跳「下一步搜什么」能力弱于 IRCoT/ReAct；② 无显式「证据不足 → 拒答」；③ ISSUP 偏单文档–单片段，多源冲突仲裁有限（虽有 Contradictory 标签）；④ 批评信号质量依赖教师模型，可错标；⑤ 低阈值下过度检索，高阈值下漏检；⑥ Ethical 自承：仍可能生成引用未充分支持的内容。
- **资源要求**：基座 Llama2-7B/13B + critic 7B；Contriever；约 150k 训练数据；GPT-4 用于部分批评标签；推理可用 vLLM，段级 beam=2。公开权重可复现。
- **可延伸问题**：Self-RAG 把「是否检索 + 是否支持」做成可训练标记，是主候选的强跳板——如何扩展到**轨迹级**充分性（继续检索新查询 / 停止回答 / 拒答）、声明级支持与冲突类型，并与过程奖励/成本约束打通？
- **原文局限与未来方向**：无独立 Limitations；Conclusion 强调按需检索与自反思；Ethical 承认仍可能出现引用未充分支持；附录提到部分检索增强设定「leave for future work」。

### 5. 短名：Adaptive-RAG (Jeong 2024)  20260809

- **研究问题**：用户查询复杂度不一——简单题套多步检索浪费算力，复杂题用单步不够；现有方法常非「极简」即「极繁」。如何按**问题复杂度**在「不检索 / 单步检索 / 多步迭代检索」间动态选策略，兼顾准确率与时延？
- **任务场景**：统一实验下的开放域 QA：单跳（SQuAD v1.1、Natural Questions、TriviaQA）+ 多跳（MuSiQue、HotpotQA、2WikiMultiHopQA）。
- **方法核心**：**Adaptive-RAG**——先用轻量 **T5-Large 复杂度分类器**把查询标为 A/B/C，再路由到对应策略：A=LLM(q)（无检索）；B=单步 LLM(q,d)；C=多步迭代（实现上用 **IRCoT**）。分类器标签自动构造：① 以三策略实际能否答对为准（平局优先更简单策略）；② 全失败时回退数据集归纳偏置（单跳→B，多跳→C）。主 LLM 可换 FLAN-T5-XL/XXL 或 GPT-3.5；检索器用现成 off-the-shelf。
- **关键假设**：① **检索前静态复杂度**≈最优策略；② 复杂度三档可覆盖真实需求；③ 自动标签（模型结果+数据偏置）足够训分类器；④ 选对策略后，策略内部无需再在线改写（无过程中回退）。
- **数据集**：上述 6 个公开 QA；分类器训练标签自造。代码：github.com/starsuzi/Adaptive-RAG。
- **评价指标**：EM / F1 / Acc；效率用平均检索/推理 **Step** 与 **Time/Query**；另报分类准确率与混淆矩阵。
- **对比基线**：No Retrieval、Single-step、Multi-step（IRCoT）；自适应基线 Adaptive Retrieval（仅决定是否检索）、Self-RAG（∗基座不同，对比需谨慎）；上界 Adaptive-RAG w/ Oracle 分类器。
- **主要结果**（Table 1，全数据平均）：相对「一律多步」，准确接近且显著更快——如 GPT-3.5：Adaptive-RAG F1 **50.91** / Time **1.46** vs Multi-step F1 50.87 / Time 3.33；FLAN-T5-XL：F1 **46.94** / Time **3.60** vs Multi 48.85 / 8.81。相对仅「是否检索」的 Adaptive Retrieval / Self-RAG，在混合复杂度上更优。Oracle 分类器 F1 可到 **56–63**，显示分类器仍是瓶颈。
- **消融/分析**：混淆矩阵——C→B 约 **31%**、B→C 约 **23%**、A→B 约 **47%**（简单题常被高估需检索）；标签分布约 A 8.6% / B 53% / C 38%；分类准确率高于其他自适应检索基线。作者称改进分类器是直接增益点。
- **失败场景**：① **静态判定**：检索中新证据无法改策略（与主候选「轨迹中决策」对立）；② 复杂度 ≠ 证据充分性/检索必要性；③ 自动标签可错，三策略皆错时靠数据集偏置；④ 无拒答、无检索失败纠正回退（对比 CRAG）；⑤ 未显式建模成本/风险/边际信息增益；⑥ 错分 C→B 会欠检索，B→C 会过度检索。
- **资源要求**：分类器 T5-Large（轻量微调）；主 LLM 为 FLAN-T5 或 GPT-3.5 API；多步路径成本≈IRCoT。代码开源，可复现。
- **可延伸问题**：静态复杂度路由证明了「策略选择」有价值——如何升级为**在线自适应**：根据中间置信、证据增益与冲突状态在「继续检索 / 停止回答 / 拒答」间切换，而非一次性分类？
- **原文局限与未来方向**（Limitations）：自动标注可能错标；需更细粒度人工复杂度数据；分类器架构偏简单，与 Oracle 差距大；Ethics 提到有害输入/检索内容检测留待未来。另文中称更细粒度复杂度分档亦为 future work。

### 6. 短名：Search-R1 (Jin 2025 / COLM)  20260810

- **研究问题**：仅靠提示让 LLM 在推理中调用搜索往往次优；有监督工具调用又依赖大规模标注轨迹且搜索不可微。如何用 **RL** 让 LLM 在逐步推理中**自主发起多轮搜索**，并稳定优化交错搜索–推理轨迹？
- **任务场景**：通用 QA（NQ、TriviaQA、PopQA）+ 多跳 QA（HotpotQA、2WikiMultiHopQA、MuSiQue、Bamboogle）；训练合并 NQ+HotpotQA，其余评测含 OOD。
- **方法核心**：**Search-R1**——把搜索引擎当 RL 环境；rollout 交错生成：``<think>`` 推理、``<search>`` 查询、环境返回 ``<information>``、最终 ``<answer>``。用 **retrieved-token masking**（只对模型生成 token 算策略梯度，检索文本不反传）稳定 PPO/GRPO。奖励为简单 **outcome EM**（答案对错），**不加 format reward、不训神经奖励模型**。默认 PPO；亦支持 GRPO。
- **关键假设**：① 稀疏 outcome 奖励足以激发有意义的搜索行为；② 掩码检索 token 即可稳定训练；③ 无需过程监督/SFT 冷启动；④ 最终 EM≈轨迹质量（中间路径、检索必要性、冲突处理可不显式建模）。
- **数据集**：上述 7 个公开 QA；知识库 Wikipedia 2018 dump；检索器 E5，固定 top-3。代码与 checkpoint：github.com/PeterGriffinJin/Search-R1。
- **评价指标**：Exact Match（主指标）；另分析训练奖励、响应长度、有效搜索次数、PPO vs GRPO 稳定性。
- **对比基线**：Direct、CoT、IRCoT、Search-o1、RAG、SFT、无搜索的 R1（同设定 RL）、Rejection Sampling；同检索器/语料/训练数据/基座以保证公平。
- **主要结果**（Table 2，Avg EM）：Qwen2.5-7B **Search-R1-base 0.431** vs RAG **0.304**（相对约 **+41%**），亦显著超 R1 / Rejection Sampling / IRCoT；3B 上约 **+20%** 相对 RAG（instruct Avg≈0.325–0.336 vs RAG 0.270）。IID（NQ/Hotpot）与 OOD 均涨；7B 学搜索的增益大于 3B。
- **消融/分析**：PPO 更稳、GRPO 收敛更快但后期易 reward collapse；Base 与 Instruct 终局接近、Instruct 收敛更快；训练中有效搜索次数上升、响应先缩短后因插入检索变长；**去掉 retrieved-token masking 明显变差**。
- **失败场景**：① **奖励稀疏**：部分正确/路径对答案错 → 零信号（后续 Search-P1 所批）；② 无显式成本/停止/拒答约束，可能过度搜索；③ 不优化冲突仲裁与引用忠实度；④ MuSiQue 等难多跳仍偏低（7B base 0.196）；⑤ GRPO 长训不稳；⑥ 无过程级「证据是否够」批判。
- **资源要求**：Qwen2.5-3B/7B + E5 + Wiki 索引；PPO 需 critic；多轮 rollout 算力明显高于单次 RAG。开源可复现，但仍属中等规模 RL。
- **可延伸问题**：Search-R1 是主候选的 **RL 交互基线**——如何在 outcome 之上加入证据正确性、检索必要性、冲突处理、停止与成本的统一过程奖励，并实现作者所提的「**基于不确定性的动态检索调整**」与拒答？
- **原文局限与未来方向**（Conclusions）：无独立 Limitations；未来明确提到更复杂奖励、**按不确定性动态调整检索**、更多工具与信息源、多模态。文中亦称 format/更复杂奖励留待 future work。

### 7. 短名：Search-P1 (Xia 2026)  20260811

- **研究问题**：Agentic RAG 的 outcome RL（如 Search-R1）有三痛——奖励稀疏忽略中间路径、部分正确轨迹零分、二值奖励收敛慢。如何用**路径中心奖励整形**从失败轨迹提取信号、稳定高效地训搜索–推理策略？
- **任务场景**：与 Search-R1 同套公开 QA（NQ、TriviaQA、PopQA、HotpotQA、2Wiki、MuSiQue、Bamboogle）+ 工业广告多跳 **AD-QA**（内部匿名，1k 测试）；训练合并 NQ+HotpotQA。
- **方法核心**：**Search-P1**——轨迹显式加入 **planner** `p`；总奖励 `R = λp·Rpath + λa·Routcome + λf·Rformat`（默认 λ≈0.3/0.6/0.1）。**Dual-Track Path Scoring**：Track A 自洽（执行自声明计划）；Track B 参考对齐（离线 rejection sampling + LLM 投票得到 `Pref`，**无序**步覆盖）；`Rpath = max(Sself, Sref)`。**Soft Outcome**：答错时给部分信用 `α·racc+(1-α)·rreason`（α=0.8）。训练用 **GRPO**；检索同设定 Wikipedia + E5 top-3。
- **关键假设**：① 参考路径近似「好路径」分布；② 无序步覆盖≈路径质量；③ soft outcome + 路径分可缓解稀疏；④ `max(Sself,Sref)` 足以避免参考路径完全压制新颖策略；⑤ 格式/路径/结果三分量可权衡。
- **数据集**：上述 7 公开集 + AD-QA（不公开）；参考 planner 由专有 HY 2.0-Instruct 离线生成并缓存。
- **评价指标**：Accuracy（答案是否被包含）；另看训练步 ACC/Reward 曲线、软格式 vs 严格格式、过程奖励权重敏感性。
- **对比基线**：Direct、CoT、RAG、IRCoT、Search-o1、**Search-R1**、**HiPRAG**（同检索设定复现）。
- **主要结果**（Table 1，ACC%）：Qwen2.5-7B Avg **47.3** vs Search-R1 **39.6**（约 **+7.7**）、HiPRAG 42.9；AD-QA **86.2** vs Search-R1 65.6（**+20.6**）。3B Avg **41.5** vs Search-R1 33.6（约 **+7.9**）。多跳与工业集增益更大。
- **消融结果**（Table 2，7B）：去 Reference-Alignment → 42.0（-5.3）；去 Self-Consistency → 44.2（-3.1）；双轨最好。Soft format 收敛快于严格/无格式；soft outcome 对单跳约 +1.2、多跳约 +3.5、AD-QA 约 +8.8。
- **失败场景**：① 策略可能被**锚定在参考路径分布**，抑制非常规但正确的检索；② 参考 planner 构造成本与教师偏差进入奖励；③ 仍不原生覆盖冲突仲裁、声明级引用、拒答；④ 步覆盖依赖 LLM 语义匹配，可奖励黑客；⑤ AD-QA 不可复现，公开集增益需与 HiPRAG 对照解读；⑥ 未显式优化「证据充分则停止」。
- **资源要求**：Qwen2.5-3B/7B；8×H20；GRPO batch 512；每 prompt 采样 16/32；需离线教师生成参考路径。算力高于 Search-R1（额外路径打分）。
- **可延伸问题**：路径奖励缓解了稀疏，但主候选还需把**检索必要性 / 停止 / 拒答 / 冲突处理 / 成本**写入同一可学习奖励，并避免参考路径僵化——如何设计不被 Pref 绑架的充分性感知过程信号？
- **原文局限与未来方向**：无独立 Limitations；Conclusion 强调路径级监督与工业迁移。解析侧可延伸：参考路径偏差、可信维度缺失。

### 8. 短名：RAG-Conflict / MADAM-RAG (Wang 2025 / COLM)  20260811

- **研究问题**：真实 RAG 常同时面对查询歧义、误导信息与噪声；既往工作往往**孤立**处理其一，忽略同一查询下多源冲突的交互与相互矛盾的期望行为。如何同时定义正确行为并有效仲裁？
- **任务场景**：冲突证据下的开放域问答——**AmbigDocs**（歧义→应并列多解）、**FaithEval** inconsistent（误导→应抑制）、自建 **RAMDocs**（歧义+误导+噪声同查询混合，并控制证据失衡）。
- **方法核心**：(1) **RAMDocs**：在 AmbigDocs 上叠加误导/噪声文档；每查询约 2.20 个有效答案、3.84 篇支持文档；规定不同期望输出（歧义并列多解，误导/噪声只保留正确）。(2) **MADAM-RAG**：每文档一 Agent（同 LLM）基于单文档作答 → 多轮辩论修订 → **Aggregator** 综合；歧义时保留多实体正确答，误导/噪声则丢弃。有早停（连续轮不变则停）。
- **关键假设**：① 冲突类型可分且期望行为可枚举；② 「一文一 Agent + 辩论 + 聚合」优于拼接上下文；③ 多数/表述顺序偏置可被辩论缓解；④ EM/Acc（全对且无错）足以刻画冲突处理质量。
- **数据集**：FaithEval inconsistent、AmbigDocs、RAMDocs（公开：github.com/HanNight/RAMDocs）。
- **评价指标**：严格 Acc（须覆盖全部正确且不含错误）；另报 Precision / Recall / F1；分析证据失衡与误导比例敏感性；附录比 token 成本。
- **对比基线**：No RAG、Concatenated-prompt、Single-Agent + Self-reflection、Speculative RAG、Astute RAG、Self-RAG（Llama2-13B）；骨干含 Llama3.3-70B-Inst、Qwen2.5-72B-Inst、GPT-4o-mini。
- **主要结果**（Table 1）：Llama3.3-70B 上 MADAM-RAG——FaithEval **43.10**（vs Concat 27.30，约 **+15.8**）、AmbigDocs **58.20**（vs Astute 46.80，约 **+11.4**）、RAMDocs **34.40**（vs Concat **32.60**，增益有限）。Qwen72B：57.70 / 52.70 / **26.40**；GPT-4o-mini RAMDocs 峰值仅 **28.00**。联合冲突远未解决。
- **消融结果**：有 Aggregator ≫ 无；辩论轮数 1→3 有增益（FaithEval 无聚合时多轮可 +21 Acc 量级）；证据失衡与误导增多时全方法掉点，MADAM-RAG 掉得相对少但仍大幅下降；多数例 1–2 轮早停。
- **失败场景**：① RAMDocs 上即便 70B+MADAM Acc 仍约 **32–34**，联合冲突未解；② 证据/误导**失衡**时性能急剧恶化；③ 多 Agent 辩论成本高（约 3k+ in / 1.5k out tokens）；④ 聚合仍可能受投票与表述顺序影响；⑤ EM 不足以刻画「是否承认冲突 / 是否错误合并多解」；⑥ 与主候选的「充分则停 / 拒答」未打通——冲突时缺「请求澄清」动作。
- **资源要求**：每文档一 Agent × 多轮 + Aggregator；需 70B 级才有明显收益；早停可降本但仍远贵于单次 RAG。代码数据公开。
- **可延伸问题**：冲突类型应作为主候选的一等状态——对歧义/误导/噪声/内外知冲突学习不同动作（并列多解 / 抑制 / 澄清 / 拒答），并用冲突承认率、误导抑制率、多解覆盖率替代纯 EM？
- **原文局限与未来方向**：无独立 Limitations；Conclusion 明确 RAMDocs 仍是挑战、未来需继续提升；文中反复强调失衡场景 gap 大。

### 9. 短名：DRAGIN (Su 2024)  20260811

- **研究问题**：动态 RAG 的两个关键——**何时检索**、**检索什么**——现有方法多依赖静态规则（每 n token / 每句），或仅用最近句/低置信 token 作查询，无法覆盖跨全文的信息需求。如何按 LLM **实时信息需求**做决策？
- **任务场景**：知识密集型生成/问答：2WikiMultihopQA、HotpotQA、StrategyQA、IIRC。
- **方法核心**：**DRAGIN** = **RIND** + **QFS**，免训练、免提示工程，可挂任意 Transformer LLM。(1) **RIND**（何时）：对已生成 token 算 `S = H · a_max · s`——熵不确定性 × 后续 token 最大注意力 × 非停用词；任一 token 超阈值 θ 则触发检索。(2) **QFS**（搜什么）：用全文 self-attention 选对当前需求重要的 token 拼查询，而非只用最近句/窗口。检索后继续生成。
- **关键假设**：① 熵+注意力+语义 ≈ 真实信息缺口（≠措辞不确定）；② 注意力可及的开源模型；③ BM25 + Wiki 段落足够；④ 阈值 θ 可跨任务调好。
- **数据集**：上述 4 公开集；语料 Wikipedia（100-token 切块）；代码开源：github.com/oneal2000/DRAGIN。
- **评价指标**：EM / F1（多跳与 IIRC）；StrategyQA 用 Accuracy；另统计检索触发频率。
- **对比基线**：wo-RAG、SR-RAG（单次）、FL-RAG（定长）、FS-RAG（定句≈IRCoT 风格）、**FLARE**（低概率触发）；检索器默认 BM25，另试 SGPT。
- **主要结果**（Table 2，Llama2-13B-chat）：DRAGIN 在 2Wiki **EM 0.304** / Hotpot **0.314** / StrategyQA **0.689** / IIRC **0.185**，多数设定最优；相对 FLARE、FS-RAG 明显更好。7B/Vicuna-13B 趋势类似。固定间隔检索常不优于单次 RAG——印证「错时机检索无益」。BM25 在其设定下常优于 SGPT。
- **消融结果**：RIND、QFS 各自替换为既有 when/what 策略均下降；FLARE 的「搜什么」尚可但「何时」不足；错误位置触发检索可能引入噪声。
- **失败场景**：① **低置信 ≠ 真缺知识**（与 FLARE 同类风险，虽加了注意力/语义仍是代理信号）；② 依赖 **attention 分数**，闭源 API 不可用（作者 Limitations）；③ 无拒答；④ 不处理冲突证据；⑤ 阈值敏感；⑥ a_max 依赖后续 token，实现上与严格在线决策有张力。
- **资源要求**：开源 LLM（需 attention）；BM25+Wiki；推理期多轮检索，无额外训练。轻量相对 RL 系。
- **可延伸问题**：相对 Adaptive-RAG（问前静态分类）与 Self-RAG（可训练标记），DRAGIN 用生成中信号做 when/what——如何把 RIND 式需求升级为可验证的**充分性/风险/拒答**决策，并摆脱对 attention API 的依赖？
- **原文局限与未来方向**：依赖 self-attention，不适用于不返回 attention 的 API；未来要发展不依赖 attention 的替代方法。

### 10. 短名：FLARE (Jiang et al., EMNLP 2023)  20260811

- **研究问题**：长文知识密集型生成中，单次 retrieve-and-generate 不够；被动多轮检索（固定窗口/前一句）常在错误时机检索、查询也不对齐**未来**要写的内容。能否在生成全程**主动决定何时检索、检索什么**？
- **任务场景**：长输出知识任务：2WikiMultihopQA、StrategyQA、ASQA（及 ASQA-hint）、WikiAsp；主实验模型 text-davinci-003。
- **方法核心**：**FLARE**（Forward-Looking Active REtrieval）。框架：生成中主动 when/what。(1) **FLAREdirect**（主方法）：先无检索生成临时下一句 `ŝ_t`；若任一 token 概率低于 θ 则触发检索；用 `ŝ_t` 作查询（整句 / 低置信 mask / 对低置信 span 问句生成）取文档后**重生成**该句。(2) **FLAREinstruct**：用检索指令让模型边写边发搜索查询（黑盒上不如 direct）。假设：低概率 ≈ 缺知识；前瞻下一句比回看过去更能对准未来意图。
- **关键假设**：① LM 校准良好，低置信 ≈ 真缺知识（≠措辞犹豫）；② 句级迭代粒度合适；③ 错误句作查询可用 mask/问句缓解；④ 阈值 θ、β 可在开发集调好；⑤ 文档前置拼接即可。
- **数据集**：上述 4 任务（每集最多 subsample 500）；Wiki 用 BM25 + Karpukhin dump；开网用 Bing；代码：github.com/jzbjyb/FLARE。
- **评价指标**：2Wiki/StrategyQA：EM（及 F1 等）；ASQA：EM、Disambig-F1、ROUGE-L、DR；WikiAsp：UniEval、实体 F1、ROUGE-L。
- **对比基线**：无检索、单次检索；多轮：previous-window（l=16）、previous-sentence（≈IRCoT 风格）、question decomposition（self-ask 式人工 exemplar）。
- **主要结果**：Figure 4 全任务优于或持平基线；2Wiki（Table 1）FLAREdirect **EM 51.0** vs 单次 39.4 / 问句分解 47.8 / FLAREinstruct 42.4；StrategyQA **EM 77.3**（单次 68.6、无检索 72.9——单次检索可伤任务）；ASQA/WikiAsp 亦全面领先。多跳增益最大，开放长文增益更小。
- **消融结果**：下一句作查询明显优于上一句（Table 3）；θ 调节检索占比——2Wiki 约超过 60% 后平台，StrategyQA **过度检索掉点**（噪声）；mask/问句查询可缓解错误句传播；过去窗口过长（>32 token）伤性能。
- **失败场景**：① **低置信 ≠ 缺知识**；② 临时错误句污染检索（虽有 mask/问句）；③ **无拒答/停止/冲突仲裁**——只会继续生成；④ 短对话（WoW）几乎无增益；⑤ ELI5 因 grounding/评测难，单次与 FLARE 均几乎无增益；⑥ 交错生成+检索开销大、无 cache 需重算。
- **资源要求**：推理期免训练；需 token 概率（API logprobs）；多轮 LM 调用 + 检索；黑盒 GPT-3.5 级成本高。
- **可延伸问题**：与 DRAGIN 同属「生成中 when/what」，但信号是**概率**而非熵×注意力——如何把「低置信触发重写」升级为可验证的**证据充分性**（继续 / 停止 / 拒答），并显式惩罚过度检索引入的噪声？
- **原文局限与未来方向**：WoW/ELI5 增益有限；工程上交错代价高；未来要更好的主动检索策略与高效「检索–生成」架构。

### 11. 短名：RAFT (Zhang et al., 2024)  20260811

- **研究问题**：领域固定、可提前接触文档时，如何把预训练 LLM **适配成领域 RAG**？纯 RAG≈开卷不复习；纯 SFT≈闭卷背书或练习时不看材料——二者都未针对「测试时 top-k 检索不完美」做准备。
- **任务场景**：领域特定 open-book QA：PubMedQA、HotpotQA、Gorilla APIBench（HF/Torch/TF Hub）；另用 NQ/TriviaQA 做 P% 与 distractor 敏感度分析。测试域与训练文档同域。
- **方法核心**：**Retrieval Augmented Fine-Tuning**——改的是微调数据配方，非检索器。(1) 每条样本：Q + 文档集 + **带原文引用的 CoT 答案 A**（`##begin_quote##`…）。(2) **golden D** + **distractor Dk**：教模型忽略无关文档、 verbatim 引用有用片段。(3) **P%** 样本保留 golden；**(1−P)%** 仅 distractor（逼模型背答案，兼备记忆与读文档）。(4) 测试：标准 top-k RAG，与检索器解耦。基座实验：LLaMA2-7B。
- **关键假设**：① 训练期模拟不完美检索 → 测试 top-k 更稳；② 无关文档可「忽略」即可（未处理多源冲突/矛盾）；③ 无 golden 时应靠参数记忆作答（**非拒答**）；④ 同域 train/test；⑤ GPT-4 生成的 CoT+引用监督可靠。
- **数据集**：PubMedQA、HotpotQA、APIBench 三 hub；分析用 NQ/TQA/Hotpot；代码 gorilla 仓库。
- **评价指标**：各域任务准确率/匹配（Table 1 主表）；API 可执行性相关指标（Gorilla 设定）。
- **对比基线**：LLaMA2-7B 0-shot；LLaMA2+RAG；**DSF**（领域 SFT 无文档）；**DSF+RAG**；参考 GPT-3.5+RAG。
- **主要结果**（Table 1，RAFT-7B）：PubMed **73.3**（DSF+RAG 71.6）；Hotpot **35.28**（DSF+RAG 仅 4.41，基座+RAG≈0）；HF **74.0** / Torch **84.95** / TF **86.86**，全面超 DSF±RAG；Hotpot 相对 DSF+RAG 约 +30pt。DSF 加 RAG **不一定更好**（Hotpot、HF 上 DSF+RAG 反而掉）——缺「读上下文」训练。
- **消融结果**：无 CoT 明显掉点（Hotpot 35.28→25.62，HF 74→59）；P% 最优因域而异（约 40/60/100），**混入无 golden 样本有益**；训练仅 golden 弱于 golden+多 distractor；训练含 distractor 后对测试 top-k 数量变化更鲁棒（Fig.6）。
- **失败场景**：① **与主候选正交**：不学「何时检索/停止/拒答」，只学「给定 top-k 时如何读」；② **(1−P) 无证据仍输出 A**——强化背诵而非证据不足拒答；③ 忽略 distractor ≠ 仲裁冲突证据；④ 跨域/跨文档集泛化非目标（作者 Related Works 自述）；⑤ P、k 敏感；⑥ 依赖高质量 CoT 标注成本（GPT-4）。
- **资源要求**：需领域 QA + 可构造 golden/distractor；SFT 7B 级；测试仍要检索器；与 FLARE/DRAGIN 免训练推理不同，属 post-training。
- **可延伸问题**：RAFT 教「抗噪声阅读」；主候选要的是轨迹级 **充分性决策**。若把「仅 distractor」监督从「背答案」改为「拒答/澄清」，并与 when-to-retrieve 联训，能否同时覆盖噪声鲁棒与证据不足？
- **原文局限与未来方向**：无独立 Limitations；Conclusion 强调 distractor、部分无 golden、CoT+引用三设计；Related Works 明确只关心同文档集 in-domain，不同于跨域 RAG 微调线。

### 12. 短名：InFO-RAG / Info-RAG (Xu et al., 2024)  20260813

- **研究问题**：即便检索变强，LLM 仍常忽略、误用或被噪声检索误导——预训练目标把检索文本当普通前缀做整段 NLL，并未显式学「如何利用不同质量的检索文本」。如何在**无监督、跨任务可泛化**前提下，把 LLM 训成 RAG 中的「信息精炼器」？
- **任务场景**：零样本 RAG：Slot-Filling（T-REx、zsRE）、ODQA（NQ、WebQ）、多跳 QA（HotpotQA、MuSiQue）、LFQA（ELI5）、对话（WoW）、LM（WikiText）、代码生成（CodeXGLUE Python/Java）；另测 ICL、开检索 SearChain 增强、三场景鲁棒性。
- **方法核心**：**InFO-RAG**——把 LLM 角色重定义为 **Information Refiner**（无论检索对错/完整与否，都应融合参数知识与检索文本，产出更简洁、准确、完整的文本 = Positive Information Gain）。在 Wikipedia 上无监督构造三类前缀 LM 任务并用 **LoRA** 混训（S1 20% / S2&S3 各 40%）：**(S1) Select and Copy**——检索含目标句，学从复杂上下文抽取并复制；**(S2) Correct and Complete**——对信息量大 token（层间 JSD 不稳定度，仿 DoLa）做 30% mask/替换，学纠错与补全；**(S3) Contextual Stimulation**——去掉目标句，仅留语义相关句，学靠参数知识作答。推理时加载 LoRA 做标准 RAG（top-5 等），非 RAG 可卸载。
- **关键假设**：① 「精炼」≈ 相对检索文本的正信息增益，可用无监督续写目标学到；② Wiki 句级三类仿真可迁移到 QA/对话/代码等任务；③ 层间不稳定 token ≈ 信息点，随机 mask/替换 ≈ 真实噪声/残缺；④ **无拒答**：无答案场景仍被鼓励用参数知识猜答；⑤ LoRA 即可改「读检索」能力且不严重遗忘。
- **数据集**：训练：英文 Wikipedia 无标注续写（每例截 15 连续句）；评测上述 11 集。检索：ColBERTv2 + Wiki 21M（部分任务）；代码用 SCODE-R + CodeSearchNet；多跳/LFQA/Dialog 用数据集自带 distractor 上下文。代码：github.com/xsc1234/INFO-RAG。
- **评价指标**：ODQA/Slot/多跳：cover EM 准确率；ELI5/WikiText：ROUGE-L；WoW：F1；代码：CodeBLEU；另报三场景（has-ans / replace / no-ans）、ICL 示例数曲线、正文档比例/位置/条数敏感性、MMLU（无 RAG）防遗忘。
- **对比基线**：同检索设定下的 LLaMA-2-7B/13B 及 chat；消融「仅在 Wiki 上标准 LM」；单任务 S1/S2/S3；开检索下 Previous SOTA / SearChain / SearChain+InFO-RAG；附录 BM25、简单 mask vs 信息 token mask。
- **主要结果**（Table 1）：相对点平均约 **+9.39%**——如 7B overall 35.78→**39.83**，13B-chat 43.23→**46.55**；多跳增益明显（7B Hotpot 39.40→46.56，MuSiQue 25.95→30.19）；代码跨域（仅 NL 训练）亦涨（Python/Java）。ICL：基线加 few-shot 常掉，InFO-RAG 可继续涨（Table 3）。SearChain+InFO-RAG 再超 SearChain（Table 4）。三场景均更稳，尤其 replace/no-ans（Table 2）。
- **消融结果**：Wiki 标准 LM ≈ 无增益（甚至略降），非「多训 Wiki」伪效应；S1 单训易过拟合伤害；S2/S3 各自对应场景有增益；**S1+S2+S3 最优**；信息 token mask > 简单 mask；正文档比例/位置/条数变化时 Max Δ 通常小于基线；MMLU 几乎持平（7B 45.3→45.0）。
- **失败场景**：① **与主候选正交偏「读侧」**：不学何时检索/停止/拒答，只学给定检索后如何精炼；② **Scenario 3 明确鼓励无证据仍用参数知识作答**——强化猜答而非拒答；③ no-ans 绝对准确率仍极低（常 <10%）；④ 噪声仿真是 token mask/替换，≠ 多源冲突/歧义/误导文档的类型化仲裁；⑤ 固定 top-k 读入，无在线充分性感知；⑥ 仅 7B/13B；⑦ 多跳开检索仍依赖外部框架（SearChain），自身非 agentic 轨迹策略。
- **资源要求**：LoRA 续训 LLaMA-2 7B/13B；4×A100，lr 1e-5，5K steps；需 Wikipedia +（评测时）ColBERTv2/BM25 等。相对全参 SFT / RL 更轻，可插拔。
- **可延伸问题**：InFO-RAG 补的是「检索已到 → 如何抗噪精炼」；主候选还缺「证据是否够 → 继续检索 / 停止回答 / 拒答」。若把 S3 监督从「刺激参数知识作答」改为「证据不足则拒答/澄清」，并与 when-to-retrieve 联训，能否同时覆盖精炼与充分性决策？
- **原文局限与未来方向**（Limitations）：算力不足，仅 7B/13B；未来更大模型。Conclusion 强调精炼视角、无监督通用性、可与 SOTA RAG 框架组合。

### 13. 短名：Factual-RAG 案例 (Li / Yuan / Zhang 2024)  20260813

- **研究问题**：开源 LLM 对**私有知识库、领域与时效查询**易幻觉；如何搭一套端到端 RAG（爬取→标注→检索→生成→评测）提升事实性？本质是 **CMU/LTI 私有库案例研究**，非新机制论文。
- **任务场景**：面向 CMU / LTI 的领域 QA（校历、项目史、论文数字等）；自建 KB + WizardLM 自动 QA 对；人工评测子集上做消融与 case study。
- **方法核心**：系统流水线而非算法创新。(1) **数据**：Selenium 爬 CMU 站 + Semantic Scholar 2023 LTI 论文 → 清洗分块（约 1000 词）→ WizardLM 每块 10 对 QA（共约 34.8k，训/测约 27.8k/7.0k；κ≈0.67）。(2) **检索**：`mxbai-embed-large-v1`（可域内微调）+ MMR top 检索 → **BGE-reranker-large** 重排至 top-5。(3) **生成**：LLaMA-2-7B-chat + LoRA（INT4）；提示含「不知道就说不知道」与篇幅约束。(4) 可改写上下文；模块端到端可训。
- **关键假设**：① 私有网页/论文爬取 ≈ 足够 KB；② 教师 LLM 合成 QA ≈ 可用监督；③ 标准 retrieve→rerank→read 即可抑幻觉；④ 小规模域内微调 embedding/生成器净收益为正（实验部分否定了生成器侧）；⑤ 提示拒答句 ≈ 有拒答能力（无系统评测）。
- **数据集**：自建 CMU/LTI（304 html + 12 pdf + 245 papers → QA 对）；非公开标准基准。代码：github.com/anlp-team/LTI_Neural_Navigator。
- **评价指标**：相对参考答案的 Recall / F1、句向量 Cosine、BLEU；每配置 4 次×随机 128 测题；无拒答率、引用忠实度、冲突处理指标。
- **对比基线**：无 RAG 基线；Raw RAG；+Embedding 微调；+Core 微调；+两者。无 Self-RAG / Adaptive / CRAG 等外部对照。
- **主要结果**（Table 1）：RAG 相对无检索全面提升（Recall 0.361→0.409，F1 0.186→0.289，Cosine 0.504→0.577，BLEU 0.043→0.102）。**仅微调 embedding** 再涨（Recall **0.437**，F1 **0.304**）。**微调 core / 双微调**：Recall 略升至约 0.45，但 F1/Cosine/BLEU **明显回落**（F1≈0.21，BLEU≈0.06）——小而偏的域内 SFT 伤害生成质量。
- **消融/案例**：作者归因于 7B + 步数少 + 数据偏斜；生成出现冗长、模板泄漏（`context:`/`answer:`）、复述原文而非改写；简单时效题可答对但易灌水；数字题敏感；中等检索难度题尚可。
- **失败场景**：① **与主候选几乎正交**：固定 top-k RAG，无「继续检索 / 停止 / 拒答」学习；② 提示有拒答句但**无拒答评测**；③ 小规模偏斜 SFT **损害**生成（与 RAFT「配方要对」同族警示）；④ 合成 QA 质量与教师偏差；⑤ 评测是表层重叠/相似度，非证据充分性或幻觉 taxonomy；⑥ 无多源冲突；⑦ 私有爬取难复现、泛化未知；⑧ 案例仍见复读、灌水、答非所问。
- **资源要求**：7B LoRA INT4；embedding 微调约 17k steps；自建爬虫与 WizardLM 标注；工程向，非大规模 RL。
- **可延伸问题**：案例证明「私有库 + RAG」必要，也证明**乱微调生成器会伤事实性以外的生成**。主候选若落地私有库，应把「证据不足拒答」做成可测指标，并避免用偏斜合成 QA 直接 SFT 生成器——宁可训检索/路由/充分性决策。
- **原文局限与未来方向**：无独立 Limitations；Conclusion 强调 embedding 微调有价值、小偏数据集微调大生成模型有限；指向更先进 QA 系统，未提动态检索策略。

### 14. 短名：ARM-RAG (Melz 2023)  20260813

- **研究问题**：冻结 LLM「聪明但健忘」——不从成败中学习；全量微调 / 更大模型成本高；经典 RAG 建好后参数与非参数记忆也固定。能否用 **低成本外存**，把成功解题的推理链（rationale）存起来再检索，提升后续解题？
- **任务场景**：**小学数学词题** GSM8K（非开放域知识 RAG）；训 5k / 测 2.5k；生成器 gpt-3.5-turbo；检索 Pyserini+FAISS。
- **方法核心**：**ARM-RAG**（Auxiliary Rationale Memory）。(1) 对训练集题多试（如 5 次），凡答对则把 **题 + 逐步 rationale + 答** 写入稠密索引；(2) 新题检索相似成功轨迹，拼进 few-shot 提示再生成；(3) **Obfuscated ARM-RAG**：检索时用 GPT 把名词/人名换成无意义词，削弱表面词匹配、逼检索更看结构。无参数更新、无拒答、无多轮证据决策——本质是「成功 CoT 的情景记忆式 RAG」。
- **关键假设**：① 成功 rationale 可迁移到新题；② 稠密检索能抓到**题型结构**而非表面主题；③ 只存成功轨迹足够（不学失败）；④ 多采样命中率可近似「可解性」；⑤ 混淆实体 ≈ 逼近结构匹配。
- **数据集**：GSM8K（取自 STaR 仓库划分）；索引仅含训练成功例。代码：作者 GitHub（Melz 2023）。
- **评价指标**：答案 Accuracy；另有单题 100 次采样准确率、强/负提示对照；无证据充分性/拒答指标。
- **对比基线**：无检索 GPT-3.5（训集约 73.2%）；同题强正确提示（单题可到 80%）、强错误提示（≈39%）；多试 5 次「任一正确」上界 91.9%；ARM vs Obfuscated ARM。
- **主要结果**（Table 2）：Baseline **73.2%** → ARM-RAG 测集 **75.3%** → Obfuscated **77.4%**（相对基线约 **+5.7%**）。训练集 ARM 达 89.0%，但约 **78%** 检索命中原题——偏「答案泄漏式提示」。单题强正确提示收益远大于 ARM。
- **消融/分析**：表面相似检索（杂货购物题）常捞到同主题但**缺百分比结构**的例；混淆后略好，仍常围着 shopping/buy；作者称需题型抽象或 taxonomy。
- **失败场景**：① **与主候选弱相关/偏正交**：外存的是数学 rationale，不是外部事实证据；无「继续检索 / 停止 / 拒答」；② 检索抓主题不抓结构，增益薄；③ 只记成功、忽略失败与冲突；④ 训练集虚高靠 exact match；⑤ 依赖 GPT 采样与 API 随机性；⑥ **未同行评审**（作者自承）；⑦ 非知识密集幻觉/私有库设定。
- **资源要求**：GPT-3.5 API + Pyserini 索引；Colab A100 跑实验；相对 STaR 微调几乎零训练成本。
- **可延伸问题**：ARM 提示「轨迹级外存」有价值，但主候选要的是**证据充分性决策**。若把记忆对象从「成功 CoT」换成「检索–批判–停止/拒答轨迹」，并按结构/冲突类型检索，能否低成本补强 agentic RAG？
- **原文局限与未来方向**：Known Limitations：未同行评审、可能有 bug。Analysis/Conclusion：增益有限；未来要题型抽象/分类以改进检索；承认强提示上限远未达到。

### 15. 短名：Corrective RAG / CRAG-纠正 (Yan et al., 2024)  20260814

> 注意：论文自简称 **CRAG**，≠ 清单里的 **CRAG Benchmark**（`06_CRAG-动态长尾评测`）。

- **研究问题**：标准 RAG 默认「检索必有用」；检索差时无关文档会误导生成。如何在**检索已出错**时做自我纠正、提高鲁棒性？
- **任务场景**：短答 PopQA（长尾子集）、长文 Biography（FactScore）、PubHealth 真假判定、ARC-Challenge 选择题；与 Self-RAG 同用 Contriever 检索结果。
- **方法核心**：**Corrective RAG**——轻量 **T5-large 检索评价器**对 query–doc 打相关分，聚合成三档动作：**(Correct)** 至少一篇过上阈值 → **decompose–filter–recompose** 抽关键知识条；**(Incorrect)** 全部低于下阈值 → **丢弃内部检索**，query 改写后 **Google Web Search** 取外网再精炼；**(Ambiguous)** 两路知识合并。即插即用，可挂标准 RAG 或 Self-RAG（Self-CRAG）。
- **关键假设**：① 整篇/条级相关分 ≈ 检索质量，可触发纠正；② 双阈值 + Ambiguous 可缓冲评价器误差；③ Web 可补静态语料缺口（偏好 Wiki 等权威页）；④ 滤噪后拼接即可，无需声明级支持/冲突类型；⑤ **Incorrect ≠ 拒答**——仍会搜网并生成，而非承认证据不足。
- **数据集**：PopQA / Biography / PubHealth / ARC-Challenge（公开）；评价器主要在 PopQA 剩余样本微调后迁移。代码：github.com/HuskyInSalt/CRAG。
- **评价指标**：Pop/Pub/ARC：Accuracy；Biography：FactScore；另报评价器准确率、检索变差时生成曲线、算力开销。
- **对比基线**：无检索 LLaMA/Alpaca/ChatGPT；标准 RAG；SAIL；Self-RAG；Ret-ChatGPT 等；消融三动作与 refinement/rewriting/selection；「一律加 web」对照。
- **主要结果**（Table 1，SelfRAG-LLaMA2-7b）：CRAG vs RAG——Pop **59.8** vs 52.8，Bio **74.1** vs 59.2，Pub **75.6** vs 39.0，ARC **68.6** vs 53.2；Self-CRAG 再超 Self-RAG（如 Pop **61.8** vs 54.9，Bio **86.2** vs 81.2）。换普通 LLaMA2-hf-7b 时 CRAG 仍稳，Self-RAG 大跌——因后者依赖特训反思标记。
- **消融结果**：去掉 Correct/Incorrect/Ambiguous 任一动作均掉点；refinement / rewriting / selection 均必要；T5 评价器 PopQA 相关判定 **84.3%** ≫ ChatGPT（≤64.7%）；检索故意变差时 Self-CRAG 掉得比 Self-RAG 缓；「一律加 web」远不如带纠正机制。
- **失败场景**：① **评价粒度是文档/条相关，非声明级充分性或冲突类型**；② Incorrect 走 Web 仍强制作答，**无显式拒答**；③ 依赖外部评价器微调与阈值（跨数据集需改阈值）；④ Web 引入噪声/偏见（作者用权威页缓解，未根除）；⑤ Ambiguous 可能混合噪声；⑥ 非轨迹中多轮「下一步搜什么」策略（相对 IRCoT/Search-R1）；⑦ 未来需去掉外挂评价器（作者自陈）。
- **资源要求**：T5-large（0.77B）评价器 + Google Search API + 任意生成器（7B 级）；相对 Self-RAG 批评器更轻；推理多一步评价与可选搜网。
- **可延伸问题**：Corrective RAG 是主候选的强跳板——「检索失败怎么办」已有三档动作。如何把 Correct/Incorrect/Ambiguous 升级为轨迹级 **继续检索（新查询）/ 停止回答 / 拒答**，并把评价从整篇相关推进到**声明级支持 + 冲突仲裁**？
- **原文局限与未来方向**（§6）：不可避免要微调外挂评价器；未来希望去掉外部评价器、让 LLM 自带检索评价能力。

### 16. 短名：HiPRAG (Wu et al., ICLR 2026)  20260814

- **研究问题**：Agentic RAG 普遍存在 **over-search**（已知仍搜）与 **under-search**（该搜不搜）——outcome RL 粒度粗，长度/次数惩罚易压掉必要检索。如何用**层次化、知识感知的过程奖励**同时抬准确率与检索效率？
- **任务场景**：与 Search-R1 同设定——训 NQ+HotpotQA；测 NQ / TriviaQA / PopQA / Hotpot / 2Wiki / MuSiQue / Bamboogle；Wiki 2018 + E5 top-3。
- **方法核心**：**HiPRAG**。(1) **可解析轨迹格式**：单容器内多 `` `<step>` ``，搜步=`(r,q,c,o)`，非搜步=`(r,o)`，便于规则切步。(2) **在线检测**：over-search——把 `q_i` 单独丢给策略模型再答，外判 `o_i`≈`o'_i` 则冗余；under-search——外判非搜步 `r/o` 事实或逻辑错则缺搜（故意不罚「局部对但不完整」以免逼过度搜）。(3) **层次奖励**：  
  `R = A(1-λf) + λf·F + λp·A·F·(Ncorr/N)`  
  过程 bonus **仅在答案对且格式对时**按最优步比例线性加码（主实验 λf=0.2, λp=0.4）。外判：GPT-4.1 mini（over）/ GPT-5 mini（under）。
- **关键假设**：① 步级「是否最优搜」可被外 LLM 在线可靠判定；② 最优步比例 ≈ 轨迹质量；③ 过程 bonus 门控可避免过早压检索；④ Cover EM ≈ 任务成功；⑤ **无拒答动作**——非搜错了只标 under-search，仍最终作答。
- **数据集**：上述 7 公开 QA；代码与模型：github.com/qualidea1217/HiPRAG。
- **评价指标**：**CEM**（主）；**OSR / USR**（过度/不足搜索率，式 2）；另报 Avg.#Searches、训练 reward 曲线。
- **对比基线**：Direct、RAG、IRCoT、Search-o1；RL：Search-R1、R1-Searcher(++)、β-GRPO；同格式消融 Search-R1-step* / β-GRPO-step*；λp=0 为 baseline。
- **主要结果**（Table 1）：HiPRAG-3B Avg CEM **65.4**、7B **67.2**（超 R1-Searcher++ 62.1 / Search-R1 60.3）。效率：7B-GRPO **OSR 2.3%**（文称基线类方法曾 >27%）、USR 可低至约 **29–33%**；3B 设定下 Avg.#Searches 约 2.45→**1.75**（相对 Search-R1 约 -29%）。跨 Qwen/Llama、PPO/GRPO、base/instruct 均涨。
- **消融结果**：仅改格式几乎不涨（涨点来自过程奖）；λp=0.4 最优（0.2≈无过程，0.6 过偏步纯度伤 CEM）；**只罚 over** → USR 飙到 52.7、CEM 58.8；**只罚 under** → USR 16.9 但 OSR 升、CEM 63.3；**双罚最好**（64.1）。λf 过大伤主目标。GRPO 更高分但不稳，PPO 更稳。
- **失败场景**：① **过程标签依赖外 LLM 与黄金答案（CEM）**，开放网/无标场景难迁移；② USR 仍高（常 30%+），「该搜不搜」未解透；③ **无拒答 / 冲突仲裁 / 声明级支持**；④ under 定义偏「非搜步事实错」，≠ 证据充分性；⑤ 格式约束可能降低推理灵活；⑥ 训练需批量重生 + 双外判，成本高；⑦ MuSiQue 等难多跳仍偏低（7B 约 34）。
- **资源要求**：4×A100 80GB，约 400 RL steps；策略 3B/7B + E5；训练期依赖 GPT-4.1/5 mini 判步。高于纯 outcome Search-R1。
- **可延伸问题**：HiPRAG 把「检索必要性」做成可学过程信号，是主候选核心拼图——如何在 **不依赖黄金答案/外判教师** 的情况下，把 over/under 与 **停止回答 / 拒答 / 冲突处理** 写入同一奖励，并压低仍高的 USR？
- **原文局限与未来方向**：无独立 Limitations；Conclusion 强调优化过程本身。Ethics 承认 Wiki/基座偏见；Reproducibility 较全。可延伸风险：奖励与开放分布偏移、过程奖对标准答案依赖（清单侧已点出）。

### 17. 短名：ALCE (Gao et al., EMNLP 2023)  20260815

- **研究问题**：LLM 作答难核验、易幻觉；商业带引用系统难复现。如何建立**可复现的自动评测**，要求端到端「检索证据 + 生成带行内引用的长答」，并量化流畅性 / 正确性 / 引用质量？
- **任务场景**：长文带引用 QA——**ASQA**（歧义事实，Wiki 21M）、**QAMPARI**（多实体列表，Wiki）、**ELI5**（why/how，Sphere≈899M）；每集抽 1k；句级声明可多引用（至多 3）。
- **方法核心**：**ALCE 基准 + 提示基线**（非新训练算法）。(1) 任务：检索 → 生成带 `[1][2]` 的陈述。(2) 自动指标：流畅 **MAUVE**；正确性按数据集（ASQA EM-recall / QAMPARI recall-5+prec / ELI5 用 InstructGPT 抽 3 子声明 + TRUE NLI **claim recall**）；引用用 TRUE NLI——**citation recall**（拼接引用是否蕴涵该句）与 **citation precision**（无关引用检测）。(3) 建模对照：Vanilla top-k、Summ/Snippet、Interact、InlineSearch、ClosedBook+PostCite、Rerank（按自动 citation recall 选样）。
- **关键假设**：① 句级切分 ≈ 可核验声明单元；② NLI 蕴涵 ≈ AIS「可归因」；③ 流畅+正确+引用三维可防捷径；④ 提示即可测「带引用生成」能力上限；⑤ **有引用 ≠ 证据充分再答**——无拒答设定。
- **数据集**：上述三集各 1k；Wiki 2018-12 / Sphere；代码数据：github.com/princeton-nlp/ALCE。无引用监督训练数据。
- **评价指标**：MAUVE；EM-recall / recall-5 / claim recall；citation Rec/Prec；人工 utility + 引用（与自动强相关，κ≈0.70/0.53）。
- **对比基线**：ChatGPT / GPT-4 / LLaMA(2)-Chat / Vicuna 等 + GTR/DPR/BM25；多种合成与后编辑策略。
- **主要结果**：流畅普遍尚可；正确与引用仍有大缺口——**ELI5 上最佳系统约一半情况引用未完整支持**（ChatGPT Vanilla cite Rec≈51%，人工≈50.8%）。ClosedBook+PostCite 正确性可强但引用差（ASQA cite Rec 26.7 vs Vanilla 73.6）。Summ/Snippet 常抬正确、伤引用；InlineSearch/Interact **未优于 Vanilla**；Rerank 抬引用；GPT-4 用更多段落双边升，ChatGPT-16K 加段几乎无益。检索 recall 远高于生成正确性——上下文有答案仍用不好。
- **消融/分析**：GTR>DPR；ChatGPT 正确性约 top-1 见顶、引用约 top-3 见顶；指令微调显著改善开源引用；三维指标可抓「整段复读作答」捷径。
- **失败场景**：① **评测向**：不学何时检索/停止/拒答；② ELI5 引用支持仍 ≈半失败；③ 易被无关段落干扰（开卷可低于闭卷正确性）；④ 多源综合弱、长上下文利用有限；⑤ NLI 难判「部分支持」、cite Prec 偏低；⑥ 无多跳/数学/代码；⑦ 无监督微调引用模型（缺标注）。
- **资源要求**：评测需 TRUE（T5-11B）+ MAUVE +（ELI5）InstructGPT 造声明；推理主要为 API/开源 LLM + 检索器。
- **可延伸问题**：ALCE 给出主候选「证据是否够」的**验收口径**——声明级 citation recall/prec。如何把这些信号做成**在线充分性决策**（支持不足 → 再检索 / 拒答），而非仅事后打分？并与冲突类型、多跳过程对齐？
- **原文局限与未来方向**（Limitations）：MAUVE 不稳；ELI5 子声明难覆盖全体答案；NLI 限制；未覆盖多跳等难场景；仅 prompting，训引用模型留待未来。Conclusion：更好检索整合、长上下文、多源综合。

### 18. 短名：FRAMES (Krishna et al., 2024)  20260815

- **研究问题**：现有基准常把事实性 / 检索 / 推理**拆开测**，难反映端到端 RAG。如何用统一评测集同时压这三项，尤其是跨多文档整合与多跳推理？
- **任务场景**：**FRAMES**——824 道人工（非纯合成）多跳事实题；答案需 2–15 篇 Wiki（约 36% 两篇、35% 三篇）；推理类型含数值 / 表格 / 多约束 / 时间 / 后处理（可重叠）；含时间戳消歧。公开：huggingface.co/datasets/google/frames-benchmark。
- **方法核心**：**评测基准 + 多步检索管线示意**。(1) 数据：合成尝试幻觉高（>30%）故改人工；质量检查含时效消歧、去 yes/no、抗污染（需额外运算非纯背事实）。(2) 单步基线：Naive / BM25-R / Oracle（金标全文）。(3) **多步**：每轮生成 k 查询 → BM25 top-n_docs 累积上下文，共 n 轮再作答；加「不重复查询 + 规划示范 + CoT」显著提升。(4) 自动裁判 LLM 与人工对齐（Acc 0.96，κ 0.889）。
- **关键假设**：① 端到端 Acc（答案是否含金标）≈ 事实+检索+推理统一能力；② BM25+Wiki dump 足以测规划（固定检索器）；③ Oracle 为完美检索上界；④ **无拒答 / 引用 / 冲突指标**——只看最终对错。
- **数据集**：824 测题 + 所需 Wiki 列表；无训练划分（评测集）。
- **评价指标**：Accuracy（LLM autorater）；另报按推理类型分解、多步 (k,n,n_docs) 曲线；BM25 上下文 recall。
- **对比基线**：Gemini-Pro/Flash-1.5、Gemma2-27B、Llama-3.2-3B-I、Qwen2.5-3B-I；单步 vs 多步规划。
- **主要结果**（Gemini-Pro）：Naive **0.408** → BM25-4 **0.474** → Oracle **0.729**；带规划多步最优约 **0.66**（(k,n,n_docs)=(5,5,10)，相对 Naive >50% 提升，逼近 Oracle）。Oracle 仍错约 27%，其中 ~80% 属数值/表格/后处理——**给齐证据仍不会算**。小模型 Naive 更低（3B≈0.10–0.12）。数值类多步可超过单步 Oracle（因多轮补检索）。
- **消融/分析**：无规划时多步增益慢且查询多样性差；规划示范后逼近 Oracle；多约束与后处理从加文档受益明显；数值/表格/后处理最难。
- **失败场景**：① **纯终点 Acc**，无 hop 级诊断、无引用充分性、无拒答；② 检索器固定 BM25，非稠密/agentic 检索 SOTA；③ 多步成本高（约 6 次串行推理）；④ Wiki 预训练污染风险（作者 Limitations）；⑤ 覆盖域仍偏百科 trivia，非私有库/冲突证据；⑥ Oracle 证明「充分证据仍推理失败」与主候选「证据够则答」正交缺口。
- **资源要求**：评测 API（Gemini 等）+ Wiki BM25 索引；多步贵。数据开源。
- **可延伸问题**：FRAMES 是主候选的**端到端难度探针**。如何把「多步检索规划」与充分性决策结合——何时停搜 / 何时承认算不出或证据仍不足而拒答，并用 hop 级与声明级指标替代纯 Acc？
- **原文局限与未来方向**（Limitations）：预训练污染；场景覆盖不全。Future Work：稠密多跳检索、过程监督/蒸馏、上下文压缩、扩域与实时检索。

### 19. 短名：CRAG Benchmark (Yang et al., 2024 / KDD Cup)  20260815

> 注意：≠ Corrective RAG（矩阵 §15）。本篇是 **Comprehensive RAG Benchmark**。

- **研究问题**：现有 RAG 评测难覆盖真实 QA 的**动态性、长尾、复杂度与噪声检索**。如何建综合事实 QA 基准（含 mock Web/KG API），并惩罚幻觉、鼓励「不知道」？
- **任务场景**：**4409** QA；五域（Finance/Sports/Music/Movie/Open）；八类题（Simple、带条件、Set、Comparison、Aggregation、Multi-hop、Post-processing、**False Premise**）；动态性 real-time→static；实体 head/torso/tail。检索：Brave 至多 50 HTML + mock KG（2.6M 实体）+ 38 mock API。三任务：① ≤5 页摘要生成；② KG+Web；③ 端到端（50 页噪声更大）。
- **方法核心**：**评测基准**（非新算法）。评分：Perfect/Acceptable/Missing/Incorrect → **1 / 0.5 / 0 / −1**；**幻觉重罚、Missing（拒答）优于 Incorrect**；truthfulness=均分。自动评：精确匹配 + GPT-3.5/Llama3 三路判别。另有工业 SOTA 人工评与流量加权。
- **关键假设**：① 分层切片（动态/流行度/题型）可洞察缺口；② mock API ≈ 真实检索噪声；③ Missing 标签可测可信度；④ 快照式实时题可泛化到演化查询。
- **数据集**：github.com/facebookresearch/CRAG/；验证/公开测/私有测划分；KDD Cup 2024。
- **评价指标**：Accuracy / Hallucination / Missing；Truthfulness（auto/human）；按域、动态性、流行度、题型分解；延迟。
- **对比基线**：LLM-only（Llama2/3、Mixtral、GPT-4 Turbo 等）；朴素 RAG（固定窗拼接 snippet）；工业 SOTA（Copilot Pro、Gemini Advanced、ChatGPT Plus、Meta SG、Perplexity）。
- **主要结果**：LLM-only Acc **≤34%**；朴素 RAG 至约 **44%**（幻觉常升，truthfulness 可仍 ≤20%）。工业最佳 Perfect≈**63%**、Truthh≈**51%**（Copilot），幻觉仍 **16–25%**。更难：实时/快变、长尾、Set/后处理/假前提（SOTA 对假前提有改善）。KG 简短精确有助；50 页 recall↑ 但窗限导致 >30% 题证据进不了 prompt。
- **消融/洞察**：检索噪声易诱发幻觉；头实体 RAG 有时伤 truthfulness（依赖检索反而不稳）；长尾/躯干 RAG 有增益；排名与上下文选择关键。
- **失败场景**：① 仍非跳级过程诊断；② Missing 有鼓励但**多数系统 Missing 率低、幻觉高**（ChatGPT Plus Missing 仅≈2%）；③ 无声明级引用指标（相对 ALCE）；④ 冲突仲裁未类型化（虽有 False Premise）；⑤ mock/快照难覆盖全网实时；⑥ 三任务未测完整搜索排序（可扩至 220K 页语料）。
- **资源要求**：跑基线需 API + mock；评测需双 LLM 裁判或人工。数据开源维护。
- **可延伸问题**：CRAG 把 **Missing** 写进主指标，直接对齐主候选「证据不足 → 拒答」。如何把动态/长尾/假前提切片上的充分性决策做成可学策略，并与 ALCE 引用、FRAMES 多跳、HiPRAG 必要性统一验收？
- **原文局限与未来方向**：Conclusion 规划多语/多模/多轮。附录 Limitations 等；强调持续维护。核心缺口已由实证指出：动态、长尾、复杂推理、抗噪利用检索。

### 20. 短名：AgenticRAGTracer (You et al., 2026)  20260815

- **研究问题**：现有多跳基准多只有终问答、缺**中间 hop 子题**，难诊断「第几跳 / 检索还是规划」出错；人工造题难扩展。如何自动构造带拓扑与 hop 真值的 Agentic RAG 诊断基准？
- **任务场景**：**1305** 例（人工终审，κ≈0.65）；拓扑 **Inference（串行）** / **Comparison（并行）**；难度 2/3/4-hop；跨 ≥11 域；语料对齐 FlashRAG Wiki 索引，与 Hotpot/2Wiki/MuSiQue 去重。统一 **Qwen-Agent + ReAct** 评 13 模型（含 Search-R1 / ReSearch / R-Search）。
- **方法核心**：**Hop-aware 基准 + 自动造题管线**。(1) 原子 QA（滤参数可答、须文档可解）；(2) 合成为 2-hop 再迭代到 3–4-hop；(3) 结构/语义/必要性三关过滤（不可参数直答、去任一文不可解、全证据可解）；(4) SPARQL 消歧 + 三人人工 Retain/Discard。评测：终答 EM/F1/LLM-Judge；**MaxD、Steps-C/I**；可对中间 hop 对照诊断。
- **关键假设**：① 中间 hop 真值可定位失败跳；② LLM 合成+过滤 ≈ 真实 agentic 多跳；③ 步数与任务 hop 对齐 ≈ 轨迹质量；④ 统一 ReAct 外壳可公平比模型。
- **数据集**：github.com/YqjMartin/AgenticRAGTracer；与主流多跳集无重叠。
- **评价指标**：EM / F1 / LLM-Judge（按 Comparison/Inference × hop）；MaxD；正确/错误轨迹平均步数；检索 top-k 行为分析。
- **对比基线**：闭源 GPT-5/o4-mini/Grok 等；开源 DeepSeek/Qwen；7B agentic 训后点（Search-R1、ReSearch、R-Search）。
- **主要结果**：难度陡——**GPT-5 在 4-hop Inference 仅 EM 22.6%**；hop↑ 全面掉点，Inference 难于 Comparison。正确轨迹步数贴近目标 hop；错误轨迹常 **过早坍缩或过度延伸（Steps-I ≫ Steps-C）**。GPT-4o 因保守 top-k 信息瓶颈极差。开源随规模升；7B agentic 训后明显强于基座。失败常起于**首跳任务分解错误**，后续检索再准也难回正。
- **消融/诊断**：宽检索（更大 top-k）与强模型相关；黑盒终答评测看不到「步结构错配」。Discussion 明确：缺元认知——死胡同不会重规划，也不能区分「还需证据」与「逻辑深渊」，需 **course correction + informed termination**。
- **失败场景**：① 合成题可能偏百科链式 trivia；② 评测仍偏终点+步数，**无拒答/引用/冲突标签**；③ ReAct 强制规划≠真自主；④ 依赖 FlashRAG 索引设定；⑤ 中间 hop 诊断能力在公开结果中主要用 MaxD/步数代理，完整 hop-EM 协议需跟代码。
- **资源要求**：FlashRAG 语料+索引；ReAct agent 框架；多模型 API。数据开源。
- **可延伸问题**：Tracer 给主候选 **hop 级验收与过程奖励对齐工具**。如何把「步数–hop 错配 / 首跳分解失败」做成可学信号，并显式加入 **停止回答 / 拒答 / 重规划**，避免错误轨迹上的 flailing？
- **原文局限与未来方向**：无独立 Limitations；Conclusion 强调步级透明与自纠正系统。Discussion 已点出 informed termination 缺口。
