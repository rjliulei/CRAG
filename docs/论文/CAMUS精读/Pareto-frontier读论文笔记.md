# Pareto frontier（帕累托前沿）是什么？——读论文收获

> 写作动机：读 IGP（*Less is More for RAG*）时反复出现 **quality–cost Pareto frontier**；把概念钉死，方便以后读压缩/剪枝/选证类论文。  
> 关联：[`02_IGP-逐节中英精读笔记.md`](./02_IGP-逐节中英精读笔记.md) · [`../12-CAMUS精读论文解析.md`](../12-CAMUS精读论文解析.md)

---

## 1. 一句话

**Pareto frontier（帕累托前沿）**：在多个互相冲突的目标下，那些「没法在不损害某一目标的同时改进另一目标」的解所连成的边界。

日常说法：**已经做到最好的一批折中方案**；再想更好，就必须牺牲别的。

---

## 2. 从「两个目标打架」说起

假设你只能同时关心两件事：

| 目标 A | 目标 B | 典型冲突 |
|--------|--------|----------|
| 答案质量 ↑（F1 / accuracy） | 成本 ↓（token 数 / 延迟 / 钱） | 多塞证据可能略涨分，但上下文更贵 |
| 召回 ↑ | 精度 ↑ | 多捞文档 vs 少而准 |
| 答对率 ↑ | 拒答/安全 ↑ | 敢答 vs 少幻觉 |

若只报「F1 高了」而成本暴涨，或「更省 token」但质量崩了，**无法判断方法整体是否更好**。  
Pareto 视角强迫你看：**在同样的成本水平下，质量是否更高？在同样的质量水平下，是否更便宜？**

---

## 3. 图怎么读（质量–成本平面）

IGP 一类论文常画：

```text
        质量 ↑（如 F1）
            │
            │          ★ 更好的前沿（「左上」）
            │        ╱
            │      ╱  IGP 曲线
            │    ╱
            │  ●──●──●  普通重排（贴着基线）
            │●
            └──────────────→ 成本 ↑（如平均输入 token TK）
```

约定（IGP Fig.3 / Fig.6）：

- **横轴**：成本（TK，越大越贵）——希望往**左**。  
- **纵轴**：质量（F1，越大越好）——希望往**上**。  
- 因此 **「左上移」= 前沿变强**：更便宜，或同样价更准，或双赢。

某一方法在扫不同预算（如 TopM=1,2,3,…）时得到一串点；把「不被其他点全面支配」的点连起来，就是该设定下的 **经验 Pareto 前沿**。

---

## 4. 支配（dominate）——判断谁更好

点 \(P\) **支配** 点 \(Q\)（在「质量↑、成本↓」约定下）当且仅当：

- \(P\) 的质量 ≥ \(Q\)，且  
- \(P\) 的成本 ≤ \(Q\)，且  
- 至少有一个严格更好。

则 \(Q\) 不在前沿上（被淘汰）。  
前沿上的点彼此：**一个 F1 更高但更贵，另一个更省但 F1 略低**——没有绝对赢家，只有折中菜单。

**「加强 Pareto frontier」**（论文话术）≈：新方法的点整体更靠左上，能支配旧方法的许多运行点。

---

## 5. IGP 里具体怎么用

| 论文用语 | 含义 |
|----------|------|
| quality–cost trade-off | 质量与成本的折中 |
| Pareto frontier | 扫 TopM 等预算后，F1–TK 平面上的有效边界 |
| win–win | 同时抬 F1 **且** 降 TK（严格支配基线的一种强情况） |
| NTE（Normalized Token Efficiency） | 相对「仅检索」的 (F1/TK) 比值；辅助看「每 token 买到的质量」，**不是**前沿本身 |

读 IGP 的收获：

1. **只重排、不剪枝**时，TopM=5 仍塞满五段 → TK 几乎不变 → 点主要在竖线上挪一点，前沿几乎不动。  
2. **准入剪枝（\(T_p\)）** 才真正把点往左推，并常带动 F1 上升 → 前沿左上移。  
3. 换检索器（BM25→Contriever）仍看同一张图：故事是否「同质」，用前沿形状比单点分数更稳。

## 6. 和「单一指标最优」的差别

| 单一最优 | Pareto |
|----------|--------|
| 固定一个目标（如只比 F1） | 同时保留多个目标 |
| 容易选出「刷分但很贵」的系统 | 给出一整条可选工作点 |
| 部署时仍要再拍脑袋调预算 | 前沿上的点可直接当部署菜单（偏质量 / 偏省钱） |

论文写「我们改善了 Pareto frontier」，比只写「F1 +2%」更诚实：承认 **没有免费午餐**，但声称 **折中菜单整体更好**。

---

## 7. 读图时的坑

1. **轴方向**：有的图横轴是「节省量」或把成本画成「越右越好」——先看轴标签。IGP 是右=更贵。  
2. **只报一个工作点**：不等于前沿；要扫预算/阈值才谈 frontier。  
3. **未计入的成本**：IGP 的探测 rollout（\(N+1\) 次）若不算进 TK，前沿偏乐观；读文时要对齐「成本定义」。  
4. **平均跨数据集**：跨集平均 F1–TK 好看，不保证每一集都左上。  
5. **与校准/拒答**：CRAG 还有 hallucination vs missing；那是另一组多目标，也可谈 Pareto，但轴不同。

## 8. 和 CAMUS 的关系（备忘）

- CAMUS 主叙事是 **选证键**（约束 ΔU ≠ cosine ≠ 熵减），不是主打质量–成本 Pareto。  
- 但落地仍有预算（top-k / 早停）：报告时可用「固定成本下 accuracy/`rag_worse`」或简单 F1–上下文长度图，**借用** Pareto 读法，避免只报一个分数。  
- SAFE-U 对照 IGP 时：若 IG 排序更尖但错自信 ↑，可能出现「TK↓ 但 rag_worse 更糟」——用双目标一眼能看出 **并非** 真左上。

## 9. 术语对照

| 英文 | 中文 | 备注 |
|------|------|------|
| Pareto optimal / efficient | 帕累托最优 / 有效 | 前沿上的单个解 |
| Pareto frontier / front | 帕累托前沿 / 前沿面 | 全体有效解的集合/曲线 |
| dominated | 被支配 | 可被全面改进，不在前沿 |
| trade-off | 折中 / 权衡 | 两目标反向拉扯 |
| operating point | 工作点 / 运行点 | 某一预算或阈值下的具体配置 |

名称来自经济学家 Vilfredo Pareto；工程/ML 里借用其「多目标无绝对最优、只谈不被支配」的框架。

---

## 10. 三句收束（可贴笔记）

1. **Pareto frontier = 多目标下「没法再白白改进」的折中边界。**  
2. **RAG 里常见质量↑ vs 成本↓；曲线「左上移」= 方法声称的系统级变好。**  
3. **读 IGP：剪枝改变的是前沿，只重排往往只在固定成本竖线上微调。**
