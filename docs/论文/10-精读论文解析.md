## 一、#1 · CRAG Benchmark — 实验舞台

**原文**：Xiao Yang et al. *CRAG – Comprehensive RAG Benchmark*. NeurIPS 2024 D&B / arXiv:2406.04744 / KDD Cup 2024.  
**本地 PDF**：`06_CRAG-动态长尾评测.pdf` · **代码**：https://github.com/facebookresearch/CRAG/

### 一句话概括

**4409** 道事实 QA + 模拟 **Web/KG/API** 检索，覆盖动态/长尾/八题型；评分 **重罚幻觉、鼓励 Missing（拒答）**，是「现实噪声 RAG」的综合评测台。

### 问题

现有 RAG 基准难同时覆盖：**动态事实、长尾实体、题型复杂度、检索噪声**；且多数只报 accuracy，不区分「错答」与「该拒未拒」。

### 方法要点

- **数据**：五域（Finance/Sports/Music/Movie/Open）；八类题（Simple、条件、Set、Comparison、Aggregation、Multi-hop、Post-processing、**False Premise**）；实体 head/torso/tail；动态性 real-time→static。
- **检索**：Brave 至多 50 HTML + mock KG（2.6M 实体）+ 38 mock API；Task3 端到端噪声更大（50 页）。
- **评分**（官方）：Perfect / Acceptable / Missing / Incorrect → **1 / 0.5 / 0 / −1**；truthfulness = 均分。**Missing 优于 Incorrect**。
- **你们 dev 用法**：Task1/2 全量 v4；裁判四分类 → **score = (2×correct + missing)/n − 1**（与官方 truthfulness 口径相关但不完全相同，写论文时需注明）。

### 主要结果（原文）

| 设置 | 大致水平 |
|------|----------|
| LLM-only | Acc ≤ **34%** |
| 朴素 RAG | Acc ~**44%**（幻觉常升，truthfulness 可仍 ≤20%） |
| 工业 SOTA | Perfect ~**63%**，truthfulness ~**51%**，幻觉仍 **16–25%** |
| 难点切片 | 实时/快变、长尾、Set/后处理/假前提 |

### 局限

- **基准 only**，不提供统一拒答算法；多数系统 **Missing 率低、幻觉高**（如 ChatGPT Plus Missing ≈2%）。
- 无声明级引用指标（相对 ALCE）；冲突类型未系统化为动作空间。
- Mock/快照网页 ≠ 全网实时；上下文窗限导致部分证据进不了 prompt。

### 没覆盖你们什么（作为基准，本文是「舞台」而非「方法」）

| CRAG 提供 | 你们要在舞台上做的 |
|-----------|-------------------|
| 题型/域/动态/长尾切片 | 在 **Task1/2 网页 RAG** 上测 **规则支持度拒答** |
| Missing 进指标 | 你们现象：**RAG 抬 accuracy 但 hallucination↑** |
| False Premise 题型 | 你们子集：**假前提已 largely missing**，非主卖点 |

### 我们可增量（措辞草案）

> 在 CRAG 噪声网页设定上，于 **已有 Vanilla/RAG 基线** 之上增加 **证据支持度门控拒答**，针对全量已见的「多答对、多幻觉、少拒答」瓶颈，而非另建基准。

### 速填模板

```text
设定：4409 QA；mock Web/KG；八题型含假前提
方法：分层评测；Missing 优于 Incorrect
没覆盖我们：（基准）方法层：支持度拒答 / rag_worse / Step 4 规则
我们可增量：在同一 benchmark 上验 hallucination↓ + score↑
```

## 二、#2 · RGB — 拒答与噪声鲁棒

**原文**：Jiawei Chen et al. *Benchmarking Large Language Models in Retrieval-Augmented Generation*. AAAI 2024 / arXiv:2309.01431.  
**本地 PDF**：`08_RGB-拒答与噪声鲁棒.pdf`

### 一句话概括

双语 **RGB** 把 RAG 能力拆成四类：**噪声鲁棒、negative rejection、信息整合、反事实鲁棒**；用 Search API 新闻文档评测 6 个 LLM，证明「加了检索仍远未可靠」。

### 问题

RAG 评测缺细粒度诊断：网页噪声、全无答案、多文档整合、文档故意写错时 LLM 行为如何？

### 方法要点

- **四 testbed**：Noise Robustness / **Negative Rejection**（仅噪声 doc → 应拒）/ Information Integration / Counterfactual Robustness。
- 数据：最新新闻 + Search API snippet，中英双语。
- 指标：准确率、**Rejection rate**（精确匹配 + ChatGPT 判 Rej*）。

### 主要结果

| 能力 | 关键发现 |
|------|----------|
| 噪声鲁棒 | 有一定抗噪；易混淆相似实体/年份 |
| **Negative rejection** | **最难**；Rej* 最高约 **45%**（英/中）；大量仍硬答 |
| 信息整合 | 无噪声最高 ~60–67%；加噪更低 |
| 反事实 | 有正确答案+风险提示，仍倾向信检索 |

### 局限

- 模型偏旧；Rej 判据与 CRAG 四分类裁判不对齐。
- Search 新闻 snippet ≠ CRAG HTML 切块 + 动态长尾。
- **只评能力、不给拒答方法**。

### 没覆盖你们什么

| RGB | 你们 |
|-----|------|
| 四能力 testbed | CRAG **score 公式 + hallucination/missing 分列** |
| 「全噪声应拒」 | **假前提已拒**；主矛盾 **有检索仍编 / rag_worse** |
| 新闻 Search API | **CRAG 八题型 + 网页噪声** |

### 我们可增量

> RGB 证「不会 negative rejection」；我们在 **CRAG** 上用 **声明级支持度阈值** 做答/拒，用原生四指标验收。

### 速填模板

```text
设定：新闻 + Search API；四 testbed
方法：评 noise / rejection / integration / counterfactual
没覆盖我们：CRAG 网页 / score / rag_worse / 生成错主导
我们可增量：支持度不足→拒答；CRAG 四指标
```

## 三、#3 · RAGTruth — 幻觉语料与检测

**原文**：Cheng Niu et al. *RAGTruth: A Hallucination Corpus for Developing Trustworthy Retrieval-Augmented Language Models*. ACL 2024 / arXiv:2401.00396.  
**本地 PDF**：`RAGTruth- A Hallucination Corpus for Developing Trustworthy Retrieval-Augmented Language Models.pdf`  
（另有 `research/papers-20260727/12_RAGTruth_ACL2024.pdf`）

### 一句话概括

近 **1.8 万**条真实 RAG 回答、**词级幻觉**与强度标注；可训较小检测器逼近 GPT-4 级提示检测——强调 **有检索上下文仍可能产生无支持声明**。

### 问题

RAG 幻觉缺大规模、细粒度监督；需区分「生成错」与「检索错」，并支持可信 RAG 开发。

### 方法要点

- 语料：多域 RAG 场景自然回答 + **span 级 hallucination 标注**（是否与检索证据一致）。
- 任务：幻觉 **检测**（非端到端拒答策略）；小模型可接近 GPT-4 检测效果。
- 定义：幻觉 = 生成内容 **不被检索上下文支持**（含编造、过度推断）。

### 主要结果（要点）

- 即便提供检索文档，模型仍频繁产出 **unsupported claims**。
- 检测器可实用化，便于审计/后处理；**检测 ≠ 预防**。

### 局限

- **标注/检测基准**，不是 CRAG 式任务成功率或 missing 优化。
- 未给出统一 **答前拒答** 或 **支持度门控** 训练配方。
- 语料域与 CRAG 网页设定不完全一致。

### 没覆盖你们什么

| RAGTruth | 你们 |
|----------|------|
| 词级幻觉检测语料 | **CRAG 四分类裁判** + 子集 **50% 幻觉率** 结构 |
| 事后检测 | Step 4 **答前** 支持度阈值 → missing |
| 通用多域 RAG 回答 | **rag_worse、过度检索、假前提** 等 CRAG 桶 |

### 我们可增量

> 借用 RAGTruth 的「无支持声明」定义写 Related Work；贡献落在 **CRAG 上答前拒答/压幻觉**，不必复现其检测器训练。

### 速填模板

```text
设定：~18k RAG 回答；词级幻觉标注
方法：幻觉检测器；unsupported span 定义
没覆盖我们：CRAG score / 拒答策略 / 噪声网页 task
我们可增量：检测思想→答前门控；不对标检测 F1
```

## 四、#4 · Self-RAG — 检索/批判/生成统一（训练侧对照）

**原文**：Akari Asai et al. *Self-RAG: Learning to Retrieve, Generate, and Critique through Self-Reflection*. ICLR 2024 / arXiv:2310.11511.  
**本地 PDF**：`../papers/重点精读/04_Self-RAG-检索批判生成.pdf`（`20260804` 目录有同名副本）

### 一句话概括

训练单一 LM，用 **reflection tokens** 自适应决定 **是否检索、是否相关（ISREL）、是否支持（ISSUP）** 及效用，推理期可调权重，提升事实性与引用。

### 问题

固定 top-k 检索损害通用能力或引入噪声；需把检索决策与生成、批判统一进同一可训练过程。

### 方法要点

- **标记**（Table 1）：Retrieve ∈ {Yes, No, **Continue**}；ISREL；**ISSUP** ∈ {fully, partially, no support, **contradictory**}；ISUSE(1–5)。
- 训练：批评器（Llama2-7B，部分 GPT-4 标签）离线插入标记 + 段落；~150k 指令对。
- 推理：按需检索 → top-K 并行生成 → 批判分数加权选段（可调阈值/权重）。

### 主要结果（Self-RAG-7B/13B 量级）

PopQA **54.9/55.8**，TriviaQA **66.4/69.3**，PubHealth **72.4/74.5**，Bio FactScore **81.2/80.2**，ASQA citation prec **66.9/70.3**。多项超 ChatGPT / 标准 RAG。

### 局限

- **Continue ≠ 新查询再搜**；多跳弱于 IRCoT/ReAct。
- **无显式「证据不足 → 拒答」**；ISSUP 偏单文档–单片段。
- 需 **训练** 批评器/生成器；8B 单卡 + 规则改进约束下 **不宜直接复现**。
- Ethical 自承：仍可能生成引用未充分支持的内容。

### 没覆盖你们什么

| Self-RAG | 你们 |
|----------|------|
| 可训练 reflection tokens | **规则/轻量** 支持度门控；Llama-3.1-8B 无微调 |
| Contriever + 百科/短答 | **CRAG 嘈杂网页** |
| IsSup 作生成内信号 | **CRAG missing/hallucination + score** |
| 纠检索/支持但未针对 rag_worse 桶 | 错误分析 **Vanilla 对、RAG 错** |

### 我们可增量

> 借鉴 ISSUP「是否被证据支持」语义，用 **规则/LLM 判支持度** 做答拒，**不**一口吃 Self-RAG 训练框架；写差异时强调 **成本与设定**。

### 速填模板

```text
设定：短答+长文引用；Contriever
方法：reflection tokens；ISREL/ISSUP/Retrieve
没覆盖我们：CRAG 网页 / 无训练预算 / 显式 missing 优化 / rag_worse
我们可增量：IsSup 思想→声明级门控；规则最小改进
```

## 五、#5 · Corrective RAG (Yan) — 检索质量纠偏

**原文**：Shi-Qi Yan et al. *Corrective Retrieval Augmented Generation*. arXiv:2401.15884.  
**本地 PDF**：`02_CorrectiveRAG-检索纠正.pdf`  
**注意**：论文简称 **CRAG** ≠ **Comprehensive RAG Benchmark**（#1）。

### 一句话概括

轻量 **T5-large 检索评价器** 对 query–doc 打相关分 → 三档 **Correct / Incorrect / Ambiguous**，触发 **滤噪重组、弃检索改 Web 搜、或合并**；即插即用，可挂 Self-RAG（Self-CRAG）。

### 问题

标准 RAG 假设「检索必有用」；检索差时无关文档误导生成——**检索失败怎么办**？

### 方法要点

- **Correct**：至少一篇过上阈值 → decompose–filter–recompose 抽知识条。
- **Incorrect**：全部低于下阈值 → **丢弃内部检索**，query 改写 + **Google Web Search** 再精炼。
- **Ambiguous**：两路合并。
- **关键**：Incorrect **≠ 拒答**——仍会搜网并 **倾向作答**。

### 主要结果（SelfRAG-LLaMA2-7b 设定）

CRAG vs RAG：Pop **59.8** vs 52.8，Bio FactScore **74.1** vs 59.2，Pub **75.6** vs 39.0，ARC **68.6** vs 53.2。Self-CRAG 再超 Self-RAG。检索故意变差时 Self-CRAG 更稳。

### 局限

- 评价粒度 = **整篇/条相关**，≠ **声明级充分性** 或冲突类型。
- **无显式拒答**；Incorrect 走 Web 仍硬答。
- 依赖 T5 评价器微调 + 阈值 + Search API。
- **纠检索 ≠ 判断「证据够不够答」**。

### 没覆盖你们什么

| Corrective RAG | 你们 |
|----------------|------|
| 文档质量三档 + Web 回退 | **答前支持度/一致性 → missing** |
| PopQA/ARC 等短答 | **CRAG 动态/长尾/假前提** |
| 检索差则换源 | **rag_worse**：有检索但 **比 Vanilla 更差** |

### 我们可增量

> 可借鉴「评价器触发动作」，但贡献落在 **充分性/冲突 → 拒答**，而非 Incorrect→Web；写 Related Work **必区分两个 CRAG**。

### 速填模板

```text
设定：Contriever + T5 评价器；PopQA/Bio/Pub/ARC
方法：Correct/Incorrect/Ambiguous → 滤噪或 Web
没覆盖我们：拒答/missing 优先 / CRAG benchmark / rag_worse
我们可增量：文档级过滤可借鉴；主贡献=支持度门控
```

## 六、#6 · Sufficient Context — 证据充分性拒答 ★

**原文**：Hailey Joren et al. *Sufficient Context: A New Lens on Retrieval Augmented Generation Systems*. **ICLR 2025** / arXiv:2411.06037.  
**本地 PDF**：`09_SufficientContext-证据充分性拒答.pdf` · **代码**：https://github.com/hljoren/sufficientcontext

### 一句话概括

定义 **sufficient context**，用 **autorater（~93%）** 标充分/不充分，分层分析 RAG 错误；**selective generation** 在应答子集上正确率 **+2–10%**。

### 问题

RAG 出错因 **检索差** 还是 **上下文够/不够时仍乱答**？ prior「相关/含答案」代理不够。

### 方法要点

1. **Sufficient**：上下文含 definitive 作答所需全部信息；**Insufficient**：不全/矛盾/缺专业知识；**不需 gold answer 标注**。
2. **Autorater** 规模化切分（MuSiQue 约 **55%** insufficient）。
3. **发现**：Sufficient 仍错 → 非单靠改检索；Insufficient 上 SOTA **35–62%** 仍错答且 **hallucinate > abstain**；Insufficient 仍有一部分答对 → 单用充分性不够。
4. **Selective generation**：intervention model + sufficient 信号 + confidence → generate/abstain。

### 局限

- FreshQA/HotpotQA/MuSiQue，**oracle 检索为主**，非 CRAG 噪声网页。
- 优化 **应答子集 precision**，非 CRAG score 结构。
- Autorater 依赖 LLM。

### 没覆盖你们什么

| 文献 | 你们 |
|------|------|
| oracle QA 上 formalize 充分性 | **CRAG Task1/2 嘈杂网页** |
| selective abstain | **rag_worse** + **过度检索** 桶 |
| +2–10% 应答精度 | **hallucination↓ + score↑** |

### 我们可增量

> 在 **CRAG 噪声网页** 上用 **声明级支持度/片段一致性** 做答拒，显式处理 **检索致错** 与四指标。

### 速填模板

```text
设定：open-book QA；sufficient vs insufficient（autorater）
方法：分层统计 + selective generation
没覆盖我们：CRAG 网页 / score / rag_worse / 过度检索
我们可增量：规则支持度门控；CRAG 200 条验收
```

## 七、#7 · UAEval4RAG — 不可答分类评测 ★

**原文**：Xiangyu Peng et al. *Unanswerability Evaluation for Retrieval Augmented Generation*. **ACL 2025** / arXiv:2412.12300.  
**本地 PDF**：`10_UAEval4RAG-不可答分类评测.pdf` · **代码**：https://github.com/SalesforceAIResearch/Unanswerability_RAGE

### 一句话概括

对 **给定 KB** 定义 **6 类 unanswerable**，自动合成并评 **Unanswered / Acceptable / Joint Score**；**无单一配置**同时最优异答与拒答。

### 问题

RAG 评测忽视「**对这份 KB 不该答**」；通用 unanswerable 集拒答常只因检索不到。

### 方法要点

- **六类**：Underspecified、**False-presuppositions**、Nonsensical、Modality-limited、Safety、Out-of-Database。
- 合成 pipeline：任意 KB → 不可答题 + 人类一致性校验。
- **Joint score**：可答正确率 vs 不可答拒答率加权（用户定权）。
- 27 组件组合：**prompt 对不可答性能影响可达 ~+80%**；LLM 选择亦关键。

### 局限

- KB 定制合成 ≠ CRAG 开放网页 + 假前提构造。
- LLM judge 口径 vs DeepSeek 四分类需对照。
- **False-presup** 你们已 largely missing → **非主创新点**。

### 没覆盖你们什么

| UAEval | 你们 |
|--------|------|
| 6 类 taxonomy + Joint | **有检索仍编 / 检索伤人** |
| KB 级不可答 | CRAG **score / hallucination / missing** |
| 组件网格 | Step 4 **规则 + 8B** |

### 我们可增量

> 聚焦 **有片段但支持不足或冲突** 的答拒边界；**不主打**假前提分类。

### 速填模板

```text
设定：任意 KB；6 类 synthetic unanswerable
方法：合成 + Unanswered/Acceptable/Joint
没覆盖我们：开放网页 / hallucination 列 / rag_worse
我们可增量：片段–声明支持度；假前提分工次要
```

## 八、#8 · Astute RAG — 不完美检索与冲突

**原文**：Fei Wang et al. *Astute RAG: Overcoming Imperfect Retrieval Augmentation and Knowledge Conflicts for Large Language Models*. ACL 2025 / arXiv:2410.07176.  
**本地 PDF**：`11_AstuteRAG-不完美检索与冲突.pdf`

### 一句话概括

量化 **不完美检索 ↔ 知识冲突**；**Astute RAG** = elicitation 内部知识 → source-aware consolidation → finalize；**worst-case** 下唯一稳匹无 RAG。

### 问题

检索噪声/误导 + **parametric vs external 冲突**；需 training-free、显式冲突处理。

### 方法要点

1. **分析**：~**45% LLM 对 & RAG 错**；~35% 两边都错；检索 precision ↔ conflict rate 强相关。
2. **流程**：Adaptive elicitation → 区分 consistent/conflicting/irrelevant → 按可靠性合并 → 定稿。
3. **结果**：worst-case（全 unhelpful passages）Astute ≈ 无 RAG，其他 RAG 大跌。

### 局限

- 偏 **合并仍作答**，非 missing 优先。
- 短答 + Google Search；无 CRAG 四指标。
- 多轮调用，成本高。

### 没覆盖你们什么

| Astute | 你们 |
|--------|------|
| 冲突时融合作答 | **证据不足 → missing** |
| worst-case 全废检索 | **rag_worse：有检索更差** |
| Google 短答 | CRAG **score + 假前提 + 长尾** |

### 我们可增量

> 借其 **LLM 对/RAG 错** 分析写 rag_worse；方法上优先 **门控拒答** 而非多轮 consolidation。

### 速填模板

```text
设定：搜索引擎；内外知识四象限
方法：elicitation → consolidation → finalize
没覆盖我们：CRAG 拒答指标 / 规则轻量 / 声明级支持度
我们可增量：冲突或不足则拒；对照 rag_worse 25 条
```
